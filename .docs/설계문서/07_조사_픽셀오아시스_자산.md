> **`npm run measure:*`는 옮기지 않았다.** 픽셀오아시스에서 그것은 이미지 변환 알고리즘의
> 수치를 뽑는 계측 코드였고, 마크다운 뷰어에는 대응물이 없다. 다만 「계측용 설정을 따로 둔
> 이유」는 1-6절에 남겼다 — 나중에 렌더링 성능을 재게 되면 그대로 쓰면 된다.

### 1-2. `capacitor.config.json`

픽셀오아시스 원본은 이렇다.

```json
{
    "appId": "com.pixeloasis.game",
    "appName": "Pixel Oasis",
    "webDir": "www",
    "server": {
        "androidScheme": "https"
    },
    "plugins": {
        "SplashScreen": {
            "launchShowDuration": 2000,
            "backgroundColor": "#1c1917",
            "showSpinner": false,
            "androidSpinnerStyle": "small"
        },
        "StatusBar": {
            "overlaysWebView": true
        },
        "SystemBars": {
            "insetsHandling": "css"
        }
    },
    "android": {
        "adjustMarginsForEdgeToEdge": "disable"
    }
}
```

**`server.allowNavigation`은 없다.** 실제로 확인했다 — `server` 아래에 `androidScheme`
하나뿐이다.

새 앱도 **`allowNavigation`을 넣지 마라.** 이유: `allowNavigation`을 열면 그 도메인이
WebView 안에서 열리고, 마크다운 문서에 들어 있는 외부 링크를 사용자가 눌렀을 때 앱 안에서
임의의 웹이 뜬다. 마크다운 파일은 사용자가 어디서 받아왔는지 알 수 없는 입력이다.
외부 링크는 `@capacitor/browser`의 `Browser.open({ url })`로 시스템 브라우저에 넘겨라.

**appId 규약.** `com.<브랜드>.<앱성격>` — 픽셀오아시스는 `com.pixeloasis.game`이다.
브랜드 부분은 소문자·숫자만, 하이픈·언더스코어 금지(자바 패키지명이 되므로).
새 앱은 **`com.marklet.md`로 정한다.** 다른 이름을 쓰고 싶으면 **첫 AAB를 업로드하기
전에** 바꿔라. 업로드 후에는 영원히 못 바꾼다 — 바꾸려면 새 앱으로 처음부터 등재해야 하고
기존 설치·리뷰·순위가 전부 사라진다.

새 앱용 `capacitor.config.json`:

```json
{
    "appId": "com.marklet.md",
    "appName": "Markdown Reader",
    "webDir": "www",
    "server": {
        "androidScheme": "https"
    },
    "plugins": {
        "SplashScreen": {
            "launchShowDuration": 1000,
            "backgroundColor": "#ffffff",
            "showSpinner": false,
            "androidSpinnerStyle": "small"
        },
        "StatusBar": {
            "overlaysWebView": false
        },
        "SystemBars": {
            "insetsHandling": "css"
        }
    },
    "android": {
        "adjustMarginsForEdgeToEdge": "disable"
    }
}
```

바꾼 곳과 이유:

- `launchShowDuration` 2000 → **1000**. 문서 뷰어는 "열자마자 보여야" 하는 앱이다.
  픽셀오아시스는 게임이라 분위기를 잡는 2초가 손해가 아니었지만 여기서는 손해다.
- `StatusBar.overlaysWebView` true → **false**. 픽셀오아시스는 캔버스를 화면 끝까지
  채우려고 true를 썼고, 그 대가로 MainActivity에서 인셋을 직접 다뤄야 했다.
  뷰어는 본문이 상태바에 가려지면 안 된다. false가 맞다.
- `adjustMarginsForEdgeToEdge: "disable"`은 **그대로 둔다.** Capacitor 8이 자동으로 넣는
  마진과 CSS `env(safe-area-inset-*)`가 이중으로 적용되어 아래쪽에 빈 띠가 생긴 적이 있다.
  인셋은 CSS 한 곳에서만 다뤄라.

### 1-3. `vite.config.ts`

픽셀오아시스 원본 전문:

```ts
import { defineConfig } from 'vite';
import { VitePWA } from 'vite-plugin-pwa';
import viteImagemin from 'vite-plugin-imagemin';

export default defineConfig(({ mode }) => ({
    root: './',
    esbuild: {
        drop: mode === 'production' ? ['console', 'debugger'] : [],
    },
    build: {
        outDir: 'www',
        emptyOutDir: true,
        rollupOptions: {
            input: {
                main: 'index.html',
                licenses: 'licenses.html',
            },
        },
    },
    plugins: [
        VitePWA({
            registerType: 'autoUpdate',
            includeAssets: ['favicon.png', 'assets/**'],
            devOptions: {
                enabled: false // 개발 중에는 SW 끄기 (HMR 간섭 방지)
            },
            workbox: {
                globPatterns: ['**/*.{js,css,html,png,jpg,jpeg,svg,json,ico}'],
                runtimeCaching: [
                    {
                        // Cache-First strategy for static assets
                        urlPattern: ({ url }) => {
                            return url.pathname.startsWith('/assets/') ||
                                url.hostname.includes('fonts.googleapis.com') ||
                                url.hostname.includes('fonts.gstatic.com');
                        },
                        handler: 'CacheFirst',
                        options: {
                            cacheName: 'static-assets-cache',
                            expiration: { maxEntries: 200, maxAgeSeconds: 60 * 60 * 24 * 365 },
                            cacheableResponse: { statuses: [0, 200] }
                        }
                    },
                    {
                        // Network-First strategy for API/Sync
                        urlPattern: ({ url }) => url.pathname.includes('/api/') || url.pathname.includes('/sync'),
                        handler: 'NetworkFirst',
                        options: {
                            cacheName: 'api-data-cache',
                            networkTimeoutSeconds: 5,
                            expiration: { maxEntries: 50, maxAgeSeconds: 60 * 60 * 24 },
                            cacheableResponse: { statuses: [0, 200] }
                        }
                    }
                ],
                navigateFallback: '/offline.html',
                navigateFallbackDenylist: [/^\/assets\//, /^\/api\//]
            }
        }),
        viteImagemin({
            gifsicle: { optimizationLevel: 7, interlaced: false },
            optipng: { optimizationLevel: 7 },
            mozjpeg: { quality: 80 },
            pngquant: { quality: [0.8, 0.9], speed: 4 },
            svgo: {
                plugins: [
                    { name: 'removeViewBox' },
                    { name: 'removeEmptyAttrs', active: false },
                ],
            },
            webp: { quality: 75 }
        })
    ],
    server: {
        port: 3000,
        open: true
    }
}));
```

**새 앱에서 반드시 유지할 것**

1. **`build.outDir: 'www'`** — `capacitor.config.json`의 `webDir`과 반드시 같아야 한다.
   Vite 기본값은 `dist`다. 그대로 두면 `cap sync`가 빈 `www`를 복사해 흰 화면이 된다.
2. **`emptyOutDir: true`** — 지난 빌드의 해시 붙은 JS가 남으면 `cap sync`가 그것까지
   APK에 넣는다. 용량만 늘고 로드되지도 않는다.
3. **`esbuild.drop: ['console','debugger']` (production만)** — 릴리스에서 console을 지운다.
   대신 **릴리스 빌드에서는 웹 로그를 볼 수 없다**는 뜻이다. 로그가 필요하면 디버그 빌드를 쓴다.
4. **`server.port: 3000`** — `scripts/dev-device.cjs`가 3000을 하드코딩해서 `adb reverse`를
   건다. 포트를 바꾸려면 두 곳을 같이 고쳐야 한다.

**새 앱에서 뺄 것 (결정)**

- **`vite-plugin-imagemin`을 빼라.** 마크다운 뷰어에는 최적화할 래스터 이미지가 사실상 없다.
  이 플러그인은 네이티브 바이너리(mozjpeg/pngquant)를 내려받아 설치 실패가 잦고, 빌드 시간을
  수십 초 늘린다. 얻는 것이 없다.
- **`vite-plugin-pwa`도 빼라.** Capacitor는 이미 `www/`를 앱 내부 자산으로 패키징해서
  `https://localhost`로 서빙한다. 오프라인은 이미 보장돼 있다. 서비스 워커를 얹으면
  ① 앱 업데이트 후에도 SW가 옛 자산을 캐시에서 내주는 사고가 생기고,
  ② `navigateFallback: '/offline.html'`이 잘못 걸리면 흰 화면의 원인이 된다.
  (픽셀오아시스는 웹 배포도 겸했기 때문에 PWA가 필요했다. 새 앱은 안드로이드 전용이다.)

새 앱용 `vite.config.ts` 전문:

```ts
import { defineConfig } from 'vite';

export default defineConfig(({ mode }) => ({
    root: './',
    esbuild: {
        // 릴리스에서 console을 지운다. 대신 릴리스 빌드에서는 웹 로그가 보이지 않는다.
        drop: mode === 'production' ? ['console', 'debugger'] : [],
    },
    build: {
        // capacitor.config.json의 webDir과 반드시 같아야 한다. 기본값 dist를 쓰면 흰 화면.
        outDir: 'www',
        emptyOutDir: true,
        rollupOptions: {
            input: {
                main: 'index.html',
                licenses: 'licenses.html',
            },
        },
    },
    server: {
        // scripts/dev-device.cjs가 이 포트로 adb reverse를 건다. 바꾸면 두 곳을 같이 고칠 것.
        port: 3000,
        open: true,
    },
}));
```

`licenses.html`을 입력에 남긴 이유: 오픈소스 라이브러리(마크다운 파서·하이라이터 등)의
라이선스 고지 페이지를 앱 안에 두기 위해서다. 픽셀오아시스도 같은 목적으로 별도 엔트리를 뒀다.
MIT/BSD 라이브러리를 앱에 넣으면 고지 의무가 생긴다.

### 1-5. ESLint / Prettier

픽셀오아시스에는 `.eslintrc.cjs`(구형)와 `eslint.config.js`(flat config)가 **둘 다** 남아
있다. ESLint 9는 flat config만 읽으므로 `.eslintrc.cjs`는 죽은 파일이다.
**새 앱은 `eslint.config.js` 하나만 둬라.**

`eslint.config.js` 전문:

```js
import typescriptEslintParser from '@typescript-eslint/parser';
import typescriptEslintPlugin from '@typescript-eslint/eslint-plugin';
import prettierPlugin from 'eslint-plugin-prettier';
import prettierConfig from 'eslint-config-prettier';

export default [
    {
        ignores: ['dist/', 'node_modules/', 'android/', 'www/', 'dev-dist/'],
    },
    {
        files: ['src/**/*.ts', 'src/**/*.tsx'],
        languageOptions: {
            parser: typescriptEslintParser,
            parserOptions: {
```

```json
}
```

`endOfLine: "auto"`는 Windows에서 필수다. 없으면 CRLF 때문에 모든 줄이 prettier 경고가 된다.

### 1-6. Vitest — 설정을 두 개로 나눈 이유

`vitest.config.ts` (일반 테스트):

```ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
    test: {
        globals: true,
        environment: 'jsdom', // 브라우저 환경 모의
        include: ['src/**/*.test.ts', 'src/**/*.spec.ts'],
    },
});
```

`vitest.measure.config.ts` (계측 전용):

```ts
import { defineConfig } from 'vitest/config';

/**
 * 실측 도구 전용 설정
 *
 * src/**\/*.measure.ts는 통과/실패를 판정하는 테스트가 아니라 샘플 이미지를
 * 실제로 처리해 수치를 뽑는 계측 코드다. 수십 초가 걸리고 sharp(네이티브)를
 * 쓰므로 일반 테스트 스위트(vitest.config.ts)에서 분리한다.
 *
 * 실행: npm run measure:palette
 */
export default defineConfig({
    test: {
        globals: true,
        environment: 'jsdom',
        include: ['src/**/*.measure.ts'],
        testTimeout: 20 * 60 * 1000,
    },
});
```

**나눈 이유는 세 가지다.**

1. `include` 패턴이 다르다. `*.measure.ts`는 일반 `npm test`에서 잡히면 안 된다.
2. `testTimeout`이 20분이다. 일반 스위트에 이 값을 걸면 진짜로 멈춘 테스트도 20분을 기다린다.
3. 계측 코드는 네이티브 모듈(`sharp`)을 쓴다. 일반 스위트가 그걸 끌고 들어가면 CI에서
   설치 실패 하나로 전체 테스트가 죽는다.

**새 앱에서는 `vitest.config.ts` 하나로 시작해라.** 나중에 큰 마크다운 파일 렌더링 시간을
재고 싶어지면 그때 `vitest.measure.config.ts`를 위 내용 그대로 추가하면 된다.
`include`를 `['src/**/*.measure.ts']`로, `testTimeout`을 길게 — 그 두 가지가 핵심이다.

(패키지명 두 곳만 바꾼다).

```groovy
apply plugin: 'com.android.application'

// ---------------------------------------------------------------------------
// 버전: package.json을 단일 소스로 사용합니다.
// versionName은 그대로, versionCode는 major*10000 + minor*100 + patch로 계산합니다.
// (예: 1.0.15 -> 10015) 같은 버전을 두 번 올릴 수 없으므로 재배포 시 patch를 올리세요.
// ---------------------------------------------------------------------------
def packageJson = new groovy.json.JsonSlurper().parseText(rootProject.file('../package.json').text)
def appVersionName = packageJson.version
def (verMajor, verMinor, verPatch) = appVersionName.tokenize('.').collect { it.toInteger() }

// ---------------------------------------------------------------------------
// 서명 자격증명: 추적되지 않는 keystore.properties에서 읽습니다.
// 파일이 없으면 릴리스 빌드가 서명 없이 생성됩니다 (디버그 빌드는 영향 없음).
// ---------------------------------------------------------------------------
def keystorePropertiesFile = rootProject.file('keystore.properties')
def keystoreProperties = new Properties()
def hasSigningConfig = keystorePropertiesFile.exists()
if (hasSigningConfig) {
    keystorePropertiesFile.withInputStream { keystoreProperties.load(it) }
} else {
    logger.warn("⚠️ keystore.properties가 없어 릴리스 빌드가 서명되지 않습니다. keystore.properties.example을 참고하세요.")
}

android {
    namespace "com.marklet.md"
    compileSdk rootProject.ext.compileSdkVersion
    defaultConfig {
        applicationId "com.marklet.md"
        minSdkVersion rootProject.ext.minSdkVersion
        targetSdkVersion rootProject.ext.targetSdkVersion
        versionCode appVersionCode
        versionName appVersionName
        testInstrumentationRunner "androidx.test.runner.AndroidJUnitRunner"
        aaptOptions {
            ignoreAssetsPattern '!.svn:!.git:!.ds_store:!*.scc:.*:!CVS:!thumbs.db:!picasa.ini:!*~'
        }
    }
    signingConfigs {
        release {

                storeFile rootProject.file(keystoreProperties['storeFile'])

    mavenCentral()
}

    implementation fileTree(include: ['*.jar'], dir: 'libs')
    implementation "androidx.appcompat:appcompat:$androidxAppCompatVersion"

    implementation project(':capacitor-android')
    testImplementation "junit:junit:$junitVersion"

    androidTestImplementation "androidx.test.espresso:espresso-core:$androidxEspressoCoreVersion"

```

> 픽셀오아시스 원본 끝에는 `google-services.json`을 찾아 Firebase 플러그인을 적용하는
> try/catch 블록이 더 있다. **새 앱에서는 지워라.** Firebase를 쓰지 않는다.

**이 파일의 핵심 세 가지**

1. **버전 단일 소스화.** `package.json`의 `version`만 고치면 `versionName`과 `versionCode`가
   같이 따라온다. `versionCode = major*10000 + minor*100 + patch`.
   - `1.0.0` → `10000`, `1.0.37` → `10037`, `1.2.3` → `10203`
   - minor·patch는 **99를 넘으면 안 된다.** `1.0.100`은 `10100`이 되어 `1.1.0`과 충돌한다.
   - 같은 versionCode는 두 번 업로드할 수 없다. **재배포하려면 반드시 patch를 올려라.**
2. **`keystore.properties`가 없어도 빌드가 죽지 않는다.** 경고만 내고 서명 없는 AAB가 나온다.
   `hasSigningConfig` 분기가 그 역할이다. 이게 없으면 새 PC에서 clone 직후 `gradlew`가
   무조건 실패해서 원인을 찾는 데 시간이 든다.
3. **디버그 빌드의 `applicationIdSuffix ".debug"`.** 5장 함정 목록에서 자세히 다룬다.

### 2-9. `AndroidManifest.xml` — 새 앱용

픽셀오아시스 원본에서 광고 관련(AdMob APPLICATION_ID meta-data, `AD_ID` 권한)을 빼고,
게임 전용 설정을 뷰어에 맞게 바꾼 것이다.

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:allowBackup="true"
        android:appCategory="productivity"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:supportsRtl="true"
        android:theme="@style/AppTheme.NoActionBar">

        <activity
            android:configChanges="orientation|keyboardHidden|keyboard|screenSize|locale|smallestScreenSize|screenLayout|uiMode"
            android:name=".MainActivity"
            android:label=""
            android:theme="@style/AppTheme.NoActionBarLaunch"
            android:launchMode="singleTask"
            android:exported="true">

            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>

            <!-- 다른 앱의 "연결 프로그램"에서 .md를 열 수 있게 한다 -->
            <intent-filter>
                <action android:name="android.intent.action.VIEW" />
                <category android:name="android.intent.category.DEFAULT" />
                <category android:name="android.intent.category.BROWSABLE" />
                <data android:scheme="content" android:mimeType="text/markdown" />
                <data android:scheme="content" android:mimeType="text/x-markdown" />
                <data android:scheme="content" android:mimeType="text/plain" />
                <data android:scheme="file" android:mimeType="text/markdown" />
            </intent-filter>
        </activity>

        <provider
            android:name="androidx.core.content.FileProvider"
            android:authorities="${applicationId}.fileprovider"
            android:exported="false"
            android:grantUriPermissions="true">
            <meta-data
                android:name="android.support.FILE_PROVIDER_PATHS"
                android:resource="@xml/file_paths" />
        </provider>
    </application>

    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="com.android.vending.BILLING" />

```

픽셀오아시스와 달라진 곳과 이유:

| 항목 | 픽셀오아시스 | 새 앱 | 이유 |
|---|---|---|---|
| `appCategory` | `game` | `productivity` | 게임이 아니다. 픽셀오아시스가 `game`을 선언한 이유는 targetSdk 36에서 대화면 방향 제한의 예외를 받기 위해서였다. 뷰어는 회전을 막을 이유가 없으므로 필요 없다 |
| `screenOrientation` | `fullSensor` | **선언하지 않음** | targetSdk 36 + 대화면에서는 앱의 방향 지정이 무시된다. 뷰어는 원래 세로·가로 다 되어야 하므로 지정 자체를 안 하는 게 맞다 |
| AdMob meta-data | 있음 | **없음** | 광고 없음 |
| `AD_ID` 권한 | 있음 | **없음** | **중요.** 이 권한이 남아 있으면 Play Console의 데이터 안전 섹션에서 광고 ID 수집을 신고해야 하고, 신고와 실제가 어긋나면 심사에서 걸린다. 광고를 안 쓰면 반드시 지워라 |
| `BILLING` 권한 | 있음 | 있음 | 팁 인앱결제에 필요하다 |
| `INTERNET` 권한 | 있음 | 있음 | 결제와 외부 링크 열기에 필요하다 |
| VIEW intent-filter | 없음 | **추가** | 픽셀오아시스에는 없던 것. 마크다운 뷰어의 존재 이유라서 새로 만들어야 한다 |

> `text/plain`을 넣은 이유: 안드로이드의 여러 파일 관리자가 `.md`의 MIME을 모르고
> `text/plain`으로 넘긴다. 넣지 않으면 "이 파일을 열 앱이 없습니다"가 뜬다.
> 반대로 `*/*`는 넣지 마라 — 모든 파일 유형의 연결 프로그램 목록에 앱이 뜨는데,
> 사용자 입장에서 소음이고 심사자도 좋아하지 않는다.

### 2-10. `MainActivity.java` — 새 앱용

픽셀오아시스 원본은 몰입 모드(시스템 바 숨김)를 강제한다. 게임에는 맞지만 **문서 뷰어에는
틀린 동작이다.** 읽는 중에 상태바가 사라지면 시계도 배터리도 안 보인다. 몰입 모드 부분을
전부 걷어내고 필요한 것만 남긴다.

```java
package com.marklet.md;

import android.content.pm.ApplicationInfo;
import android.os.Bundle;
import android.webkit.WebView;

import com.getcapacitor.BridgeActivity;

public class MainActivity extends BridgeActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // WebView 디버깅은 디버그 빌드에서만 활성화 (릴리스에서 내부 상태 노출 방지)
        if ((getApplicationInfo().flags & ApplicationInfo.FLAG_DEBUGGABLE) != 0) {
            WebView.setWebContentsDebuggingEnabled(true);
        }
    }
}
```

**`FLAG_DEBUGGABLE` 검사는 반드시 남겨라.** 이걸 빼고 무조건
`setWebContentsDebuggingEnabled(true)`를 부르면, 스토어에 나간 앱을 USB로 연결한 누구든
Chrome DevTools로 WebView 내부를 들여다볼 수 있다. 픽셀오아시스는 이 조치를
`a731ee2` 커밋에서 "보안" 항목으로 넣었다.

`BuildConfig.DEBUG` 대신 `getApplicationInfo().flags`를 쓴 이유: Capacitor가 만든
MainActivity는 앱 모듈의 `BuildConfig`를 import하지 않은 상태로 생성되고, 패키지명을
바꾸면 import 경로가 어긋난다. `ApplicationInfo` 방식은 패키지명과 무관하게 동작한다.

## 3. 자동화 스크립트 — 전문

`scripts/` 아래에 그대로 만들어라. 파일 확장자는 **`.cjs`여야 한다.**

### 3-1. `scripts/lib/assert-no-dev-server.cjs`

**가장 먼저 만들어라.** 나머지 두 스크립트가 이걸 import한다.

```js
/**
 * 릴리스 산출물에 개발 서버 주소가 섞이지 않도록 검사
 *
 * `npm run dev:device`는 기기가 PC의 Vite 서버를 바라보도록 생성 설정에
 * `server.url`을 주입합니다. 그 상태로 릴리스를 빌드하면 localhost를 로드하는
 * 앱이 배포되어 실행 즉시 흰 화면이 됩니다.
 *
 * dev:device는 종료 시 설정을 되돌리지만, 비정상 종료로 남을 수 있어
 * 빌드·업로드 직전에 한 번 더 확인합니다.
 */

const fs = require('fs');
const path = require('path');

const GENERATED_CONFIG = path.resolve(
    __dirname,
    '..',
    '..',
    'android',
    'app',
    'src',
    'main',
    'assets',
    'capacitor.config.json',
);

/** 개발 서버 주소가 남아 있으면 메시지를 출력하고 프로세스를 종료합니다. */
function assertNoDevServer() {
    if (!fs.existsSync(GENERATED_CONFIG)) return;

    let config;
    try {
        config = JSON.parse(fs.readFileSync(GENERATED_CONFIG, 'utf8'));
    } catch {
        return; // 설정을 읽지 못하면 빌드 단계에서 걸립니다
    }

    const url = config.server?.url;
    if (!url) return;

    console.error('');
    console.error('❌ 생성된 Capacitor 설정에 개발 서버 주소가 남아 있습니다.');
    console.error(`   server.url = ${url}`);
    console.error('');
    console.error('   이대로 빌드하면 실행 즉시 흰 화면이 되는 앱이 만들어집니다.');
    console.error('   아래 명령으로 설정을 재생성한 뒤 다시 시도하세요:');
    console.error('');
    console.error('     npm run build:android');
    console.error('');
    process.exit(1);
}

module.exports = { assertNoDevServer, GENERATED_CONFIG };
```

이 검사는 실제 사고에서 나왔다. `dev:device`를 Ctrl+C가 아니라 터미널 창을 닫아서 끝내면
`server.url = http://localhost:3000`이 남고, 그대로 릴리스를 빌드하면 **실행하자마자
흰 화면인 앱**이 스토어에 올라간다. 기기에는 앱이 설치되고 아이콘도 뜨는데 열면 아무것도
없다. 빌드 로그에는 아무 경고도 안 나온다.

### 3-2. `scripts/build-aab.cjs`

`npm run build:aab`. Android Studio 없이 CLI로 서명된 AAB를 만든다.

```js
#!/usr/bin/env node

/**
 * 릴리스 AAB 빌드 스크립트
 *
 * Android Studio 없이 CLI만으로 서명된 AAB를 생성합니다.
 *
 * JAVA_HOME이 Android Studio 번들 JDK(jbr)를 가리키는 경우, 스튜디오 업데이트 중에는
 * 그 경로가 사라져 gradlew 런처가 아예 뜨지 못합니다. 이를 피하기 위해 유효한 JDK를
 * 직접 찾아 자식 프로세스에만 JAVA_HOME을 지정합니다. (시스템 환경변수는 건드리지 않음)
 *
 * 사용법: npm run build:aab
 */

const { spawnSync, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');
const { assertNoDevServer } = require('./lib/assert-no-dev-server.cjs');

const repoRoot = path.resolve(__dirname, '..');
const androidDir = path.join(repoRoot, 'android');
const isWindows = process.platform === 'win32';

/** 해당 경로가 실제로 동작하는 JDK인지 확인 */
function isUsableJdk(home) {
    if (!home) return false;
    const javaBin = path.join(home, 'bin', isWindows ? 'java.exe' : 'java');
    // jvm.cfg가 없으면 런타임이 반쯤 지워진 상태(스튜디오 업데이트 중)입니다.
    const jvmCfg = path.join(home, 'lib', 'jvm.cfg');
    return fs.existsSync(javaBin) && fs.existsSync(jvmCfg);
}

/** PATH에 있는 java로부터 JDK 홈 경로를 역추적 */
function jdkFromPath() {
    try {
        const probe = isWindows ? 'where' : 'which';
        const out = execFileSync(probe, ['java'], { encoding: 'utf8' });
        const javaBin = out.split(/\r?\n/).find(Boolean);
        if (!javaBin) return null;
        // <home>/bin/java -> <home>
        return path.resolve(path.dirname(javaBin), '..');
    } catch {
        return null;
    }
}

function resolveJdk() {
    if (isUsableJdk(process.env.JAVA_HOME)) {
        return process.env.JAVA_HOME;
    }

    const fallback = jdkFromPath();
    if (isUsableJdk(fallback)) {
        console.log(`ℹ️  JAVA_HOME이 유효하지 않아 PATH의 JDK를 사용합니다: ${fallback}`);
        return fallback;
    }

    console.error('❌ 사용 가능한 JDK를 찾지 못했습니다.');
    console.error('   JAVA_HOME을 JDK 21 경로로 지정하거나, java를 PATH에 추가하세요.');
    process.exit(1);
}

function main() {
    assertNoDevServer();

    const javaHome = resolveJdk();
    const gradlew = path.join(androidDir, isWindows ? 'gradlew.bat' : 'gradlew');

    if (!fs.existsSync(gradlew)) {
        console.error('❌ gradlew를 찾을 수 없습니다:', gradlew);
        process.exit(1);
    }

    if (!fs.existsSync(path.join(androidDir, 'keystore.properties'))) {
        console.warn(
            '⚠️  keystore.properties가 없습니다. AAB가 서명되지 않아 업로드할 수 없습니다.',
        );
        console.warn('   android/keystore.properties.example을 복사해 값을 채우세요.');
    }

    console.log('🏗️  릴리스 AAB 빌드 중...');
    // Windows의 .bat는 Node 20+에서 shell 없이는 실행되지 않으므로 shell 경유로 실행합니다.
    // 경로에 공백이 있을 수 있어 실행 파일은 따옴표로 감쌉니다.
    const result = spawnSync(`"${gradlew}"`, [':app:bundleRelease'], {
        cwd: androidDir,
        env: { ...process.env, JAVA_HOME: javaHome },
        stdio: 'inherit',
        shell: true,
    });

    if (result.error) {
        console.error('❌ gradlew 실행 실패:', result.error.message);
        process.exit(1);
    }

    if (result.status !== 0) {
        process.exit(result.status ?? 1);
    }

    const aab = path.join(
        androidDir,
        'app',
        'build',
        'outputs',
        'bundle',
        'release',
        'app-release.aab',
    );

    if (!fs.existsSync(aab)) {
        console.error('❌ 빌드는 끝났지만 AAB를 찾을 수 없습니다:', aab);
        process.exit(1);
    }

    const version = require(path.join(repoRoot, 'package.json')).version;
    const sizeMb = (fs.statSync(aab).size / 1024 / 1024).toFixed(1);

    console.log('');
    console.log(`✅ 빌드 완료 — v${version} (${sizeMb} MB)`);
    console.log(`   ${aab}`);
}

main();
```

이 스크립트에 들어간 판단 네 가지:

1. **`isUsableJdk`가 `bin/java`만이 아니라 `lib/jvm.cfg`도 본다.** 함정 1번 참조.
2. **`JAVA_HOME`을 자식 프로세스에만 준다.** 시스템 환경변수는 건드리지 않는다.
   Android Studio가 자기 JBR을 기대하고 있으므로 전역을 바꾸면 스튜디오 쪽이 깨진다.
3. **`shell: true`와 실행 파일 따옴표.** Node 20부터 `.bat`/`.cmd`는 `shell` 없이 실행되지
   않는다(CVE-2024-27980 대응). 그리고 경로에 `Program Files` 같은 공백이 있어서 따옴표가 필요하다.
4. **빌드 성공 후 AAB 파일 존재를 다시 확인한다.** gradle이 exit 0으로 끝나고도 산출물이
   없는 경우가 있다.

### 3-3. `scripts/publish.cjs`

```js
#!/usr/bin/env node

/**
 * Play Console 업로드 스크립트
 *
 * 서명된 AAB를 빌드해 지정한 트랙에 업로드합니다.
 * Gradle Play Publisher(GPP)를 사용하며, 서비스 계정 키가 있어야 동작합니다.
 *
 * 사용법:
 *   node scripts/publish.cjs internal      # 내부 테스트 트랙
 *   node scripts/publish.cjs production    # 프로덕션
 */

const { spawnSync, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');
const readline = require('readline');
const { assertNoDevServer } = require('./lib/assert-no-dev-server.cjs');

const repoRoot = path.resolve(__dirname, '..');
const androidDir = path.join(repoRoot, 'android');
const credentialsPath = path.join(androidDir, 'play-service-account.json');
const isWindows = process.platform === 'win32';

const VALID_TRACKS = ['internal', 'alpha', 'beta', 'production'];

/** 해당 경로가 실제로 동작하는 JDK인지 확인 */
function isUsableJdk(home) {
    if (!home) return false;
    const javaBin = path.join(home, 'bin', isWindows ? 'java.exe' : 'java');
    const jvmCfg = path.join(home, 'lib', 'jvm.cfg');
    return fs.existsSync(javaBin) && fs.existsSync(jvmCfg);
}

/** PATH에 있는 java로부터 JDK 홈 경로를 역추적 */
function jdkFromPath() {
    try {
        const probe = isWindows ? 'where' : 'which';
        const javaBin = execFileSync(probe, ['java'], { encoding: 'utf8' })
            .split(/\r?\n/)
            .find(Boolean);
        return javaBin ? path.resolve(path.dirname(javaBin), '..') : null;
    } catch {
        return null;
    }
}

function resolveJdk() {
    if (isUsableJdk(process.env.JAVA_HOME)) return process.env.JAVA_HOME;

    const fallback = jdkFromPath();
    if (isUsableJdk(fallback)) {
        console.log(`ℹ️  JAVA_HOME이 유효하지 않아 PATH의 JDK를 사용합니다: ${fallback}`);
        return fallback;
    }

    console.error('❌ 사용 가능한 JDK를 찾지 못했습니다.');
    process.exit(1);
}

/** 프로덕션 배포 전 확인 (되돌리기 어려운 작업) */
function confirmProduction(version) {
    return new Promise((resolve) => {
        const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
        rl.question(
            `\n⚠️  v${version}를 프로덕션에 배포합니다. 실제 사용자에게 즉시 공개됩니다.\n   계속하려면 'yes'를 입력하세요: `,
            (answer) => {
                rl.close();
                resolve(answer.trim().toLowerCase() === 'yes');
            },
        );
    });
}

async function main() {
    assertNoDevServer();

    const track = process.argv[2];

    if (!VALID_TRACKS.includes(track)) {
        console.error(`❌ 트랙을 지정하세요. 사용 가능: ${VALID_TRACKS.join(', ')}`);
        console.error('   예) node scripts/publish.cjs internal');
        process.exit(1);
    }

    if (!fs.existsSync(credentialsPath)) {
        console.error('❌ 서비스 계정 키가 없습니다:', credentialsPath);
        console.error('   발급 방법은 android/PLAY_PUBLISHING.md를 참고하세요.');
        process.exit(1);
    }

    if (!fs.existsSync(path.join(androidDir, 'keystore.properties'))) {
        console.error(
            '❌ keystore.properties가 없어 AAB가 서명되지 않습니다. 업로드할 수 없습니다.',

        process.exit(1);

    if (track === 'production' && !(await confirmProduction(version))) {

        process.exit(0);

    const gradlew = path.join(androidDir, isWindows ? 'gradlew.bat' : 'gradlew');

    console.log(`🚀 v${version} → ${track} 트랙 업로드 중...`);

    const result = spawnSync(`"${gradlew}"`, [':app:publishReleaseBundle', '--track', track], {
        cwd: androidDir,
        env: { ...process.env, JAVA_HOME: javaHome },
        stdio: 'inherit',
        shell: true,
    });

    if (result.error) {
        console.error('❌ gradlew 실행 실패:', result.error.message);
        process.exit(1);
    }

    if (result.status !== 0) {
        process.exit(result.status ?? 1);
    }

    console.log('');
    console.log(`✅ v${version}를 ${track} 트랙에 업로드했습니다.`);
    console.log('   Play Console에서 검토 상태를 확인하세요.');
}

main();
```

### 3-4. `scripts/play-status.cjs`

Play Console을 열지 않고 트랙 상태를 본다. **`gradlew`를 거치지 않고 Android Publisher
API를 직접 호출한다** — Node 내장 `crypto`로 JWT를 만들어 OAuth 토큰을 받는다.
의존성이 하나도 필요 없다.

```js
#!/usr/bin/env node

/**
 * Play Console 트랙 상태 조회
 *
 * 업로드한 버전이 각 트랙에서 실제로 어떤 상태인지 확인합니다.
 * (검토 중인지, 배포됐는지, 어떤 버전이 활성인지)
 *
 * 사용법: npm run play:status
 */

const crypto = require('crypto');
const fs = require('fs');
const path = require('path');

const repoRoot = path.resolve(__dirname, '..');
const credentialsPath = path.join(repoRoot, 'android', 'play-service-account.json');
const PACKAGE_NAME = 'com.marklet.md';
const SCOPE = 'https://www.googleapis.com/auth/androidpublisher';
const API = 'https://androidpublisher.googleapis.com/androidpublisher/v3';

function base64url(input) {
    return Buffer.from(input).toString('base64url');
}

/** 서비스 계정 키로 OAuth 액세스 토큰 발급 */
async function getAccessToken(credentials) {
    const now = Math.floor(Date.now() / 1000);
    const header = base64url(JSON.stringify({ alg: 'RS256', typ: 'JWT' }));
    const claims = base64url(
        JSON.stringify({
            iss: credentials.client_email,
            scope: SCOPE,
            aud: 'https://oauth2.googleapis.com/token',
            exp: now + 3600,
            iat: now,
        }),
    );

    const signature = crypto
        .createSign('RSA-SHA256')
        .update(`${header}.${claims}`)
        .sign(credentials.private_key)
        .toString('base64url');

    const res = await fetch('https://oauth2.googleapis.com/token', {
        method: 'POST',
        headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
        body: new URLSearchParams({
            grant_type: 'urn:ietf:params:oauth:grant-type:jwt-bearer',
            assertion: `${header}.${claims}.${signature}`,
        }),
    });

    const body = await res.json();
    if (!res.ok) throw new Error(`토큰 발급 실패: ${JSON.stringify(body)}`);
    return body.access_token;
}

async function api(token, urlPath, options = {}) {
    const res = await fetch(`${API}${urlPath}`, {
        ...options,
        headers: { Authorization: `Bearer ${token}`, ...(options.headers ?? {}) },
    });
    const text = await res.text();
    const body = text ? JSON.parse(text) : {};
    if (!res.ok) throw new Error(`${urlPath} → ${res.status}: ${JSON.stringify(body)}`);
    return body;
}

async function main() {
    if (!fs.existsSync(credentialsPath)) {
        console.error('❌ 서비스 계정 키가 없습니다:', credentialsPath);
        process.exit(1);
    }

    const credentials = JSON.parse(fs.readFileSync(credentialsPath, 'utf8'));
    const token = await getAccessToken(credentials);

    // 트랙 조회는 edit 컨텍스트가 필요합니다. 조회만 하고 바로 폐기합니다.
    const edit = await api(token, `/applications/${PACKAGE_NAME}/edits`, { method: 'POST' });

    try {
        const { tracks = [] } = await api(
            token,
            `/applications/${PACKAGE_NAME}/edits/${edit.id}/tracks`,
        );

        console.log(`📦 ${PACKAGE_NAME}\n`);

        // --raw: 국가 타겟팅 등 원본 필드까지 확인할 때 사용
        if (process.argv.includes('--raw')) {
            const internal = tracks.find((t) => t.track === 'internal');
            console.log(JSON.stringify(internal ?? tracks, null, 2));
            return;
        }

        for (const track of tracks) {
            console.log(`━━ ${track.track} ━━`);

            if (!track.releases?.length) {
                console.log('   (출시 없음)\n');
                continue;
            }

            for (const release of track.releases) {
                console.log(`   상태       : ${release.status}`);
                console.log(`   버전 코드  : ${(release.versionCodes ?? ['-']).join(', ')}`);
                if (release.name) console.log(`   출시 이름  : ${release.name}`);
                if (release.userFraction !== undefined) {
                    console.log(`   배포 비율  : ${release.userFraction * 100}%`);
                }
                console.log('');
            }
        }
    } finally {
        // 조회용 edit이 남지 않도록 정리
        await api(token, `/applications/${PACKAGE_NAME}/edits/${edit.id}`, {
            method: 'DELETE',
        }).catch(() => {});
    }
}

main().catch((e) => {
    console.error('❌', e.message);
    process.exit(1);
});
```

### 3-5. `scripts/logcat.cjs`

```js
#!/usr/bin/env node

/**
 * 앱 전용 logcat 뷰어
 *
 * 기기 전체 로그는 (특히 삼성 기기에서) 시스템 로그가 대부분이라 읽기 어렵습니다.
 * 이 스크립트는 앱 프로세스의 로그만 보여주고, 앱이 재시작되어 PID가 바뀌면
 * 자동으로 다시 붙습니다.
 *
 * 사용법:
 *   npm run logcat                     앱 프로세스 전체 로그
 *   npm run logcat -- --focus          결제·크래시 관련 로그만
 *   npm run logcat -- --grep "패턴"    임의 패턴만
 *
 * 참고: 릴리스 빌드에서는 웹(console.log) 로그가 나오지 않습니다.
 *       Capacitor의 loggingBehavior 기본값이 debug이기 때문입니다.
 *       웹 로그가 필요하면 디버그 빌드를 사용하세요.
 */

const { spawn, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');

// 디버그 빌드는 applicationIdSuffix로 패키지명이 분리되어 있습니다.
// 실행 중인 쪽을 자동으로 찾되, 디버그 빌드를 우선합니다(로그가 더 많음).
const APP_IDS = ['com.marklet.md.debug', 'com.marklet.md'];
const isWindows = process.platform === 'win32';

/**
 * focus 모드에서 통과시킬 로그 "태그" 목록.
 *
 * 메시지 내용이 아니라 태그로 거릅니다. 내용으로 거르면 삼성 기기의 렌더링 로그
 * (`I/View ... CapacitorWebView ...`)까지 통과해 버립니다.
 */
const FOCUS_TAGS = [
    /^Capacitor(\/|$)/i, // Capacitor, Capacitor/Console(웹 console.log), Capacitor/Plugin/...
    /Billing/i, // BillingClient 등 결제
    /Purchase/i, // cordova-plugin-purchase
    /^AndroidRuntime$/, // 크래시
    /^System\.err$/, // 스택 트레이스
];

/** 태그가 일반적이어도 내용이 우리 것이면 통과 */
const FOCUS_MESSAGE = /🛍️|후원|팁/;

/** `-v brief` 형식: `I/Tag    ( 1234): message` */
const LOGCAT_LINE = /^([VDIWEF])\/(.+?)\(\s*\d+\):\s?(.*)$/;

function passesFocus(line) {
    const match = LOGCAT_LINE.exec(line);
    if (!match) return false; // "--------- beginning of main" 같은 구분선은 숨김

    const tag = match[2].trim();
    const message = match[3];

    return FOCUS_TAGS.some((re) => re.test(tag)) || FOCUS_MESSAGE.test(message);
}

/** adb 실행 파일 경로 찾기 */
function resolveAdb() {
    const candidates = [];

    // 1. android/local.properties의 sdk.dir
    try {
        const localProps = fs.readFileSync(
            path.resolve(__dirname, '..', 'android', 'local.properties'),
            'utf8',
        );
        const match = localProps.match(/^sdk\.dir=(.+)$/m);
        if (match) {
            // properties 파일은 백슬래시와 콜론을 이스케이프합니다
            const sdkDir = match[1].trim().replace(/\\:/g, ':').replace(/\\\\/g, '\\');
            candidates.push(path.join(sdkDir, 'platform-tools', isWindows ? 'adb.exe' : 'adb'));
        }
    } catch {
        // local.properties가 없으면 다음 후보로
    }

    // 2. 환경변수
    for (const env of [process.env.ANDROID_HOME, process.env.ANDROID_SDK_ROOT]) {
        if (env) {
            candidates.push(path.join(env, 'platform-tools', isWindows ? 'adb.exe' : 'adb'));
        }
    }

    for (const candidate of candidates) {
        if (fs.existsSync(candidate)) return candidate;
    }

    // 3. PATH에 있기를 기대
    return 'adb';
}

const adb = resolveAdb();

function adbSync(args) {
    try {
        return execFileSync(adb, args, { encoding: 'utf8' }).trim();
    } catch {
        return '';
    }
}

/** 앱이 뜰 때까지 기다렸다가 { appId, pid } 반환 */
async function waitForApp() {
    let announced = false;

    for (;;) {
        for (const appId of APP_IDS) {
            const pid = adbSync(['shell', 'pidof', '-s', appId]);
            if (pid) return { appId, pid };
        }

        if (!announced) {
            console.log(`⏳ 앱 실행을 기다리는 중... (${APP_IDS.join(' 또는 ')})`);
            announced = true;
        }
        await new Promise((resolve) => setTimeout(resolve, 1000));
    }
}

function parseArgs() {
    const argv = process.argv.slice(2);
    const grepIndex = argv.indexOf('--grep');
    return {
        focus: argv.includes('--focus'),
        grep: grepIndex >= 0 && argv[grepIndex + 1] ? new RegExp(argv[grepIndex + 1], 'i') : null,
    };
}

async function main() {
    const { focus, grep } = parseArgs();

    const devices = adbSync(['devices'])
        .split(/\r?\n/)
        .slice(1)
        .filter((line) => line.includes('\tdevice'));

    if (devices.length === 0) {
        console.error('❌ 연결된 기기가 없습니다. USB 디버깅을 확인하세요.');
        process.exit(1);
    }

    // grep이 있으면 내용으로, focus면 태그 기준으로, 둘 다 없으면 앱 로그 전체
    const accepts = grep ? (line) => grep.test(line) : focus ? passesFocus : null;

    if (grep) console.log(`🔎 패턴 필터: ${grep}`);
    else if (focus) console.log('🔎 focus 모드 — 결제·크래시 로그만 표시');

    // 이전에 쌓인 로그를 버려 현재 세션만 봅니다
    adbSync(['logcat', '-c']);

    for (;;) {
        const { appId, pid } = await waitForApp();
        console.log(`\n📱 ${appId} (pid ${pid}) 로그 — Ctrl+C로 종료\n`);

        await new Promise((resolve) => {
            const child = spawn(adb, ['logcat', '--pid', pid, '-v', 'brief'], {
                stdio: ['ignore', 'pipe', 'inherit'],
            });

            let buffer = '';
            child.stdout.on('data', (chunk) => {
                buffer += chunk.toString();
                const lines = buffer.split('\n');
                buffer = lines.pop() ?? '';

                for (const line of lines) {
                    if (!accepts || accepts(line)) console.log(line);
                }
            });

            child.on('close', resolve);
        });

        console.log('\n🔄 앱 프로세스가 종료되었습니다. 재시작을 기다립니다...\n');
    }
}

main();
```

**여기서 배운 것 두 가지**

1. **필터는 메시지가 아니라 태그로 걸어라.** 처음에는 메시지 내용으로 걸렀는데,
   삼성 기기의 `I/View ... CapacitorWebView ...` 같은 렌더링 로그가 전부 통과했다.
   `-v brief` 형식(`I/Tag ( 1234): message`)을 정규식으로 쪼개 태그만 본다.
2. **`adb logcat -c`로 먼저 비운다.** 안 그러면 지난 며칠 로그가 쏟아져서
   지금 실행한 세션이 어디부터인지 알 수 없다.

### 3-6. `scripts/dev-device.cjs`

USB로 연결한 실기기에서 라이브 리로드. 코드를 저장하면 기기 화면이 즉시 갱신된다.

```js
#!/usr/bin/env node

/**
 * 실기기 라이브 리로드
 *
 * 코드를 저장하면 USB로 연결된 기기 화면이 즉시 갱신됩니다.
 * 파일 열기·공유처럼 실기기가 필요한 기능을 재빌드 없이 확인할 때 사용합니다.
 *
 * `npx cap run android -l`을 쓰지 않는 이유:
 * Capacitor CLI가 내부적으로 './gradlew'를 실행하는데, Windows(cmd.exe)에서는
 * 이 경로 형식과 확장자 없는 셸 스크립트를 실행하지 못해 실패합니다.
 * 또한 cap run은 개발 서버를 직접 띄우지 않고, host 기본값이 LAN IP라
 * localhost 바인딩인 Vite에 기기가 접근할 수 없습니다.
 * 그래서 같은 일을 gradlew.bat와 adb로 직접 수행합니다.
 *
 * 동작 순서
 *   1. Vite 개발 서버 기동
 *   2. adb reverse 로 기기의 localhost:3000 을 PC로 연결 (USB 경유)
 *   3. Capacitor 동기화 후, 생성된 설정에 개발 서버 주소 주입
 *   4. 디버그 APK 빌드·설치·실행
 *
 * 참고
 *   - 설치되는 앱은 `com.marklet.md.debug` 로 스토어 버전과 공존합니다.
 *   - 인앱 결제는 Play가 설치한 앱에서만 동작하므로 여기서는 확인할 수 없습니다.
 *   - 3번에서 수정하는 파일은 동기화 때마다 재생성되는 산출물이라 저장소에 영향이 없습니다.
 *
 * 사용법: npm run dev:device   (종료는 Ctrl+C)
 */

const { spawn, spawnSync, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');

const repoRoot = path.resolve(__dirname, '..');
const androidDir = path.join(repoRoot, 'android');
const PORT = 3000;
const DEV_URL = `http://localhost:${PORT}`;
const APP_ID = 'com.marklet.md.debug';
const MAIN_ACTIVITY = 'com.marklet.md.MainActivity';
const isWindows = process.platform === 'win32';

const generatedConfig = path.join(
    androidDir,
    'app',
    'src',
    'main',
    'assets',
    'capacitor.config.json',
);

/** adb 실행 파일 경로 찾기 (android/local.properties → 환경변수 → PATH) */
function resolveAdb() {
    const candidates = [];

    try {
        const localProps = fs.readFileSync(path.join(androidDir, 'local.properties'), 'utf8');
        const match = localProps.match(/^sdk\.dir=(.+)$/m);
        if (match) {
            const sdkDir = match[1].trim().replace(/\\:/g, ':').replace(/\\\\/g, '\\');
            candidates.push(path.join(sdkDir, 'platform-tools', isWindows ? 'adb.exe' : 'adb'));
        }
    } catch {
        // local.properties가 없으면 다음 후보로
    }

    for (const env of [process.env.ANDROID_HOME, process.env.ANDROID_SDK_ROOT]) {
        if (env) candidates.push(path.join(env, 'platform-tools', isWindows ? 'adb.exe' : 'adb'));
    }

    return candidates.find((c) => fs.existsSync(c)) ?? 'adb';
}

const adb = resolveAdb();

/** 유효한 JDK 경로 (JAVA_HOME이 깨져 있으면 PATH의 java에서 역추적) */
function resolveJavaHome() {
    const usable = (home) =>
        home &&
        fs.existsSync(path.join(home, 'bin', isWindows ? 'java.exe' : 'java')) &&
        fs.existsSync(path.join(home, 'lib', 'jvm.cfg'));

    if (usable(process.env.JAVA_HOME)) return process.env.JAVA_HOME;

    try {
        const javaBin = execFileSync(isWindows ? 'where' : 'which', ['java'], { encoding: 'utf8' })
            .split(/\r?\n/)
            .find(Boolean);
        const home = javaBin ? path.resolve(path.dirname(javaBin), '..') : null;
        if (usable(home)) return home;
    } catch {
        // 못 찾으면 그대로 진행
    }
    return process.env.JAVA_HOME;
}

function adbSync(args) {
    return spawnSync(adb, args, { encoding: 'utf8' });
}

/** USB로 연결된 실기기 시리얼 (에뮬레이터 제외) */
function findDevice() {
    const serials = (adbSync(['devices']).stdout ?? '')
        .split(/\r?\n/)
        .slice(1)
        .filter((line) => line.includes('\tdevice'))
        .map((line) => line.split('\t')[0])
        .filter((serial) => !serial.startsWith('emulator-'));

    return serials[0] ?? null;
}

/** 셸 경유 실행 (Windows의 .cmd/.bat 실행에 필요) */
function run(command, args, options = {}) {
    return spawn(command, args, {
        cwd: repoRoot,
        stdio: 'inherit',
        shell: true,
        ...options,
    });
}

function runToCompletion(command, args, options = {}) {
    const result = spawnSync(command, args, {
        cwd: repoRoot,
        stdio: 'inherit',
        shell: true,
        ...options,
    });
    return result.status === 0;
}

/** 개발 서버가 응답할 때까지 대기 */
async function waitForDevServer(timeoutMs = 60000) {
    const deadline = Date.now() + timeoutMs;

    while (Date.now() < deadline) {
        try {
            const res = await fetch(DEV_URL, { signal: AbortSignal.timeout(2000) });
            if (res.ok) return true;
        } catch {
            // 아직 기동 중
        }
        await new Promise((resolve) => setTimeout(resolve, 500));
    }
    return false;
}

/** 주입 전 원본 설정. 종료 시 이 내용으로 되돌립니다. */
let originalConfig = null;

/** 생성된 Capacitor 설정에 개발 서버 주소를 주입 */
function injectDevServer() {
    originalConfig = fs.readFileSync(generatedConfig, 'utf8');
    const config = JSON.parse(originalConfig);

    config.server = {
        ...config.server,
        url: DEV_URL,
        cleartext: true, // 개발 서버가 http이므로 필요
    };

    fs.writeFileSync(generatedConfig, JSON.stringify(config, null, 2));
}

/**
 * 주입한 개발 서버 주소를 제거
 *
 * 남겨두면 이후 릴리스 빌드가 localhost를 로드하는 앱이 되어 흰 화면이 됩니다.
 */
function restoreConfig() {
    if (originalConfig === null) return;
    try {
        fs.writeFileSync(generatedConfig, originalConfig);
        console.log('↩️  Capacitor 설정을 되돌렸습니다.');
    } catch (err) {
        console.error('⚠️  설정 복원 실패. 릴리스 전에 `npm run build:android`를 실행하세요:', err);
    }
    originalConfig = null;
}

async function main() {
    const device = findDevice();
    if (!device) {
        console.error('❌ USB로 연결된 기기를 찾지 못했습니다. USB 디버깅을 확인하세요.');
        process.exit(1);
    }
    console.log(`📲 대상 기기: ${device}`);

    console.log('🚀 Vite 개발 서버를 시작합니다...');
    const vite = run('npm', ['run', 'dev']);

    let shuttingDown = false;
    const shutdown = () => {
        if (shuttingDown) return;
        shuttingDown = true;
        console.log('\n🧹 정리 중...');
        restoreConfig();
        adbSync(['-s', device, 'reverse', '--remove', `tcp:${PORT}`]);
        vite.kill();
    };

    process.on('SIGINT', shutdown);
    process.on('exit', shutdown);
    vite.on('exit', (code) => {
        if (!shuttingDown) {
            console.error(`❌ 개발 서버가 종료되었습니다 (code ${code})`);
            process.exit(code ?? 1);
        }
    });

    if (!(await waitForDevServer())) {
        console.error(`❌ 개발 서버가 ${DEV_URL} 에서 응답하지 않습니다.`);
        shutdown();
        process.exit(1);
    }
    console.log(`✅ 개발 서버 준비 완료 (${DEV_URL})`);

    // 기기의 localhost:3000 → PC의 개발 서버 (USB 경유, Wi-Fi 불필요)
    if (adbSync(['-s', device, 'reverse', `tcp:${PORT}`, `tcp:${PORT}`]).status !== 0) {
        console.error('❌ adb reverse 설정에 실패했습니다.');
        shutdown();
        process.exit(1);
    }
    console.log(`🔌 adb reverse 설정 완료 (기기 localhost:${PORT} → PC)`);

    console.log('🔄 Capacitor 동기화...');
    if (!runToCompletion('npm', ['run', 'sync:android'])) {
        shutdown();
        process.exit(1);
    }

    injectDevServer();
    console.log('⚙️  개발 서버 주소 주입 완료');

    console.log('🏗️  디버그 APK 빌드 (처음에는 시간이 걸립니다)...');
    const gradlew = path.join(androidDir, isWindows ? 'gradlew.bat' : 'gradlew');
    if (
        !runToCompletion(`"${gradlew}"`, [':app:assembleDebug'], {
            cwd: androidDir,
            env: { ...process.env, JAVA_HOME: resolveJavaHome() },
        })
    ) {
        shutdown();
        process.exit(1);
    }

    const apk = path.join(androidDir, 'app', 'build', 'outputs', 'apk', 'debug', 'app-debug.apk');
    console.log('📦 설치 중...');
    if (!runToCompletion(`"${adb}"`, ['-s', device, 'install', '-r', `"${apk}"`])) {
        shutdown();
        process.exit(1);
    }

    adbSync(['-s', device, 'shell', 'am', 'start', '-n', `${APP_ID}/${MAIN_ACTIVITY}`]);

    console.log('');
    console.log('✅ 라이브 리로드 실행 중');
    console.log('   코드를 저장하면 기기 화면이 즉시 갱신됩니다.');
    console.log('   로그: npm run logcat -- --focus');
    console.log('   종료: Ctrl+C');
    console.log('');

    // Vite가 살아있는 동안 유지
    await new Promise(() => {});
}

main();
```

**놓치기 쉬운 지점**

- `am start -n` 의 컴포넌트 이름이 **`com.marklet.md.debug/com.marklet.md.MainActivity`**
  다. 앞은 `applicationId`(suffix 포함), 뒤는 **자바 클래스의 실제 패키지**다.
  `applicationIdSuffix`는 자바 패키지를 바꾸지 않는다. 여기를 `...debug.MainActivity`로 쓰면
  `Activity class does not exist` 가 난다.
- `adb reverse`를 쓰므로 **Wi-Fi가 필요 없다.** 기기의 `localhost:3000`이 USB를 타고
  PC로 온다. `cap run -l`의 LAN IP 방식과 달리 회사·카페 네트워크에서도 된다.
- `cleartext: true`가 필요하다. 개발 서버가 http이고 앱은 `androidScheme: https`이므로
  이 플래그 없이는 차단된다.
- 종료 시 `restoreConfig()`를 부르지만 **터미널 창을 그냥 닫으면 안 불린다.**
  그래서 `assert-no-dev-server.cjs`가 있다.

### 3-7. `scripts/remove-flatdir.cjs`

```js
#!/usr/bin/env node

/**
 * Capacitor Hook - flatDir 경고 제거 스크립트
 *
 * cap sync 후 자동으로 실행되어 flatDir를 제거합니다.
 */

const fs = require('fs');
const path = require('path');

const buildGradlePath = path.join(
    __dirname,
    '..',
    'android',
    'capacitor-cordova-android-plugins',
    'build.gradle',
);

console.log('🔧 [Post-Sync Hook] flatDir 경고 제거 중...');

try {
    if (!fs.existsSync(buildGradlePath)) {
        console.log('⚠️  build.gradle 파일을 찾을 수 없습니다:', buildGradlePath);
        process.exit(0);
    }

    let content = fs.readFileSync(buildGradlePath, 'utf8');

    // flatDir 블록 제거 (정규식 사용)
    const flatDirPattern = /repositories\s*\{([^}]*?)flatDir\s*\{[^}]*\}([^}]*?)\}/s;

    if (flatDirPattern.test(content)) {
        content = content.replace(
            flatDirPattern,
            "repositories {$1// flatDir 제거: fileTree(dir: 'src/main/libs')로 이미 처리됨 (경고 해결)$2}",
        );

        fs.writeFileSync(buildGradlePath, content, 'utf8');
        console.log('✅ flatDir 제거 완료!');
    } else {
        console.log('✨ flatDir가 이미 제거되어 있습니다.');
    }
} catch (error) {
    console.error('❌ flatDir 제거 중 오류:', error.message);
    // 빌드를 중단하지 않도록 exit(0)
    process.exit(0);
}
```

**왜 필요한가.** `cordova-plugin-purchase`는 Cordova 플러그인이라
`android/capacitor-cordova-android-plugins/build.gradle`이 자동 생성되고, 거기에
`flatDir` 저장소 선언이 들어간다. Gradle 8은 `flatDir` 사용에 대해 매 빌드마다 경고를
쏟는다. 그 파일은 `cap sync`마다 다시 생성되므로 손으로 고쳐도 소용없다.
그래서 `sync:android` 스크립트가 sync 직후에 이 후처리를 항상 돌린다.

**실패해도 `exit(0)`인 것이 의도적이다.** 경고 제거는 빌드를 막을 만한 일이 아니다.

## 4. 사람이 직접 해야 하는 것 — 한 단계씩

에이전트가 할 수 없는 일이다. 사장님이 손으로 눌러야 한다.
아래 순서를 지켜라. 순서를 어기면 서로를 기다리게 된다.

### 4-1. 릴리스 키스토어 만들기 (최초 1회, 되돌릴 수 없음)

> **⚠ 2026-08-03 — 이 절의 파일 이름과 별칭은 `03_출시_절차서.md` 2-1절이 대체했다.**
> 아래는 `release-key.keystore` / 별칭 `mdreader`를 쓰는데, **확정값은
> `marklet-upload-key.keystore` / 별칭 `marklet`이다.** 명령의 형태와 화면 순서,
> `-storepass`를 명령줄에 쓰지 말라는 경고는 그대로 유효하니 그 부분만 참고하고,
> **이름은 `03_출시_절차서.md`의 것을 써라.** 백업도 3곳이다(그 문서 2-6절).
> (`00_시작하기.md` 정비 기록 참조. 01~03이 04~07보다 우선한다.)

터미널에서 `android/app/` 디렉터리로 가서 실행한다.

```bash
keytool -genkeypair -v \
  -keystore release-key.keystore \
  -alias mdreader \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -storetype PKCS12
```

**`-storepass` / `-keypass`를 명령줄에 쓰지 마라.** 셸 히스토리에 평문으로 남는다.
위처럼 생략하면 keytool이 대화식으로 묻는다.

화면에서 보게 되는 것 (실제 순서):

1. `키 저장소 비밀번호 입력:` — 비밀번호를 친다. **화면에 아무것도 안 보인다.** 정상이다.
2. `새 비밀번호 다시 입력:`
3. `이름과 성을 입력하십시오.` → 아무거나 넣어도 된다. 예: `mdreader`
4. `조직 단위 이름을 입력하십시오.` → 비워도 된다 (Enter)
5. 조직 / 구/군/시 / 시/도 / 국가 코드 → 국가만 `KR`로 채우고 나머지는 Enter
6. `CN=mdreader, ..., C=KR이(가) 맞습니까? [아니오]:` → **`y`** 를 입력
7. 완료. `release-key.keystore` 파일이 생긴다.

그 다음 `android/keystore.properties`를 만든다 (`keystore.properties.example`을 복사):

```properties
storeFile=app/release-key.keystore
storePassword=<위에서 정한 비밀번호>
keyAlias=mdreader
keyPassword=<위와 같은 값>
```

**`storePassword`와 `keyPassword`가 같은 값인 것이 정상이다.** PKCS12 형식은 키별
비밀번호를 지원하지 않는다. `-keypass`로 다른 값을 줘도 keytool이 무시하고 경고만 낸다.
이 PC에서 실제로 확인한 경고 문구:

```
경고: 다른 저장소 및 키 비밀번호는 PKCS12 KeyStores에 대해 지원되지 않습니다.
사용자가 지정한 -keypass 값을 무시하는 중입니다.
```

**이 파일을 잃어버리면 앱 업데이트를 영원히 올릴 수 없다.**
Google Drive든 USB든 저장소 밖 두 곳 이상에 백업해라. 비밀번호는 파일과 **다른 곳에**
적어라(비밀번호 관리자). 같은 폴더에 메모를 두면 백업 하나가 새는 순간 둘 다 샌다.

### 4-6. 인앱 상품 등록 (소모성 팁)

Play Console → **수익 창출 → 제품 → 인앱 상품 → 상품 만들기**

세 개를 만든다. **상품 ID는 나중에 못 바꾼다.**

| 상품 ID | 이름 | 가격(대한민국) |
|---|---|---|
| `tip_coffee` | 커피 한 잔 | ₩1,500 |
| `tip_lunch` | 점심 한 끼 | ₩5,500 |
| `tip_dinner` | 저녁 한 끼 | ₩11,000 |

각 상품 화면에서:

- **상품 유형**: 인앱 상품 (구독 아님)
- **이름 / 설명**: 위 표대로. 설명에 "감사 표시로 후원자 배지와 테마가 열립니다" 정도를 쓴다
- 가격을 정하면 다른 국가는 Google이 자동 환산해 준다
- 저장 후 **활성화** 를 눌러야 앱에서 보인다. 안 누르면 상품이 안 내려온다

> **소모성/비소모성은 Play Console에서 고르는 값이 아니다.** 콘솔의 "인앱 상품"은
> 하나의 유형이고, 소모성인지 아닌지는 **앱이 구매를 소비(consume)하는지**로 결정된다.
> 코드에서 `ProductType.CONSUMABLE`로 등록하고 `finish()`를 부르면 소모된다. 5장 참조.

> **순수 기부는 심사에서 걸릴 수 있다.** 그래서 아주 작은 감사 표시를 돌려준다.
> 결정: **후원자 배지(설정 화면에 표시) + 읽기 테마 3종 해금.** 기능 제한을 걸지 않으므로
> "돈을 내야 쓸 수 있는 앱"이 아니고, 그렇다고 아무것도 안 주지도 않는다.

### 4-7. 라이선스 테스터 등록 (결제를 공짜로 테스트)

Play Console → **설정 → 라이선스 테스트** → 사장님 구글 계정 이메일을 추가 →
`라이선스 응답: RESPOND_NORMALLY` 로 둔다.

이러면 **실제 결제창이 뜨지만 돈이 빠져나가지 않는다.**
등록하지 않으면 테스트할 때마다 진짜로 결제된다.

**중요: 인앱결제는 Play가 설치한 앱에서만 동작한다.**
`npm run dev:device`로 설치한 디버그 APK에서는 결제창이 뜨지 않는다.
결제를 확인하려면 `npm run publish:internal`로 내부 테스트 트랙에 올리고,
테스터 링크로 Play 스토어에서 설치해서 확인해야 한다.

## 5. 인앱결제 — 픽셀오아시스 코드와 소모성 팁의 차이

### 5-1. 쓰는 플러그인

`cordova-plugin-purchase@13.18.0`. Cordova 플러그인이지만 Capacitor에서 그대로 동작한다.
전역 객체 이름은 **`window.CdvPurchase`** 다 (패키지 이름과 다르다).
Play Billing Library **9.0.0** 을 안에 물고 있다 (`plugin.xml`에서 확인).

설치:

```bash
npm install cordova-plugin-purchase@^13.18.0
npx cap sync android
```

**`deviceready` 이벤트를 기다려야 한다.** Cordova 플러그인이라 `document`에
`deviceready` 리스너를 붙여 그 안에서 초기화한다. Capacitor가 Cordova 브리지를 흉내내
이 이벤트를 발생시킨다.

### 5-2. 픽셀오아시스 `src/managers/purchase-manager.ts` — 실제 코드

**비소모성 상품 하나(`remove_ads`)** 를 다루는 코드다. 새 앱과 다른 점을 보려면 이걸 먼저
읽어야 한다. 광고 문구를 제외한 구조는 그대로 쓸 수 있다.

```ts
/**
 * PurchaseManager - 인앱 결제 관리
 */
import { Toast } from '../utils/toast';

class PurchaseManagerClass {
    readonly productId = 'remove_ads';
    private readonly storageKey = 'pixel_oasis_is_purchased';
    isPurchased = false;

    /**
     * 사용자가 방금 buy()로 시작한 구매인지 여부
     *
     * 비소비성 상품은 완결 후에도 APPROVED 상태로 남아 앱을 켤 때마다
     * approved 이벤트가 다시 전달됩니다. 그때마다 구매 완료 안내가 뜨지 않도록
     * 사용자가 직접 시작한 구매와 구분하는 데 사용합니다.
     */
    private purchaseRequested = false;

    private getCdvPurchase(): CdvPurchaseGlobal | null {
        return window.CdvPurchase || null;
    }

    init(): void {
        const initializeStore = () => {
            const CdvPurchase = this.getCdvPurchase();
            if (!CdvPurchase) {
                console.log('🛍️ Purchase plugin not available (Web environment?)');
                return;
            }

            const { store, ProductType, Platform } = CdvPurchase;

            // 플러그인 상세 로그 설정 (개발: 4(DEBUG), 배포: 0(QUIET))
            store.verbosity = import.meta.env.DEV ? 4 : 0;

            if (!ProductType || !Platform) {
                console.error('🛍️ Critical: Purchase constants are missing!');
                return;
            }

            // 제품 등록
            try {
                store.register([
                    {
                        id: this.productId,
                        alias: this.productId,
                        type: ProductType.NON_CONSUMABLE,
                        platform: Platform.GOOGLE_PLAY,
                    },
                ]);
            } catch (err) {
                console.error('🛍️ Failed to register product:', err);
            }

            store.ready(() => {
                const product = store.get(this.productId);
                if (product && product.valid) {
                    // 정상
                } else {
                    console.error('🛍️ Product not found or invalid. Triggering update...');
                    store.update();
                }
            });

            // 승인 처리 (결제 완료 직후)
            //
            // 영수증 검증 서버(store.validator)를 두지 않으므로 verify()를 거치지 않고
            // 바로 finish()로 거래를 완결합니다. finish()가 Google Play의 acknowledge에
            // 해당하며, 3일 내에 완결되지 않은 구매는 자동으로 환불됩니다.
            store.when().approved(async (transaction) => {
                const alreadyGranted = this.isPurchased;
                const userInitiated = this.purchaseRequested;
                this.purchaseRequested = false;

                if (userInitiated) Toast.info('결제 승인 중입니다...');

                // 사용자가 이미 결제를 마쳤으므로 권한을 먼저 부여합니다.
                // 완결에 실패하더라도 미완결 거래는 다음 실행 시 다시 전달되어 재시도됩니다.
                if (!alreadyGranted) {
                    this.isPurchased = true;
                    this.persistPurchase();
                    this.updateUI();
                }

                try {
                    // 이미 완결된 거래는 플러그인이 내부적으로 건너뜁니다.
                    await transaction.finish();
                } catch (err) {
                    console.error('🛍️ 거래 완결 실패 (다음 실행 시 재시도됩니다):', err);
                }

                if (userInitiated) {
                    Toast.success('고맙습니다! 이제 광고 없이 즐기실 수 있어요 ☕');
                } else if (!alreadyGranted) {
                    Toast.info('후원 내역을 복원했습니다. 고맙습니다 ☕');
                }
            });

            // 상태 업데이트 감지 (기존 구매 확인 등)
            store.when().updated((product: unknown) => {
                const prod = product as { id: string; state: string; owned: boolean };
                if (prod.id === this.productId && prod.owned && !this.isPurchased) {
                    this.isPurchased = true;
                    this.persistPurchase();
                    this.updateUI();
                }
            });

            store.error((error) => {
                // 구매가 완료되지 못했으므로 표시를 해제합니다.
                // 남겨두면 다음 실행 시 재전달되는 approved를 새 구매로 오인합니다.
                this.purchaseRequested = false;

                // 에러 코드 6 (ERROR_PURCHASE_CANCELLED)은 사용자 취소이므로 조용히 넘어감
                if (error.code === 6) {
                    Toast.info('취소되었습니다.');
                    return;
                }
                console.error(`Purchase error: ${error.message} (${error.code})`);
            });

            store.initialize([Platform.GOOGLE_PLAY]);

            // 초기화 직후 업데이트 강제 호출 (누락 방지)
            setTimeout(() => store.update(), 2000);

            // 로컬 저장소 상태 복원
            if (localStorage.getItem(this.storageKey) === 'true') {
                this.isPurchased = true;
                this.updateUI();
            }
        };

        // Cordova/Capacitor 환경에서는 deviceready가 필수
        document.addEventListener('deviceready', initializeStore, false);
    }

    private persistPurchase(): void {
        localStorage.setItem(this.storageKey, 'true');
    }

    async buy(): Promise<void> {
        const CdvPurchase = window.CdvPurchase;
        if (!CdvPurchase) {
            Toast.info('후원은 모바일 앱에서만 가능합니다.');
            return;
        }
        if (this.isPurchased) {
            Toast.info('이미 후원해 주셨어요. 고맙습니다 ☕');
            return;
        }

        const product = CdvPurchase.store.get(this.productId);
        if (!product) {
            Toast.error('상품 정보를 찾을 수 없습니다. (제품 객체 없음)');
            CdvPurchase.store.update();
            return;
        }
        if (!product.loaded || !product.valid || !product.state) {
            CdvPurchase.store.update();
        }

        // 이후 approved 이벤트가 앱 시작 시 재전달이 아니라
        // 사용자가 직접 시작한 구매임을 구분하기 위한 표시
        this.purchaseRequested = true;

        try {
            // v13 권장 방식: 오퍼(Offer)를 통한 주문
            if (product.getOffer && typeof product.getOffer === 'function') {
                const offer = product.getOffer();
                if (offer?.canPurchase) {
                    await offer.order();
                    return;
                }
            }
            // Fallback: 기존 ID 기반 주문
            CdvPurchase.store.order(this.productId);
        } catch (err) {
            this.purchaseRequested = false;
            const msg = err instanceof Error ? err.message : String(err);
            Toast.error(`결제 요청 중 예외 발생: ${msg}`);
        }
    }

    /**
     * 후원 버튼에 스토어가 내려준 표시 가격을 채운다
     *
     * 가격을 문구에 하드코딩하면 Play Console에서 가격을 바꾸는 순간 거짓이 되고,
     * 다른 통화를 쓰는 사용자에게는 처음부터 틀린 값이 보인다. 스토어가 지역·통화에
     * 맞춰 포맷한 값만 쓰고, 아직 받지 못했으면 가격을 생략한다.
     */
    private renderPrice(): void {
        const price = this.getFormattedPrice();
        // 모달 템플릿이 열릴 때마다 새로 복제되므로 매번 다시 채운다
        document.querySelectorAll('.remove-ads-price').forEach((el) => {
            el.textContent = price ? ` (${price})` : '';
        });
    }

    private getFormattedPrice(): string {
        const product = this.getCdvPurchase()?.store.get(this.productId);
        return product?.getOffer?.()?.pricingPhases?.[0]?.formattedPrice ?? '';
    }
}

export const PurchaseManager = new PurchaseManagerClass();
```

### 5-3. 과거에 있었던 버그 — "인앱결제 거래 완결 실패"

커밋 `0aa9f3c` (2026-07-28). 커밋 메시지 원문에서 옮긴다.

> approved 핸들러가 `transaction.verify().finished()`를 호출했으나
> `verify()`는 `Promise<void>`를 반환하므로 `.finished()`에서 TypeError가 발생했고,
> 그 아래의 구매 상태 저장·UI 갱신·성공 토스트가 모두 실행되지 않았다.
>
> 더 심각하게는 거래가 완결(acknowledge)되지 않아 Google Play가 3일 후
> 구매를 자동 환불했다. 실기기 로그에서 `acknowledged=false`로 확인.
>
> 영수증 검증 서버를 두지 않으므로 `transaction.finish()`를 직접 호출하도록 수정.
>
> `vite-env.d.ts`: transaction을 `unknown` 대신 `CdvPurchaseTransaction`으로 타입 지정.
> **기존 코드의 `@ts-expect-error`가 이 버그를 가리고 있었다.**
>
> 2025-12-30부터 존재한 버그로, 이번 마이그레이션과 무관하다.

**버그가 있던 코드:**

```ts
store.when().approved((transaction) => {
    Toast.info('결제 승인 중입니다...');
    // @ts-expect-error - verify exists
    transaction.verify().finished();   // ← 여기서 TypeError. 아래가 전부 죽는다
    this.isPurchased = true;
    this.persistPurchase();
    this.updateUI();
    Toast.success('구매가 완료되었습니다!');
});
```

**고친 코드:**

```ts
store.when().approved(async (transaction) => {
    // 사용자가 이미 결제를 마쳤으므로 권한을 먼저 부여합니다.
    // 완결에 실패하더라도 미완결 거래는 다음 실행 시 다시 전달되어 재시도됩니다.
    this.isPurchased = true;
    this.persistPurchase();
    this.updateUI();

    try {
        await transaction.finish();
    } catch (err) {
        console.error('🛍️ 거래 완결 실패 (다음 실행 시 재시도됩니다):', err);
    }

    Toast.success('구매가 완료되었습니다!');
});
```

**여기서 뽑아낼 교훈 네 개 — 새 앱에서도 그대로 적용된다.**

1. **`@ts-expect-error`를 붙여 타입 검사를 끄면 그 줄의 버그가 영원히 숨는다.**
   플러그인의 타입이 마음에 안 들면 억제하지 말고 `vite-env.d.ts`에 직접 인터페이스를 써라.
2. **영수증 검증 서버가 없으면 `verify()`를 부르지 마라.** `finish()`를 직접 부른다.
   `verify()`는 `store.validator`를 설정한 경우에만 쓰는 것이고, 그때는 `verified` 이벤트에서
   완결한다.
3. **완결(`finish`)을 3일 안에 안 하면 Google Play가 자동 환불한다.** 사용자는 돈을 냈고
   앱은 혜택을 줬는데 3일 뒤 돈만 돌아간다. 로그도 안 남는다(릴리스는 console을 지우므로).
4. **권한 부여를 완결보다 먼저 해라.** 완결이 네트워크 문제로 실패해도 사용자는 이미 돈을
   냈다. 미완결 거래는 다음 실행 때 다시 `approved`로 전달되므로 재시도된다.

### 5-4. 소모성 상품은 무엇이 달라지는가 — 플러그인 소스로 확인한 사실

`node_modules/cordova-plugin-purchase/www/store.js`를 직접 열어 확인했다.

**(1) `finish()`가 하는 일이 상품 유형에 따라 다르다.**

```js
if (product.type === CdvPurchase.ProductType.NON_RENEWING_SUBSCRIPTION
    || product.type === CdvPurchase.ProductType.CONSUMABLE) {
    if (!transaction.isConsumed)
        return this.bridge.consumePurchase(onSuccess, onFailure, receipt.purchaseToken);
}
else { // subscription and non-consumable
    if (!transaction.isAcknowledged)
        return this.bridge.acknowledgePurchase(onSuccess, onFailure, receipt.purchaseToken);
}
```

즉 **같은 `transaction.finish()` 호출이 소모성이면 `consumePurchase`, 비소모성이면
`acknowledgePurchase`로 갈린다.** 갈림의 기준은 `store.register()`에 준 `type`이다.

**→ `type: ProductType.CONSUMABLE`로 등록하지 않으면 consume이 아니라 acknowledge만
된다. 그러면 Google Play 입장에서 그 상품은 "이미 소유 중"이라 같은 사용자가 다시 살 수
없다.** 두 번째 후원 시도에서 `ITEM_ALREADY_OWNED` (에러 코드 7)가 뜬다.
**팁 상품에서 이건 치명적이다 — 재후원이 통째로 막힌다.**

**(2) 상태 전이도 다르다.**

```js
static toState(fromConstructor, state, isAcknowledged, isConsumed) {
    switch (state) {
        case PurchaseState.PURCHASED:
            if (isConsumed)        return TransactionState.FINISHED;
            else if (isAcknowledged) return TransactionState.APPROVED;
            else if (fromConstructor) return TransactionState.INITIATED;
            else                   return TransactionState.APPROVED;
        ...
```

- **비소모성**: acknowledge 후에도 `APPROVED`로 남는다 → **앱을 켤 때마다 `approved`
  이벤트가 다시 온다.** 픽셀오아시스가 `purchaseRequested` 플래그를 둔 이유다
  (커밋 `f080508`: "앱을 켤 때마다 구매 완료 안내가 반복되던 문제").
- **소모성**: consume 후 `FINISHED`가 되어 **다시 전달되지 않는다.**
  단, consume이 끝나기 전에 앱이 죽으면 다음 실행에서 `APPROVED`로 재전달된다.
  그때 다시 `finish()`를 불러 consume해야 하고, **감사 표시를 두 번 주면 안 된다.**

**(3) "복원"의 의미가 사라진다.**

비소모성은 재설치 후 `store.update()`로 소유권을 되찾을 수 있다. 소모성은 소비된 순간
Google Play에서 사라지므로 **복원할 근거가 없다.**

**결정: 새 앱에 "구매 복원" 버튼을 두지 마라.** 대신 후원자 배지는 로컬에만 저장하고,
설정 화면에 이렇게 한 줄을 둔다: "후원 표시는 이 기기에만 저장됩니다. 앱을 지우면 사라집니다."
서버가 없으므로 이게 정직한 설명이다.

### 5-5. 새 앱용 `purchase-manager.ts` — 소모성 팁 버전

위의 확인된 동작에 맞춰 다시 쓴 것이다. 그대로 쓰면 된다.

```ts
/**
 * TipManager — 소모성 팁(후원) 인앱결제
 *
 * 픽셀오아시스와 다른 점
 *   - 상품이 여러 개이고 전부 CONSUMABLE이다
 *   - finish()가 consume을 부르므로 재구매가 가능하다
 *   - 소비된 거래는 재전달되지 않으므로 "복원" 개념이 없다
 *   - 다만 consume 직전에 앱이 죽으면 다음 실행에서 재전달되므로
 *     transactionId로 중복 지급을 막는다
 */
import { Toast } from '../utils/toast';

/** Play Console에 등록한 상품 ID. 순서가 화면 표시 순서다. */
export const TIP_PRODUCT_IDS = ['tip_coffee', 'tip_lunch', 'tip_dinner'] as const;
export type TipProductId = (typeof TIP_PRODUCT_IDS)[number];

/** 감사 표시 상태를 담는 로컬 저장소 키 */
const STORAGE_KEY = 'mdreader_supporter';

interface SupporterState {
    /** 누적 후원 횟수 */
    count: number;
    /** 이미 처리한 거래 ID. consume 실패 후 재전달될 때 중복 지급을 막는다 */
    handled: string[];
}

class TipManagerClass {
    private state: SupporterState = { count: 0, handled: [] };

    /** 사용자가 방금 buy()로 시작한 구매인지 */
    private purchaseRequested = false;

    /** 후원자인가 (배지·테마 해금 조건) */
    get isSupporter(): boolean {
        return this.state.count > 0;
    }

    get tipCount(): number {
        return this.state.count;
    }

    init(): void {
        this.loadState();

        const initializeStore = () => {
            const CdvPurchase = window.CdvPurchase;
            if (!CdvPurchase) {
                console.log('🛍️ 결제 플러그인이 없습니다 (웹 환경).');
                return;
            }

            const { store, ProductType, Platform } = CdvPurchase;
            store.verbosity = import.meta.env.DEV ? 4 : 0;

            if (!ProductType || !Platform) {
                console.error('🛍️ 결제 상수가 없습니다.');
                return;
            }

            // 소모성으로 등록해야 finish()가 consume을 부른다.
            // NON_CONSUMABLE로 등록하면 acknowledge만 되어 재후원이 막힌다.
            store.register(
                TIP_PRODUCT_IDS.map((id) => ({
                    id,
                    alias: id,
                    type: ProductType.CONSUMABLE,
                    platform: Platform.GOOGLE_PLAY,
                })),
            );

            store.ready(() => {
                const missing = TIP_PRODUCT_IDS.filter((id) => !store.get(id)?.valid);
                if (missing.length) {
                    console.error('🛍️ 상품을 받지 못했습니다:', missing.join(', '));
                    store.update();
                }
                this.renderPrices();
            });

            store.when().approved(async (transaction) => {
                const txId = transaction.transactionId ?? '';
                const alreadyHandled = txId !== '' && this.state.handled.includes(txId);
                const userInitiated = this.purchaseRequested;
                this.purchaseRequested = false;

                // 사용자는 이미 결제를 마쳤다. 감사 표시를 먼저 반영한다.
                // consume에 실패해도 미완결 거래는 다음 실행에 재전달되어 재시도된다.
                if (!alreadyHandled) {
                    this.state.count += 1;
                    if (txId) this.state.handled.push(txId);
                    this.saveState();
                    this.updateUI();
                }

                try {
                    // 소모성이므로 이 호출이 consumePurchase로 간다.
                    // 이걸 부르지 않으면 3일 뒤 자동 환불되고, 그 전까지 재구매도 막힌다.
                    await transaction.finish();
                } catch (err) {
                    console.error('🛍️ 거래 완결 실패 (다음 실행 시 재시도됩니다):', err);
                }

                if (userInitiated && !alreadyHandled) {
                    Toast.success('고맙습니다! 큰 힘이 됩니다 ☕');
                }
            });

            store.error((error) => {
                this.purchaseRequested = false;

                // 6 = 사용자 취소
                if (error.code === 6) {
                    Toast.info('취소되었습니다.');
                    return;
                }
                // 7 = ITEM_ALREADY_OWNED. 소모성인데 이게 뜨면 이전 구매가
                //     consume되지 않은 것이다. update()가 미완결 거래를 다시 흘려보낸다.
                if (error.code === 7) {
                    Toast.info('이전 후원을 정리하는 중입니다. 잠시 후 다시 시도해 주세요.');
                    window.CdvPurchase?.store.update();
                    return;
                }
                console.error(`🛍️ 결제 오류: ${error.message} (${error.code})`);
            });

            store.initialize([Platform.GOOGLE_PLAY]);

            // 초기화 직후 한 번 더 — 상품 목록 누락 방지
            setTimeout(() => store.update(), 2000);
        };

        document.addEventListener('deviceready', initializeStore, false);
    }

    async buy(productId: TipProductId): Promise<void> {
        const CdvPurchase = window.CdvPurchase;
        if (!CdvPurchase) {
            Toast.info('후원은 앱에서만 가능합니다.');
            return;
        }

        const product = CdvPurchase.store.get(productId);
        if (!product) {
            Toast.error('상품 정보를 받지 못했습니다. 잠시 후 다시 시도해 주세요.');
            CdvPurchase.store.update();
            return;
        }

        this.purchaseRequested = true;

        try {
            const offer = product.getOffer?.();
            if (offer?.canPurchase) {
                await offer.order();
                return;
            }
            CdvPurchase.store.order(productId);
        } catch (err) {
            this.purchaseRequested = false;
            const msg = err instanceof Error ? err.message : String(err);
            Toast.error(`결제 요청 실패: ${msg}`);
        }
    }

    /**
     * 버튼에 스토어가 내려준 표시 가격을 채운다.
     * 가격을 코드에 적으면 Play Console에서 값을 바꾸는 순간 거짓이 되고,
     * 다른 통화를 쓰는 사용자에게는 처음부터 틀린 값이 보인다.
     */
    renderPrices(): void {
        const store = window.CdvPurchase?.store;
        for (const id of TIP_PRODUCT_IDS) {
            const price = store?.get(id)?.getOffer?.()?.pricingPhases?.[0]?.formattedPrice ?? '';
            document.querySelectorAll(`[data-tip-price="${id}"]`).forEach((el) => {
                el.textContent = price;
            });
            // 가격을 못 받았으면 버튼을 비활성화한다. 눌러도 결제창이 안 뜨기 때문이다.
            document.querySelectorAll(`[data-tip-buy="${id}"]`).forEach((el) => {
                (el as HTMLButtonElement).disabled = price === '';
            });
        }
    }

    updateUI(): void {
        this.renderPrices();
        document.body.classList.toggle('is-supporter', this.isSupporter);
        document.querySelectorAll('[data-tip-count]').forEach((el) => {
            el.textContent = String(this.state.count);
        });
    }

    private loadState(): void {
        try {
            const raw = localStorage.getItem(STORAGE_KEY);
            if (raw) this.state = { count: 0, handled: [], ...JSON.parse(raw) };
        } catch {
            // 깨졌으면 초기값 유지
        }
    }

    private saveState(): void {
        // handled가 무한히 자라지 않게 최근 50건만 남긴다
        if (this.state.handled.length > 50) {
            this.state.handled = this.state.handled.slice(-50);
        }
        try {
            localStorage.setItem(STORAGE_KEY, JSON.stringify(this.state));
        } catch (err) {
            console.error('후원 상태 저장 실패:', err);
        }
    }
}

export const TipManager = new TipManagerClass();
```

### 5-6. `vite-env.d.ts` — 플러그인 타입 선언

**`@ts-expect-error`로 때우지 말고 이 파일을 만들어라.** 5-3의 버그가 그래서 생겼다.

```ts
/// <reference types="vite/client" />

interface CdvPurchaseOffer {
    id: string;
    canPurchase: boolean;
    order: () => Promise<void>;
    pricingPhases?: { formattedPrice: string }[];
}

interface CdvPurchaseProduct {
    id: string;
    state: string;
    title: string;
    loaded: boolean;
    valid: boolean;
    canPurchase: boolean;
    owned: boolean;
    getOffer: () => CdvPurchaseOffer | undefined;
}

/**
 * 승인된 거래
 *
 * finish()가 Google Play의 acknowledge(비소모성) 또는 consume(소모성)에 해당합니다.
 * 3일 내에 완결되지 않은 구매는 자동으로 환불되므로 반드시 호출해야 합니다.
 */
interface CdvPurchaseTransaction {
    transactionId?: string;
    /** 거래를 완결합니다. 영수증 검증 서버가 없으면 이것을 직접 호출합니다. */
    finish: () => Promise<void>;
    /** store.validator를 설정한 경우에만 사용합니다. 완결은 verified 이벤트에서 처리합니다. */
    verify: () => Promise<void>;
}

interface CdvPurchaseGlobal {
    store: {
        verbosity: number;
        register: (
            product: { id: string; alias?: string; type: unknown; platform?: unknown } | unknown[],
        ) => void;
        get: (id: string) => CdvPurchaseProduct | undefined;
        when: () => {
            approved: (
                callback: (transaction: CdvPurchaseTransaction) => void | Promise<void>,
            ) => void;
            owned: (callback: (product: unknown) => void) => void;
            updated: (callback: (product: unknown) => void) => void;
        };
        error: (callback: (error: { code: number; message: string }) => void) => void;
        ready: (callback: () => void) => void;
        initialize: (platforms: unknown[]) => void;
        update: () => Promise<void>;
        order: (productId: string) => void;
    };
    ProductType: {
        CONSUMABLE: unknown;
        NON_CONSUMABLE: unknown;
        PAID_SUBSCRIPTION: unknown;
    };
    Platform: {
        GOOGLE_PLAY: unknown;
    };
}

interface Window {
    CdvPurchase?: CdvPurchaseGlobal;
}
```

### 5-7. 회귀 테스트 — 반드시 넣어라

픽셀오아시스는 완결 버그를 고치면서 테스트 3건을 추가했고, "`finish()` 호출을 제거하면
실패하는 것"을 확인했다. 새 앱도 같은 방식으로 최소 다음 네 개를 넣어라.

1. **승인된 거래에 대해 `finish()`를 정확히 1회 호출한다** — 안 부르면 자동 환불된다
2. **`finish()`가 거부(reject)해도 감사 표시는 유지된다** — 사용자는 이미 결제했다
3. **같은 `transactionId`가 두 번 전달되면 후원 횟수가 두 번 오르지 않는다**
4. **`ProductType.CONSUMABLE`로 등록한다** — `register`에 넘긴 인자를 그대로 검사

3번과 4번이 소모성 팁에서 새로 필요한 것이다.

`store` 모의는 `approved` 콜백을 붙잡아 직접 실행하는 방식으로 만든다:

```ts
function setupStore() {
    let approvedCallback: ((t: unknown) => void | Promise<void>) | undefined;

    const mockStore = {
        register: vi.fn(),
        when: vi.fn(() => ({
            approved: vi.fn((cb) => { approvedCallback = cb; return { approved: vi.fn(), updated: vi.fn() }; }),
            updated: vi.fn(() => ({ approved: vi.fn(), updated: vi.fn() })),
        })),
        error: vi.fn(), initialize: vi.fn(), update: vi.fn(),
        order: vi.fn(), ready: vi.fn(), get: vi.fn().mockReturnValue({}),
    } as unknown as CdvPurchaseGlobal['store'];

    window.CdvPurchase = {
        store: mockStore,
        ProductType: { CONSUMABLE: 'consumable' },
        Platform: { GOOGLE_PLAY: 'google-play' },
    } as unknown as CdvPurchaseGlobal;

    TipManager.init();

    // deviceready 리스너를 직접 실행
    const listener = (document.addEventListener as unknown as ReturnType<typeof vi.fn>)
        .mock.calls.find((c) => c[0] === 'deviceready')?.[1];
    listener?.();

    return () => approvedCallback;
}
```

> **모의가 구현과 어긋난 채 통과한 사례가 픽셀오아시스에 여러 번 있었다.**
> 완결 버그 때도 "기존 테스트 모의가 버그 있는 API 형태를 흉내내고 있어" 테스트가
> 초록불이었다. 모의를 만들 때는 `node_modules`의 실제 타입 정의를 열어 확인해라.

### 함정 1. Android Studio 번들 JBR이 깨져 gradle이 조용히 실패한다

**증상.** `gradlew`를 돌렸는데 아무 일도 안 일어나거나 알 수 없는 오류로 끝난다.
그런데 기기에는 앱이 **설치돼 있다.** 그래서 "빌드는 됐구나" 하고 테스트를 계속한다.
실제로 설치돼 있던 것은 **하루 전에 만든 APK**였다. 고친 내용이 하나도 반영되지 않은
상태로 몇 시간을 검증했다.

**원인.** `JAVA_HOME`이 Android Studio 번들 JDK(JetBrains Runtime, `jbr`)를 가리키고 있고,
스튜디오가 업데이트되는 동안 그 디렉터리의 내용물이 반쯤 지워진다.
`bin/java.exe`는 남아 있는데 `lib/jvm.cfg`가 없는 상태가 된다. 런처는 존재하지만 JVM이 뜨지 못한다.

**이 PC에서 지금 이 순간 재현되는 상태다.** 2026-07-31에 확인:

```bash
$ echo "$JAVA_HOME"
C:\Program Files\Android\Android Studio\jbr

$ ls "/c/Program Files/Android/Android Studio/jbr/bin/java.exe"
/c/Program Files/Android/Android Studio/jbr/bin/java.exe     ← 있다

$ ls "/c/Program Files/Android/Android Studio/jbr/lib/jvm.cfg"
ls: cannot access '...': No such file or directory           ← 없다
```

`JAVA_HOME`이 지금도 깨진 경로를 가리키고 있다. 스크립트의 JDK 자동 탐색이 없으면
**오늘도 빌드가 안 된다.**

**해결.** `bin/java` 존재만으로 판단하면 안 된다. `lib/jvm.cfg`까지 확인한다.

```js
function isUsableJdk(home) {
    if (!home) return false;
    const javaBin = path.join(home, 'bin', isWindows ? 'java.exe' : 'java');
    // jvm.cfg가 없으면 런타임이 반쯤 지워진 상태(스튜디오 업데이트 중)입니다.
    const jvmCfg = path.join(home, 'lib', 'jvm.cfg');
    return fs.existsSync(javaBin) && fs.existsSync(jvmCfg);
}
```

그리고 유효하지 않으면 PATH의 `java`에서 홈을 역추적해 **자식 프로세스에만** `JAVA_HOME`을
넘긴다. 시스템 환경변수는 건드리지 않는다 (Android Studio는 자기 JBR을 기대하고 있으므로
전역을 바꾸면 스튜디오 쪽이 깨진다).

**`org.gradle.java.home`만으로는 왜 부족한가.**

`gradle.properties`의 `org.gradle.java.home`은 **Gradle 데몬이 어느 JDK로 빌드를 수행할지**를
정하는 값이다. 그런데 그 값을 읽으려면 먼저 **Gradle 런처 JVM이 떠야 한다.**
런처를 띄우는 것은 `gradlew.bat` 스크립트이고, 그 스크립트는 `JAVA_HOME` → PATH의 `java`
순서로 실행 파일을 찾는다.

즉 `JAVA_HOME`이 깨져 있으면 `gradle.properties`를 **읽기도 전에** 죽는다.
`org.gradle.java.home`은 이 문제를 절대 고칠 수 없다.
게다가 `gradle.properties`에 절대 경로를 박으면 다른 PC에서 clone했을 때 그대로 깨진다.
**JDK 경로는 파일에 적지 말고 실행 시점에 찾아라.** 그게 `build-aab.cjs`의 `resolveJdk()`다.

**추가로 확인할 것.** 이 PC의 `where java` 결과:

```
C:\Program Files\Eclipse Adoptium\jdk-21.0.9.10-hotspot\bin\java.exe
C:\Program Files\Eclipse Foundation\jdk-8.0.302.8-hotspot\bin\java.exe
```

**JDK 8이 PATH 두 번째에 있다.** 순서가 뒤바뀌면 폴백이 JDK 8을 집어서 AGP 8.13이
`Unsupported class file major version` 으로 죽는다. 폴백을 믿기 전에 한 번은
`java -version`으로 21이 나오는지 봐라.

### 함정 2. 키스토어 비밀번호가 추적 대상 문서에 들어가 유출됐다

커밋 `ada4447` (2026-07-31), 제목 "보안: 커밋된 임시 메모에서 키스토어 비밀번호 제거".

**무슨 일이 있었나.** `.docs/_temp.md`가 git에 추적된 채 **키스토어 비밀번호와 키
비밀번호를 평문으로** 담고 있었다. `origin/master`에도 올라가 있었고 **9개 커밋에 걸쳐**
남아 있었다. 파일 자체는 1.0.7 시절 Android Studio 수동 빌드 절차를 적어 둔 작업 메모였다.
누가 악의로 넣은 게 아니라, 빌드하면서 임시로 적어 둔 것이 그대로 커밋된 것이다.

**피해 범위를 먼저 확인했다.** 이 순서를 그대로 따라라.

```bash
# 1) 저장소가 공개인지 확인 (비공개였다 — 비인증 GitHub API 조회가 404)
# 2) 키 파일 자체가 커밋된 적이 있는지 — 전체 이력에서 추가 이벤트를 찾는다
git log --all --diff-filter=A --format="%h %s" -- \
  "*.keystore" "*.jks" "android/keystore.properties" "android/play-service-account.json"
#   → 0건

# 3) 지금 실제로 무시되고 있는지
git check-ignore -v android/keystore.properties android/play-service-account.json
#   → 두 줄 다 규칙에 걸림
```

**결론: 유출된 것은 비밀번호 문자열뿐이고 키스토어 파일 자체는 안전했다.**
파일이 없으면 비밀번호만으로는 서명할 수 없다. 그래도 원격 이력에 남아 있으므로
비밀번호는 교체해야 한다.

**회전(교체) 절차.**

Play 앱 서명을 쓰고 있으면 **업로드 키만 바꾸면 된다.** 앱 서명 키는 Google이 갖고 있어
사용자 설치본에는 영향이 없다.

1. 새 키스토어를 만든다 (4-1 절차)
2. Play Console → **설정 → 앱 서명 → 업로드 키 재설정 요청**
3. 새 키의 인증서를 내보내 첨부한다:
   ```bash
   keytool -export -rfc -keystore new-key.keystore -alias mdreader -file upload_certificate.pem
   ```
4. Google의 승인을 기다린다 (수 일)
5. 승인되면 `android/keystore.properties`를 새 값으로 바꾼다
6. **옛 비밀번호를 쓰는 문서·메모를 전부 지운다**

**같은 실수를 막기 위해 `.gitignore`에 넣은 규칙:**

```gitignore
# 자격증명이 섞이기 쉬운 임시 메모
.docs/_temp.md
```

작업 메모를 `.docs/_temp.md` 한 곳으로 몰고, 그 파일을 통째로 무시한다.
"조심하자"가 아니라 구조로 막는 것이다.

### 함정 3. `keytool -list`는 store 비밀번호만 검증한다

**이걸 모르면 "비밀번호가 맞다"고 확인해 놓고 빌드에서 실패한다.**

`keytool -list -keystore f.keystore -storepass XXX` 가 성공해도 **key 비밀번호가 맞는지는
전혀 확인되지 않았다.** `-list`는 인증서 목록을 읽을 뿐 개인 키를 건드리지 않기 때문이다.

**이 PC에서 직접 실험해 확인했다** (JDK 21, 실험 후 파일 삭제):

```bash
# store=STORE111, key=KEY222 로 JKS 키스토어 생성
keytool -genkeypair -storetype JKS -keystore j.keystore -alias a \
  -keyalg RSA -keysize 2048 -validity 100 -storepass STORE111 -keypass KEY222 -dname "..."

# (1) -list 는 store 비밀번호만으로 성공한다
keytool -list -keystore j.keystore -storepass STORE111      → exit 0   ← key 비번은 검사 안 됨

# (2) 개인 키를 실제로 쓰는 명령은 key 비밀번호를 검증한다
keytool -certreq -alias a -keystore j.keystore -storepass STORE111 -keypass WRONGPW  → exit 1
keytool -certreq -alias a -keystore j.keystore -storepass STORE111 -keypass KEY222   → exit 0
```

**key 비밀번호까지 확인하려면 `-certreq`를 써라:**

```bash
keytool -certreq -alias <별칭> -keystore <파일> -storepass <store> -keypass <key> > /dev/null
echo $?     # 0이면 둘 다 맞다
```

**PKCS12에 대한 별도 사실.** JDK 9부터 keytool 기본 형식은 PKCS12이고,
**PKCS12는 키별 비밀번호를 지원하지 않는다.** 다른 값을 줘도 무시하고 경고만 낸다.
이 PC에서 확인한 실제 경고:

```
경고: 다른 저장소 및 키 비밀번호는 PKCS12 KeyStores에 대해 지원되지 않습니다.
사용자가 지정한 -keypass 값을 무시하는 중입니다.
```

→ **새로 만드는 키스토어라면 `storePassword`와 `keyPassword`가 같은 값이 정상이다.**
다르게 적어 두면 그 자체가 나중에 혼란을 만든다.

### 함정 4. 디버그 빌드 패키지명을 분리하지 않으면 스토어 설치본을 지워야 한다

```groovy
debug {
    // Play 앱 서명을 사용하므로 스토어 설치본과 서명이 달라 덮어쓸 수 없습니다.
    // 패키지명을 분리해 스토어 버전을 지우지 않고 나란히 설치·테스트합니다.
    applicationIdSuffix ".debug"
    versionNameSuffix "-debug"
}
```

**왜 필요한가.** Play 앱 서명을 쓰면 사용자가 받는 앱은 **Google의 키로** 서명된다.
로컬 디버그 빌드는 안드로이드 디버그 키로 서명된다. 패키지명이 같고 서명이 다르면
`adb install -r`이 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`로 거부한다.
설치하려면 스토어 버전을 **지워야** 하고, 그러면 그 앱의 로컬 데이터도 같이 날아간다.

패키지명을 나누면 두 앱이 홈 화면에 나란히 있는다.
스토어 버전에서 실제 사용 데이터를 유지한 채 개발 버전을 계속 갈아엎을 수 있다.

**따라오는 함정 두 개.**

1. **`am start`의 컴포넌트 이름.** `applicationIdSuffix`는 자바 패키지를 바꾸지 않는다.
   ```bash
   # 맞다
   adb shell am start -n com.marklet.md.debug/com.marklet.md.MainActivity
   # 틀리다 — Activity class does not exist
   adb shell am start -n com.marklet.md.debug/com.marklet.md.debug.MainActivity
   ```
2. **logcat이 어느 쪽을 볼지 정해야 한다.** `logcat.cjs`가
   `['com.marklet.md.debug', 'com.marklet.md']` 순서로 `pidof`를 돌려
   실행 중인 쪽을 찾는다. 디버그를 앞에 둔 이유는 로그가 더 많이 나오기 때문이다.
3. **인앱결제는 `.debug` 빌드에서 동작하지 않는다.** Play가 설치한 앱이 아니기 때문이다.
   결제 확인은 반드시 내부 테스트 트랙을 거쳐야 한다.

### 함정 5. 서비스 계정에 일부러 프로덕션 권한을 주지 않는다

**권한을 주면 스크립트 한 줄로 전 세계 사용자에게 배포가 나간다.**
`node scripts/publish.cjs production`은 프로덕션 트랙에 즉시 올리고, GPP 설정이
`releaseStatus = COMPLETED`라 **단계적 출시도 아니고 100% 즉시 공개다.**

`publish.cjs`에 `yes` 입력 확인이 있지만 그건 사람이 실수로 엔터를 누르는 것만 막는다.
**에이전트가 자동으로 돌리는 경우, 또는 다른 트랙을 올리려다 인자를 틀리는 경우는 못 막는다.**

그래서 서비스 계정에는 내부·비공개 테스트 트랙 권한만 준다.
프로덕션 승격은 **Play Console에서 사람이 직접** 한다.
"내부 테스트에서 확인된 빌드를 프로덕션으로 승격" 버튼 한 번이라 번거롭지도 않다.

이 조합이 만드는 성질이 좋다: **자동화는 되돌릴 수 있는 곳까지만 하고, 되돌릴 수 없는
곳에는 사람의 손을 한 번 넣는다.**

### 함정 6. 버전 번호를 두 곳에 적으면 반드시 어긋난다

픽셀오아시스 초기에는 `package.json`의 `version`과 `build.gradle`의 `versionName`·
`versionCode`를 손으로 맞췄다. 커밋 `a2459aa` 제목이 그냥 **"feat: 버전일치"** 다.
맞추는 작업 자체가 커밋이 될 만큼 자주 어긋났다는 뜻이다.

지금은 `build.gradle`이 `package.json`을 읽는다:

```groovy
def packageJson = new groovy.json.JsonSlurper().parseText(rootProject.file('../package.json').text)
def appVersionName = packageJson.version
def (verMajor, verMinor, verPatch) = appVersionName.tokenize('.').collect { it.toInteger() }
def appVersionCode = verMajor * 10000 + verMinor * 100 + verPatch
```

**주의할 점:**

- minor·patch가 **99를 넘으면 안 된다.** `1.0.100` → `10100` = `1.1.0`과 충돌한다
- **같은 versionCode는 Play에 두 번 올릴 수 없다.** 업로드에 실패해 다시 올릴 때도
  patch를 올려야 한다. "빌드만 다시 했는데 왜 거부되지"의 답이 이것이다
- 버전 문자열이 `1.0` 처럼 두 자리면 `tokenize('.')` 결과가 2개라 구조분해에서 실패한다.
  **항상 세 자리로 쓴다**

### 함정 7. 개발 서버 주소가 릴리스에 섞이면 흰 화면인 앱이 나간다

커밋 `dbf19ef`. `dev:device`가 생성 설정에 주입한 `server.url = http://localhost:3000`이
남은 채 릴리스를 빌드하면, 설치는 되고 아이콘도 뜨는데 **열면 흰 화면**이다.
빌드 로그에는 아무 경고도 없다.

`dev:device`는 Ctrl+C 종료 시 설정을 되돌리지만 **터미널 창을 그냥 닫으면 안 돌아온다.**
그래서 `build:aab`와 `publish` 맨 앞에서 `assertNoDevServer()`를 한 번 더 검사한다.
(3-1절에 전문이 있다.)

**이 패턴 자체를 기억해라: 되돌리는 코드를 썼으면, 되돌아왔는지 확인하는 코드도 써라.**

### 함정 8. `npx cap run android -l`은 Windows에서 동작하지 않는다

커밋 `dbf19ef` 메시지 원문:

> `npx cap run android -l` 은 Windows에서 동작하지 않는다. Capacitor CLI가
> 자체 프로세스로 `'./gradlew'`를 실행하는데 cmd.exe가 이 경로 형식과
> 확장자 없는 셸 스크립트를 처리하지 못한다. 또한 cap run은 개발 서버를
> 직접 띄우지 않고, host 기본값이 LAN IP라 localhost 바인딩인 Vite에
> 기기가 접근할 수 없다.

그래서 `dev-device.cjs`가 `gradlew.bat`과 `adb`로 같은 일을 직접 한다.
**시간을 아끼려고 `cap run -l`부터 시도하지 마라. 안 된다.**

### 함정 9. Node 20+ 에서 `.bat`/`.cmd`는 `shell: true` 없이 실행되지 않는다

```js
spawnSync(`"${gradlew}"`, [':app:bundleRelease'], {
```

### 함정 10. 저장소 경로에 한글이 있으면 AGP가 빌드를 거부한다

### 함정 11. `cap sync`가 만드는 파일을 손으로 고치면 다음 sync에 사라진다

- `android/app/src/main/assets/capacitor.plugins.json`

**sync 뒤에 자동으로 다시 적용되는 후처리 스크립트**로 만들어라 (3-7절).

### 함정 12. 릴리스 빌드에서는 웹 로그가 보이지 않는다

두 겹으로 막혀 있다.

1. `vite.config.ts`의 `esbuild.drop: ['console','debugger']`가 릴리스에서 console 호출을 지운다
2. Capacitor의 `loggingBehavior` 기본값이 `debug`라 릴리스 빌드에서는 웹 로그를 네이티브로
   넘기지 않는다

**그래서 릴리스 빌드에서 "왜 안 되는지"를 로그로 알 수 없다.**
픽셀오아시스는 이것 때문에 사용자에게 보이는 실패를 여러 번 놓쳤다:

- 커밋 `e178e64`: "저장이 실패해도 console.error만 남는데 프로덕션은 console을 제거한다.
  사용자는 앱을 껐다 켠 뒤에야 작업이 사라진 것을 안다" → **Toast로 알리도록 고침**
- 커밋 `c956025`: DB 읽기 오류가 조용히 넘어가 저장된 작업을 덮어썼다
- 커밋 `f7fb980`: "BGM 로드 실패는 지금까지 조용히 무음이 되어 원인을 알 수 없었다"

**규칙: 사용자가 알아야 하는 실패는 console이 아니라 화면에 띄워라.**
마크다운 뷰어에서 이에 해당하는 것 — 파일 열기 실패, 인코딩 판별 실패, 저장 실패,
용량이 커서 렌더링을 포기한 경우.

### 함정 13. 미디어쿼리 `orientation: landscape`는 키보드가 올라와도 참이 된다

커밋 `30f0c2e`. 실기기 보고: "글자 입력 중일 때 이미지가 좌측 정렬되어 보인다".

> 원인은 미디어쿼리 조건이다. `orientation: landscape`는 **뷰포트 높이가 폭보다
> 작으면 참**이라, 세로로 든 기기에서 소프트 키보드가 올라와도 매칭된다.
> 브라우저에서 375×340으로 줄여 확인하니 실제로 landscape가 true였다.

**해결: 가로모드 전용 레이아웃은 `orientation`이 아니라 `min-width`로 걸어라.**

```css
/* 틀리다 — 키보드가 올라온 세로 화면도 잡는다 */
@media (orientation: landscape) { ... }

/* 맞다 — 진짜 가로는 폭이 넓다 */
@media (min-width: 600px) { ... }
```

확인 결과:

```
375×340 (키보드 올라온 세로)  → 2단 레이아웃 미적용
844×390 (진짜 가로)          → 2단 레이아웃 적용
```

**마크다운 뷰어는 편집 기능이 있으므로 이 함정을 반드시 만난다.**

### 함정 14. 한글 IME + `maxlength`는 마지막 글자를 덮어쓴다

커밋 `30020cb`. 실기기에서 나온 문제다.

> `maxlength="40"`과 한글 IME의 조합 탓이다. 조합 중인 글자도 value 길이에 포함되므로,
> 한도에 닿으면 브라우저가 새 입력을 거부하고 조합이 진행되지 못한다. 그래서 자모를
> 눌러도 새 글자가 되지 않고 **마지막 글자만 계속 바뀌었다.**

**해결: `maxlength` 속성을 쓰지 말고, `compositionstart`/`compositionend`를 추적해
조합이 끝난 뒤에만 자른다.** 영문처럼 조합이 없는 입력은 즉시 자른다.

같은 커밋에서 나온 것 두 개 더:

- **키보드를 닫을 방법이 없었다.** `enterkeyhint="done"`을 주면 키 모양만 바뀌고 동작은
  없다. `form` 안이면 브라우저가 처리하지만 form 밖이면 아무 일도 안 한다.
  **Enter를 받아 직접 `blur()`해라. 단, 조합 중인 Enter는 가로채면 안 된다**
  (한글 확정용 Enter까지 먹으면 글자가 씹힌다).
- **`<input>`은 부모의 `text-align`을 상속하지 않는다.** `<div>`에서 가운데였던 것이
  `<input>`으로 바꾸면 왼쪽으로 붙는다. `text-align: center`를 명시해야 한다.

### 함정 15. 키보드가 올라오면 입력칸이 화면 밖으로 나간다

커밋 `853ad93`.

> 포커스 시 `scrollIntoView`로 올리되, **포커스 직후가 아니라 `visualViewport`의
> `resize`를 기다린 뒤에** 옮긴다 — 키보드가 자리를 잡기 전에 계산하면 엉뚱한 위치로 간다.
> 모달의 `overflow`도 `hidden`에서 `auto`로 바꿨다. **스크롤될 여지가 없으면
> `scrollIntoView`가 아무것도 하지 않는다.**

두 가지가 세트다. 하나만 하면 안 고쳐진다.

### 함정 16. 여닫기 타이머가 겹치면 UI가 사라지고 뒤로가기를 먹는다

커밋 `13195dc`.

> 열기는 10ms 뒤 `.visible`을 붙이고 닫기는 300ms 뒤 `display:none`을 건다.
> 그 사이에 반대 동작이 들어오면 뒤늦게 터진 타이머가 새 상태를 덮어썼다.
> (…) 그때 화면에는 아무것도 없는데 `isOpen`은 true이고 뒤로가기 스택에 닫기 핸들러가 남아
> **안드로이드 뒤로가기 한 번을 잡아먹었다.**

**해결: 모달별로 걸린 타이머를 들고 있다가 반대 동작에서 취소한다.**

마크다운 뷰어의 목차 서랍·검색 패널·설정 시트가 전부 이 구조다. 처음부터 이렇게 만들어라.

### 함정 17. Tailwind의 `.hidden`이 컴포넌트 클래스에 진다

커밋 `3370254`. **6개 클래스 중 5개가 이 상태였다.**

> Tailwind는 style.css 맨 위에서 들어오므로 `.hidden{display:none}`이 가장 먼저 놓인다.
> 그 뒤의 컴포넌트 클래스가 `display`를 지정하면 같은 명시도(클래스 하나)에서
> **나중에 선언된 쪽이 이긴다.**

증상은 "숨겼는데 화면에 보이고, 눌러도 반응이 없다"이다.

**해결 두 가지를 같이 해야 한다.**

1. `src/css/utilities.css`를 만들어 `.hidden{display:none}`을 넣고,
   **CSS import 중 가장 마지막에** 불러온다.
   (처음에 `responsive.css`에 넣었더니 그 뒤에 오는 CSS를 못 이겼다.)
2. **`.hidden`을 페이드/애니메이션 용도로 쓰지 마라.** 픽셀오아시스는 시작 화면 페이드에
   `.hidden`을 쓰고 있어서 `.hidden`에 `display:none`을 걸 수 없었다.
   페이드용은 `.is-leaving` 같은 다른 이름으로 분리한다.

그리고 **import 순서를 검사하는 테스트를 넣었다.** 브라우저 없이 판정할 수 있다:
`utilities.css`가 마지막 import인지, `style.css`가 불러오는 파일에 `.hidden` 보정이 없는지.

### 함정 18. 백그라운드 전환 시 디바운스된 저장을 flush하지 않으면 데이터가 사라진다

커밋 `be7e44f`. 사용자가 직접 보고한 문제였다.

> `saveProgress()`는 1초 디바운스인데 백그라운드 전환 시 flush하지 않았다.
> 그래서 프로세스가 회수되면 그 1초 안의 변경이 사라졌다.

**해결:**

```ts
document.addEventListener('visibilitychange', () => {
    if (document.visibilityState === 'hidden') flushPendingSave();
});
```

**마크다운 뷰어에서 이건 더 중요하다.** 편집 중에 홈키를 누르면 사용자 문서가 날아간다.
`visibilitychange(hidden)`에서 즉시 저장해라. `beforeunload`는 안드로이드 WebView에서
믿을 수 없다.

같은 계열로 커밋 `a811c3f`가 있다: `destroy()`에서
`document.removeEventListener('visibilitychange', ...)`를 빼먹어 메모리 누수가 있었다.
**붙였으면 떼는 것도 같이 써라.**

### 함정 19. 존재하지 않는 전역을 검사하는 조건은 영원히 거짓이다

커밋 `82f814a`. 토스트 아이콘이 **한 번도** 렌더링되지 않았다.

> `toast.ts`가 `window.lucide`가 있는지 확인한 뒤 아이콘을 그렸는데, 그 값은 코드
> 어디에서도 할당되지 않았다. lucide는 `icons.ts`에서 ES 모듈로 import해 쓰기 때문이다.

**그리고 테스트가 `window.lucide`를 목으로 채워 넣어 이 결함을 가리고 있었다.**
목을 없애고 실제 라이브러리로 SVG가 생겼는지 확인하도록 바꾸자 드러났다.

같은 커밋에서: **lucide는 `<i>`를 `<svg>`로 `replaceChild`한다.** 그래서
`.foo i { ... }` 같은 셀렉터는 적용되지 않는다 (커밋 `610c9c9`에서 남은 하나를 더 잡았다).
아이콘 라이브러리를 쓸 거라면 CSS 셀렉터를 `svg`로 써라.

### 함정 20. 앱 용량 — 에셋이 AAB의 대부분을 차지한다

커밋 `f7fb980`: **BGM이 AAB의 68%(108.5MB)** 였다. Opus 64k로 바꿔 167MB → 88.6MB.

마크다운 뷰어에는 오디오가 없지만 같은 함정이 **폰트**에 있다.

`font-family: -apple-system, 'Noto Sans KR', 'Roboto', sans-serif` /
고정폭은 `ui-monospace, 'Roboto Mono', monospace`.
픽셀오아시스는 Google Fonts를 `<link>`로 불러왔는데, **그건 오프라인에서 깨진다.**
(픽셀오아시스는 PWA 캐시로 덮었지만 첫 실행에는 인터넷이 필요했다.)
시스템 폰트는 용량 0이고 오프라인에서도 확실하다.

### 함정 22. 스토어 등재 — 실제로 정책에 걸린 것들

`store/README.md`에 기록된 것 중 새 앱에도 그대로 해당하는 것:

- **없는 기능을 쓰면 메타데이터 정책 위반이다.** 픽셀오아시스는 실제로 한 번 걸렀다
  ("갤러리의 원본 비교는 아직 없는 기능이라 문장을 지웠다").
  마크다운 뷰어에서 위험한 것: "모든 마크다운 문법 지원", "PDF 내보내기" 같은 문구
- **순위 주장(`1위`, `최고`), 이용자 후기 인용, 전체 대문자**는 정책 위반
- **가격을 설명에 쓰지 마라.** 통화·지역별로 다르고 바뀌면 거짓이 된다
- 글자 수 상한: 앱 이름 30 / 간단한 설명 80 / 자세한 설명 4000
- **스크린샷은 앞 3장이 전부를 결정한다.** 목록에서 보통 3장까지만 보인다.
  브랜드용 히어로 화면을 1번에 두지 마라 — 예쁘지만 무슨 앱인지 말해주지 않는다
- **업로드 전에 폭 200px로 줄여서 봐라.** 목록에서 그 정도 크기로 나온다.
  그 크기에서 무슨 화면인지 모르겠으면 다시 찍는 게 맞다
- **문구 변경은 검색 색인 갱신에 며칠~2주 걸린다.** 바로 노출이 늘지 않아도 정상이다

**언어 폴백 규칙 (Android Publisher API로 확인한 사실).**
Play는 기기 언어에 맞는 등재가 있으면 그것을, 없으면 **앱의 기본 언어** 등재를 보여준다.
픽셀오아시스는 기본 언어가 `ko-KR`이라, 브라질·인도 사용자가 **한국어 설명을 읽고 있었다.**
en-US를 추가해도 **기기 언어가 영어인 사용자에게만** 효과가 있다.

→ **마크다운 뷰어는 처음부터 기본 언어를 `en-US`로 잡아라.** 개발자용 도구라 해외 비중이
크고, 한국어 등재는 따로 추가하면 한국 사용자는 그대로 한국어를 본다.
기본 언어는 나중에 바꾸기 번거롭다.

**이미지는 언어별로 따로 올리지 않으면 기본 언어 것이 재사용된다.** (API로 확인함 —
en-US의 이미지 개수가 0인 것이 정상이었다.)

## 7. 검증 방법 — adb로 에뮬레이터를 몰아 확인한다

에이전트가 화면을 보지 못해도 앱을 조작하고 결과를 확인할 수 있다.
픽셀오아시스에서 실제로 쓴 명령들이다.

### 7-1. adb 실행 파일 찾기

Windows에서 SDK 경로는 보통 `%LOCALAPPDATA%\Android\Sdk` 다.

```bash
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"
EMU="$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe"
```

PATH에 없어도 `android/local.properties`의 `sdk.dir`에서 찾을 수 있다.
**주의: properties 파일은 백슬래시와 콜론을 이스케이프한다.**
`D\:\\Android\\Sdk` 같은 형태라 `\\:` → `:`, `\\\\` → `\\` 로 되돌려야 경로가 된다.
(`logcat.cjs`의 `resolveAdb()`가 그렇게 한다.)

### 7-2. 기기 확인 — `-s`를 반드시 쓴다

```bash
adb devices
```

출력 예:

```
List of devices attached
emulator-5554	device
R3CT10ABCDE	device
```

**실기기와 에뮬레이터가 동시에 붙어 있으면 `adb`가 어느 쪽인지 모른다.**
이후 모든 명령에 `-s <시리얼>`을 붙여라. 안 붙이면 `more than one device` 로 실패하거나,
더 나쁘게는 엉뚱한 기기에서 실행된다.

`dev-device.cjs`는 시리얼이 `emulator-`로 시작하지 않는 것만 골라 실기기를 잡는다.

### 7-3. 에뮬레이터 띄우기

```bash
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd Medium_Tablet -no-boot-anim
```

픽셀오아시스는 `Medium_Tablet`(2560×1600, 320dpi, API 35)로 태블릿 스크린샷을 찍었다.
부팅에 20초~2분 걸린다.

**디버그 APK는 네이티브 라이브러리가 없어 x86_64 에뮬레이터에서 그대로 돈다.**
(Capacitor 앱은 순수 자바/웹이라 ABI 문제가 없다.)

부팅 완료를 기다리는 확실한 방법:

```bash
adb -s emulator-5554 wait-for-device shell 'while [[ -z $(getprop sys.boot_completed) ]]; do sleep 1; done'
```

### 7-4. 설치와 실행

```bash
# 디버그 APK 설치 (스토어 본앱과 패키지가 달라 충돌하지 않는다)
adb -s emulator-5554 install -r android/app/build/outputs/apk/debug/app-debug.apk

# 실행 — 앞은 applicationId(suffix 포함), 뒤는 자바 클래스의 실제 패키지
adb -s emulator-5554 shell am start -n com.marklet.md.debug/com.marklet.md.MainActivity

# 강제 종료 (재시작 검증용)
adb -s emulator-5554 shell am force-stop com.marklet.md.debug

# 데이터 초기화 (첫 실행 상태 재현)
adb -s emulator-5554 shell pm clear com.marklet.md.debug
```

### 7-5. 지금 어느 화면인지 확인

```bash
adb -s emulator-5554 shell dumpsys activity activities | grep topResumedActivity
```

출력 예:

```
topResumedActivity=ActivityRecord{a1b2c3 u0 com.marklet.md.debug/com.marklet.md.MainActivity t42}
```

**이게 왜 중요한가.** 앱이 크래시하면 액티비티가 사라지는데, 화면을 못 보는 에이전트는
"탭이 안 먹었나?" 하고 같은 조작을 반복하게 된다. 조작 전후로 이걸 한 번씩 확인하면
크래시를 즉시 안다.

앱이 살아 있는지만 보려면:

```bash
adb -s emulator-5554 shell pidof -s com.marklet.md.debug
```

PID가 안 나오면 죽은 것이다. (`logcat.cjs`가 이 방식으로 앱을 기다린다.)

### 7-6. 화면 조작

```bash
# 탭 (x y — 화면 픽셀 좌표)
adb -s emulator-5554 shell input tap 540 1200

# 스와이프 (x1 y1 x2 y2 지속시간ms) — 아래로 스크롤
adb -s emulator-5554 shell input swipe 540 1600 540 600 300

# 길게 누르기 = 같은 좌표로 긴 스와이프
adb -s emulator-5554 shell input swipe 540 1200 540 1200 800

# 텍스트 입력 (공백은 %s, 한글은 안 들어간다)
adb -s emulator-5554 shell input text "hello%sworld"

# 키 이벤트
adb -s emulator-5554 shell input keyevent KEYCODE_BACK      # 뒤로가기 (=4)
adb -s emulator-5554 shell input keyevent KEYCODE_HOME      # 홈 (=3)
adb -s emulator-5554 shell input keyevent KEYCODE_ENTER     # 엔터 (=66)
adb -s emulator-5554 shell input keyevent KEYCODE_APP_SWITCH # 최근 앱 (=187)
```

**`input text`로 한글은 입력되지 않는다.** adb는 ASCII 키 이벤트만 보낸다.
함정 14(한글 IME + maxlength)는 **adb로 재현할 수 없다.** 실기기에서 손으로 쳐야 한다.
픽셀오아시스도 그 버그는 실기기 보고로 알았다.

**좌표를 알아내는 방법.** 화면 크기를 먼저 본다:

```bash
adb -s emulator-5554 shell wm size
# Physical size: 1080x2400
```

그다음 스크린샷을 받아 눈으로 좌표를 읽는다 (7-8절).

### 7-7. 회전

두 가지 방법이 있고 **동작이 다르다.**

```bash
# (1) 설정으로 강제 고정 — 안정적이다. 스크린샷 찍을 때 이걸 써라
adb -s emulator-5554 shell settings put system accelerometer_rotation 0
adb -s emulator-5554 shell settings put system user_rotation 1
#   user_rotation: 0=세로, 1=가로(왼쪽), 2=거꾸로 세로, 3=가로(오른쪽)

# 자동 회전으로 되돌리기
adb -s emulator-5554 shell settings put system accelerometer_rotation 1

# (2) 에뮬레이터 콘솔로 물리 회전 흉내 — 센서 이벤트가 실제로 발생한다
adb -s emulator-5554 emu rotate
```

**둘을 구분해서 써라.**
`settings put`은 시스템이 방향을 고정하는 것이고, `emu rotate`는 기기를 실제로 돌린 것처럼
센서 값을 바꾼다. **`orientationchange` 이벤트나 `screen.orientation` API를 검증하려면
`emu rotate`를 써야 한다.** `settings put`은 그 경로를 타지 않는 경우가 있다.

회전 후에는 레이아웃이 자리 잡을 시간을 줘라 (0.5~1초). 바로 스크린샷을 찍으면 전환
중간 프레임이 잡힌다.

### 7-8. 스크린샷

```bash
adb -s emulator-5554 exec-out screencap -p > build/shot-01.png
```

**`exec-out`이어야 한다.** `adb shell screencap -p > f.png`를 쓰면 Windows에서
줄바꿈이 CRLF로 변환되어 **PNG가 깨진다.** `exec-out`은 바이너리를 그대로 흘린다.
픽셀오아시스의 `store/assets/SCREENSHOTS.md`에도 `exec-out`으로 적혀 있다.

찍은 파일은 Read 도구로 직접 볼 수 있다. 좌표를 재거나 레이아웃 깨짐을 확인할 때 쓴다.

### 7-9. 로그 보기

```bash
# 앱 프로세스 로그만 (PID를 먼저 구한다)
PID=$(adb -s emulator-5554 shell pidof -s com.marklet.md.debug)
adb -s emulator-5554 logcat --pid "$PID" -v brief

# 크래시만
adb -s emulator-5554 logcat -v brief AndroidRuntime:E System.err:W '*:S'

# 웹 console.log만 (디버그 빌드에서만 나온다)
adb -s emulator-5554 logcat -v brief 'Capacitor/Console:V' '*:S'

# 세션 시작 전에 비우기
adb -s emulator-5554 logcat -c
```

`npm run logcat`이 이 과정을 자동화한 것이다 (PID 재접속 포함).

### 7-10. 파일 넣고 빼기 — 마크다운 뷰어에 특히 필요하다

테스트용 `.md` 파일을 기기에 올려 두면 "다른 앱에서 열기" 흐름을 검증할 수 있다.

```bash
# PC → 기기의 다운로드 폴더
adb -s emulator-5554 push test.md /sdcard/Download/test.md

# 미디어 스캐너에 알려 파일 관리자에 즉시 보이게 한다 (안 하면 목록에 안 뜬다)
adb -s emulator-5554 shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Download/test.md

# 앱이 저장한 파일 확인
adb -s emulator-5554 shell ls -la /sdcard/Download/

# 기기 → PC
adb -s emulator-5554 pull /sdcard/Download/edited.md ./edited.md
```

**VIEW 인텐트를 직접 쏘아 파일 열기 경로를 테스트한다:**

```bash
adb -s emulator-5554 shell am start -a android.intent.action.VIEW \
  -d file:///sdcard/Download/test.md -t text/markdown \
  -n com.marklet.md.debug/com.marklet.md.MainActivity
```

이러면 파일 관리자를 거치지 않고 인텐트 처리 코드만 바로 확인할 수 있다.

### 7-11. 실제로 쓴 검증 시나리오 (픽셀오아시스 사례)

- **키보드 올라온 상태의 레이아웃**: 에뮬레이터(API 36, 1080×2400)에서 세로·가로 각각
  키보드를 올린 채 확인. 입력칸이 보이는지, 가운데 정렬인지, 완료 키로 닫히는지
- **홈키 이탈 시 데이터 유실**: `input keyevent KEYCODE_HOME` → `am force-stop` →
  다시 `am start` → 저장 내용 확인
- **모달 빠른 재탭**: 백드롭 탭으로 닫고 0.3초 안에 다시 탭 → `topResumedActivity`와
  화면 스크린샷으로 모달이 살아 있는지 확인 (함정 16)
- **회전 중 레이아웃**: `emu rotate` → 1초 대기 → `exec-out screencap`

### 7-12. 에뮬레이터로 확인할 수 **없는** 것

솔직하게 적어 둔다. 이건 실기기가 필요하다.

| 항목 | 이유 |
|---|---|
| 인앱결제 | Play가 설치한 앱에서만 동작. 내부 테스트 트랙을 거쳐야 한다 |
| 한글 IME 조합 | `input text`는 ASCII만 보낸다 (함정 14) |
| 실제 소프트 키보드 동작 | 에뮬레이터는 PC 키보드를 쓰면 화면 키보드가 안 뜬다. 설정에서 하드웨어 키보드를 꺼야 한다 |
| 삼성 One UI 고유 동작 | 로그 양, 폰트 크기 설정, 엣지 패널 등 |
| 기기 저장소 접근 권한 흐름 | 에뮬레이터에서도 되지만 제조사별 문서 앱과의 연동은 다르다 |

- `.eslintrc.cjs` (죽은 파일)

## 9. 확인하지 못한 것

추측을 사실처럼 쓰지 않기 위해 남긴다.

1. **JBR 사고 당시의 로그·커밋 기록은 찾지 못했다.**
   `scripts/build-aab.cjs`의 주석("JAVA_HOME이 Android Studio 번들 JDK(jbr)를 가리키는 경우,
   스튜디오 업데이트 중에는 그 경로가 사라져 gradlew 런처가 아예 뜨지 못합니다")과
   `isUsableJdk`가 `lib/jvm.cfg`를 검사한다는 사실, 그리고 **지금 이 PC에서
   `JAVA_HOME`이 실제로 깨져 있다는 것**은 직접 확인했다.
   "하루 지난 APK가 설치돼 있었다"는 구체적 정황은 사장님이 알려 준 내용이고
   저장소에서는 근거를 찾지 못했다. git log와 `.docs/` 전체를 검색했다.

2. **`org.gradle.java.home`을 실제로 시도했다가 실패한 기록은 없다.**
   `gradle.properties`에 그 항목 자체가 없다. 본문에 쓴 "런처가 먼저 떠야 하므로
   `org.gradle.java.home`으로는 못 고친다"는 **Gradle 실행 구조에 근거한 설명**이지
   이 저장소에서 재현한 결과가 아니다.

3. **키스토어 비밀번호 회전을 실제로 수행했는지는 확인하지 못했다.**
   커밋 `ada4447`은 유출된 메모를 지우고 `.gitignore` 규칙을 추가한 것까지다.
   커밋 메시지에 "비밀번호가 원격 이력에 남아 있으므로 교체가 필요하다"고 적혀 있지만,
   교체를 마쳤다는 후속 기록은 없다. **6-2절의 회전 절차는 Play 앱 서명 구조에 근거한
   일반 절차이고, 픽셀오아시스에서 실행된 절차가 아니다.**

4. **`emu rotate`를 픽셀오아시스에서 실제로 썼다는 기록은 없다.**
   저장소 문서에서 확인된 회전 방법은 `settings put system user_rotation` 뿐이다
   (`store/assets/SCREENSHOTS.md`). `emu rotate`는 에뮬레이터 콘솔 명령으로 알려진
   것이고, 이 세션에서 실행해 보지는 않았다.

5. **웹 조사를 하지 않았다.** WebFetch를 쓸 수 있었지만 이 임무는 "저장소에서 뽑아내는 것"
   이라 외부 문서를 확인하지 않았다. 특히 다음은 **원문 확인이 필요하다**:
   - Play 콘솔 UI 화면 문구(4장) — 콘솔은 자주 바뀐다
   - 미완결 구매의 자동 환불 기간이 "3일"인 것 — 코드 주석과 커밋 메시지의 서술이고
     Google 공식 문서를 이번에 확인하지 않았다
   - 안드로이드에서 `.md` 파일의 표준 MIME 타입 (`text/markdown`은 RFC 7763이지만
     기기별 파일 관리자가 어떻게 넘기는지는 실측이 필요하다)

6. **`keystore.properties`와 `play-service-account.json`의 실제 내용은 열지 않았다.**
   자격증명이므로 의도적으로 읽지 않았다. 구조(키 이름)는 `keystore.properties.example`과
   `build.gradle`의 읽는 코드로 파악했다.

7. **AAB 실제 용량은 재지 않았다.** 커밋 `f7fb980`에 "167MB → 88.6MB"로 기록되어 있으나
   현재 버전(1.0.37)의 값은 측정하지 않았다.
