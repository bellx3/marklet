# 01. 경쟁 조사 및 차별점 확정

조사일: 2026-07-30 ~ 2026-07-31
대상: Google Play 마크다운 뷰어·에디터 앱
목적: "마크다운 앱 시장이 블루오션이다"라는 가설 검증 + 차별점 3개 확정

---

## 0. 이 문서를 읽는 에이전트에게

이 문서는 **결론이 확정된 문서**다. 여기 적힌 차별점 3개(§7)와 판정(§8)은 이미 결정된 것이고,
앱을 만들 때 다시 논의할 대상이 아니다. 이후 문서(02, 03...)의 기능 명세는 전부 이 문서의
§7에서 파생된다.

조사 방법과 그 한계는 §1에 적어뒀다. **§1을 먼저 읽어라.** 이 문서의 숫자 중 어디까지가
확인된 것이고 어디부터가 추정인지 구분하지 않으면 잘못된 판단을 하게 된다.

## 1. 조사 방법과 한계 — 먼저 읽어라

### 1.1 실제로 쓴 방법

이 세션에서 `WebSearch` 도구는 오류를 냈다(`API Error: 400 output_config.effort 'xhigh' is
not supported when thinking is disabled`). 그래서 `WebFetch`만 썼다.

`play.google.com`을 `WebFetch`로 직접 받으면 **본문을 못 읽는다.** Play 스토어는 JS로 렌더링되고,
마크다운 변환 시 상단 내비게이션만 남고 잘린다. 4개 앱을 그렇게 시도했고 전부 실패했다.

작동한 경로는 세 가지다. 나중에 이 조사를 갱신할 때 그대로 쓰면 된다.

| 소스 | URL 형식 | 얻을 수 있는 것 |
|---|---|---|
| Play(리더 프록시 경유) | `https://r.jina.ai/https://play.google.com/store/apps/details?id=<pkg>&hl=en&gl=US` | 설치수 구간, 별점, 리뷰수, 최종 업데이트, 인앱결제/광고 라벨, 설명문, **리뷰 3~4건** |
| Play 검색(프록시 경유) | `https://r.jina.ai/https://play.google.com/store/search?q=<query>&c=apps&hl=ko&gl=KR` | 앱 목록 + 패키지명. **패키지명을 찾는 유일하게 안정적인 방법** |
| AndroidRank | `https://androidrank.org/application/<임의슬러그>/<pkg>` | **별점 분포(5/4/3/2/1 각각의 개수)**, 추정 설치수, 30·60일 성장률, 설치 마일스톤 이력 |
| APKCombo | `https://apkcombo.com/<슬러그>/<pkg>/` | 설치수 구간, 버전, 업데이트일 (Play 프록시가 막힐 때 백업) |

AndroidRank는 슬러그가 틀려도 패키지명이 맞으면 열리는 경우가 있으나, 등록 안 된 앱은 404다.
소규모 앱(1K+ 이하)은 대부분 등록돼 있지 않다.

`appbrain.com`, `apkfab.com`, `old.reddit.com`은 전부 **403 Forbidden**으로 막혔다.
Reddit 커뮤니티 의견은 이 조사에 포함되지 않았다 — 못 봤다.

### 1.2 확인 못 한 것 (추측으로 메우지 마라)

- **리뷰는 앱당 3~4건만 봤다.** Play는 스토어 페이지에 대표 리뷰 몇 건만 노출한다.
  전체 리뷰 본문은 접근하지 못했다. §4의 불만 목록은 **전수 조사가 아니라 표본**이다.
  다만 별점 분포(§2)로 불만의 *양*은 정량 확인했다.
- **기능 대조표(§5)는 대부분 스토어 설명문 기준이다.** 앱을 실제로 설치해서 검증하지 않았다.
  "지원한다고 써 있다"와 "실제로 된다"는 다르다. 특히 Mermaid·각주·목차는 설명문에 안 적혀
  있어도 되는 경우가 있고, 적혀 있어도 깨지는 경우가 있다.
  → **개발 착수 전에 상위 3개(Simple Markdown, Markdown Editor & MD Viewer, Markdown
    Viewer(TJ App))는 실기기에 설치해서 §5를 직접 검증할 것.** 이건 사람이 해야 한다.
- **정확한 설치 수는 Google이 공개하지 않는다.** "100,000+" 같은 구간만 공개된다.
  AndroidRank의 "추정 설치수"는 그쪽의 자체 추정이며, 검증하지 않았다.
- **iA Writer**: `ia.net/writer` 공식 페이지를 확인했다. 지원 플랫폼으로 **Mac, Windows,
  iPhone, iPad만 명시**돼 있고 Android는 없다. Play 검색 "iA Writer"에도 나오지 않는다.
  과거 Android 판이 있었다가 단종됐다는 얘기가 있으나 **단종 시점을 확인하지 못했다.**
  결론: **현재 Play에 없다. 경쟁 대상에서 제외.**
- **Epsilon Notes**: Play 검색 "Epsilon Notes"에 나오지 않는다. **패키지명을 찾지 못했다.**
  현재 Play에 없거나 한국 리전에서 안 보이는 것으로 보이나, 확정하지 못했다.
- **Markor**: `net.gsantner.markor`로 Play를 치면 **404**다. 오픈소스 진영(F-Droid/GitHub)
  에는 살아 있는 것으로 알려져 있으나 확인하지 않았다. **Play 스토어 경쟁자가 아니다.**
- **Logseq**: `com.logseq.app`로 Play를 치면 **404**다. Play에 없다.

## 3. 시장 구조 요약

조사한 20개 앱은 세 덩어리로 갈린다. 이걸 뭉뚱그리면 판단을 그르친다.

**(A) PKM/노트 앱** — Obsidian(500만), Joplin(50만), Zettel Notes(5만)
마크다운을 저장 형식으로 쓰는 지식관리 도구다. 볼트/동기화/백링크가 본체다.
설치수는 크지만 **"메모 앱을 찾는 사람"이 받는 앱**이지 "md 파일을 열고 싶은 사람"이
받는 앱이 아니다. 우리와 같은 수요를 놓고 싸우지 않는다.

**(B) 에디터 앱** — Simple Markdown(10만), Markdown Editor/Adeeteya(5만), PocketMark(1만),
Markdown Editor & MD Viewer(1만)
파일 하나를 열어 고치고 저장한다. **여기가 우리 경쟁 구역이다.**
그런데 이들의 ★1~2 비율이 15~29%이고, 불만 대부분이 "저장이 깨진다"다(§4).

**(C) 순수 뷰어 앱** — Markdown Viewer/TJ App(1만, ★2.6), 마크다운 뷰어(500+),
Pilcrow(50+), Markdown Mono(1천+)
**뷰어만 하는 앱 중 별점이 정상인 것은 설치 1천 이하뿐이다.**
설치 1만을 넘긴 유일한 순수 뷰어(TJ App)는 ★2.6이다.
→ **"뷰어 중심"이라는 사장님의 범위 결정은 맞다. 이 칸이 비어 있다.**
  단, "비어 있다"가 "수요가 있다"는 뜻은 아니다. §8에서 판정한다.

## 4. 불만 목록 — 별 1~2개의 이유

리뷰 원문 인용. 출처는 각 앱의 Play 스토어 페이지(2026-07-31 기준 노출 리뷰).
**표본이다. 전수 조사가 아니다.**

### 4.1 파일 저장이 깨진다 — 가장 크고, 가장 반복되는 불만

> "the text editing and save features are extremely frustrating. Half the time it errors
> out, the other half it saves to an unknown location rather than overwriting the original"
> — Paul Luminaux, 2026-06-14, **Simple Markdown**

> "if I save a document, and then open another, it has been consistent that I cannot edit."
> — Robb Sadler, 2026-01-21, ★5, **Simple Markdown** (★5인데도 이 버그를 적었다)

> 저장 시 파일명 뒤에 숫자가 붙은 중복 파일이 생기는데, 숫자가 `.md` **뒤에** 붙어서
> 쓸 수 없는 파일이 된다 — ★2, **Markdown Editor (Adeeteya)**

> 로컬 저장 시 가끔 에러가 나고, 가끔은 불완전한 파일이 저장된다. 작업 1시간을 날렸다
> — 별점 미표시, **Markdown Editor (Adeeteya)**

> "Lasted update broke it completely. Can't open any markdown files or text files...
> Can't save without an ad breaking the saving of the file."
> — 2026-07, **Easy Markdown**

> "Accidentally lost my content too many times...the exit button isn't red, it has an
> innocuous looking icon, and the app doesn't ask for confirmation to delete your work."
> — Kyle The Scientist, 2026-01-27, ★1, **Open Note**

> 저장 안 된 파일에 대해 아무 경고가 없어서 "I just lost a little work"
> — ★3, **Markdown Mono**

> "the 'share to' feature...is broken because instead of creating a new note, it'll replace
> an existing note at random which deletes all the text from said note."
> — Chee-Rex, ★4, **Joplin**

**정리: 이 카테고리의 ★1은 대부분 "내 파일이 없어졌다/망가졌다"다.**
기능이 부족해서가 아니다.

이건 픽셀오아시스에서 이미 한 번 겪은 실패다. 캔버스 저장이 실패해도 아무 안내 없이
조용히 넘어가서, 사용자는 저장된 줄 알고 앱을 껐다가 작업을 잃었다
(작업 #21 "저장 실패 무음 문제 해소", #37 "이미지 로드·처리 실패의 무음 종료 해소").
**픽셀오아시스에선 그림 한 장이었지만, 마크다운 앱에선 사용자가 직접 쓴 글이다.
같은 실패를 하면 ★1이 훨씬 세게 온다.**

### 4.2 외부 앱에서 .md 파일을 못 연다

Simple Markdown GitHub 이슈 트래커(`github.com/wbrawner/SimpleMarkdown/issues`)에서 확인:

- `#128` (열림, 2025-08-02) "Always get warning that the file is not a text file when using Dropbox app"
- `#58` (열림, **2019-11-10부터 6년 8개월째 열려 있음**) "Can't overwrite file" — `bug`, `help wanted` 라벨
- `#105` "Cannot open .md files in Dropbox"
- `#90` "Cannot open files from third-party apps"
- `#27` "Previewing Markdown from Other Applications"
- `#139` "Keyboard covers text during editing"

> "There is no method for saving into OneDrive... 파일을 PC로 메일로 보내야 한다"
> — John Knight, 2026-04-12, **Simple Markdown**

**설치 10만짜리 1위 앱이 "다른 앱에서 파일을 못 연다"는 이슈를 6년째 못 닫고 있다.**
Android의 SAF(Storage Access Framework)와 `ACTION_VIEW` 인텐트 처리를 제대로 한 앱이
사실상 없다는 뜻이다. 이게 §7-3의 근거다.

### 6.2 한국어 문서에서 깨지는 것 — 기술적 근거

**(a) 한 줄 개행(soft line break)이 무시된다 — 확인함**

CommonMark 명세 §6.8을 확인했다. 문단 안의 단일 개행은 **공백으로 렌더된다.**
`<br>`가 되려면 줄 끝에 공백 2개 이상 또는 백슬래시가 필요하다.

한국어 문서 작성 관행과 정면으로 충돌한다:
- AI(ChatGPT/Claude) 응답, Notion 내보내기, 카톡에서 복사한 텍스트는 한 줄 개행을 문단 구분으로 쓴다.
- 한국어 사용자는 엔터를 치면 줄이 바뀔 것이라 기대한다.
- 그런데 CommonMark 뷰어로 열면 **문단 전체가 한 덩어리로 뭉친다.**

GitHub 코멘트란은 `breaks: true`로 동작하지만 **`.md` 파일 렌더링은 그렇지 않다.**
사용자는 "GitHub에서 보던 거랑 다르네"라고 느끼고 원인을 모른다.

**조사한 어떤 앱도 이 옵션을 스토어 설명문에 언급하지 않았다.**
(설명문에 없다는 것이지, 구현에 없다는 것은 실기기로 검증하지 않았다.)

→ **결정: `breaks` 토글을 기본 켬으로 넣는다.** 근거는 §7-2.

**(b) 한국어 줄바꿈 위치 — 확인함(명세), 실기기 미검증**

CSS `word-break`의 기본값 `normal`은 CJK 문자를 **아무 데서나** 끊는다.
한국어는 어절 단위(공백 기준)로 끊어야 읽힌다. `word-break: keep-all`이 그 동작이다.

좁은 폰 화면에서 이 차이는 크다. `normal`이면 "마크다운 뷰"에서 줄이 바뀌어
"어를 만든다"가 다음 줄로 넘어간다. 읽는 속도가 눈에 띄게 떨어진다.

**Chromium/Android WebView가 `word-break: keep-all`을 지원하는 것은 명세상 사실이나,
이 조사에서 실기기로 확인하지는 않았다.** 개발 초기에 반드시 실기기 검증할 것.

**(c) 코드 블록 안의 한글 — 확인 못 함**

`font-family: monospace`를 그대로 두면 Android WebView는 Roboto Mono 계열로 잡는다.
이 폰트에는 한글 글리프가 없어서 폴백이 일어나고, 폴백 폰트는 고정폭이 아니다.
결과적으로 한글 주석이 섞인 코드 블록에서 정렬이 어긋날 수 있다.

**이건 추정이다. 실기기에서 확인하지 못했다.**
개발 초기에 "한글 주석이 든 코드 블록"을 실기기에서 캡처해서 확인할 것.
문제가 있으면 폰트 스택을 `'D2Coding', 'Nanum Gothic Coding', monospace`처럼 명시하거나
번들 폰트를 넣어야 한다(APK 용량 증가 — 이후 문서에서 결정).

**(d) 한글 검색 — 아무도 안 한다**

문서 내 검색을 지원하는 앱은 Pilcrow, Zettel Notes, Easy Markdown, iothub 정도다.
**초성 검색(ㅁㅋㄷㅇ → 마크다운)을 지원하는 앱은 조사 범위에 하나도 없다.**
한국 사용자에게 초성 검색은 "당연히 되는 것"으로 인식된다.

### 차별점 1 — "AI가 뱉은 마크다운을 손대지 않고 그대로 연다"

**측정 기준:** 아래 6개를 **설정 변경 없이 첫 화면에서 전부 렌더**한다.
Mermaid 다이어그램 / KaTeX 수식 / GFM 표(가로 스크롤 포함) / 각주 / 체크박스 /
언어별 코드 하이라이트.

**경쟁 앱이 못 하는 증거:**
- Mermaid를 설명문에 명시한 뷰어·에디터는 `cloud.iothub.markdown_viewer_editor`
  **하나뿐이고 설치 500+**다. Obsidian·Joplin은 PKM 앱이라 볼트를 만들어야 파일을 본다.
- **각주를 언급한 앱은 하나도 없다.**
- 설치 10만짜리 1위 Simple Markdown은 **표의 오른쪽을 못 본다**
  (한국 사용자 리뷰, 2026-05-21). CSS `overflow-x: auto` 한 줄이면 되는데 안 돼 있다.
- Pilcrow가 표 가로스크롤·KaTeX·목차·검색을 다 갖췄지만 **Mermaid가 없고 설치가 50개**다.

**왜 이게 다운로드로 이어지는가:**
Simple Markdown의 설치 이력이 답이다. 10,000 → 50,000에 5년 1개월이 걸렸는데,
50,000 → 100,000은 4개월 20일 만에 끝났다(2025-11-15 → 2026-04-06). 30일 평가 증가율
7.29%는 Obsidian(2.25%)의 3배, Joplin(1.05%)의 7배다. 이 시장에 **2025년 하반기부터
새 수요가 밀려들고 있고, 그 수요는 PKM 사용자가 아니다.** 정황상 원인은 AI다 —
사장님 본인이 그 이유로 이 앱을 만들려고 하는 것과 같은 동기다. 그리고 AI가 내놓는 문서는
일반 메모와 다르다. 표를 쓰고, 수식을 쓰고, 시퀀스 다이어그램을 그리고, 코드 블록을 섞는다.
그런데 이 시장의 앱들은 전부 "메모 앱" 시절 사양에 머물러 있어서, AI 출력물을 열면
표가 잘리거나 ```mermaid 블록이 회색 코드 덩어리로 나온다. 사용자는 "이 앱은 내 파일을
제대로 못 여는구나" 한 번 겪고 지운다. 반대로 열자마자 다이어그램이 그려지면 그 순간
설치를 유지한다. 이건 스크린샷 한 장으로 스토어에서 증명 가능한 차이이기도 하다 —
**"Mermaid 다이어그램이 그려진 화면"을 첫 번째 스크린샷으로 걸면 경쟁 앱 어느 것도
같은 그림을 못 건다.** 픽셀오아시스에서 배운 것이 이것이다(작업 #33 "Play 스토어 등재 개선"):
스토어에서 이기는 것은 기능 목록이 아니라 첫 스크린샷 한 장이다.

---

### 차별점 2 — "한국어 문서를 한국어답게 렌더한다"

**측정 기준:** 세 가지를 구현하고, 각각을 스토어 스크린샷으로 before/after 증명한다.
1. **개행 유지 토글** (`breaks: true`, **기본 켬**) — 한 줄 개행을 `<br>`로 렌더
2. **`word-break: keep-all`** — 한국어를 어절 단위로 줄바꿈
3. **초성 검색** — 문서 내 검색에서 `ㅁㅋㄷㅇ`로 `마크다운`을 찾는다

**경쟁 앱이 못 하는 증거:**
- 조사한 20개 앱 중 **개행 처리 옵션을 언급한 앱이 하나도 없다.**
- **초성 검색을 언급한 앱이 하나도 없다.**
- 한국 시장을 노린 마크다운 앱 중 설치 1천을 넘긴 것이 **하나도 없다**
  (`com.codeshift.bestmarkdown` 100+, `com.dangundad.simplemarkdown` 100+,
  `dev.markdownviewer.app` 500+). 즉 이 자리는 **비어 있고, 아무도 제대로 차지하지 않았다.**
- 한국 사용자가 남긴 불만 3건이 전부 렌더링 문제였다(§6.1).

**왜 이게 다운로드로 이어지는가:**
CommonMark 명세 §6.8상 문단 안의 단일 개행은 공백이 된다. 그런데 한국 사용자가 여는 문서의
상당수는 AI 응답이거나 Notion 내보내기이고, 이들은 한 줄 개행을 문단 구분으로 쓴다.
그래서 한국 사용자가 마크다운 뷰어를 처음 켜면 **자기가 쓴 글이 한 덩어리로 뭉쳐서 나온다.**
사용자는 이걸 "마크다운 명세대로 동작한 결과"로 이해하지 않는다. "이 앱 이상하다"로 이해한다.
이게 이탈의 첫 순간이고, 그 순간을 없애는 데 필요한 것은 옵션 하나다. 게다가 이건
**한국어 스토어 등재 문구로 직접 쓸 수 있다** — "엔터를 친 대로 줄이 바뀝니다"는 한 줄이
경쟁 앱 20개 중 어디에도 없는 문장이다. 픽셀오아시스는 국내 사용자를 잡을 특별한 이유가
없는 앱이었고(색칠 게임은 어느 나라 사람이든 같다), 그래서 등재 문구가 남들과 비슷해질
수밖에 없었다. 마크다운 뷰어는 다르다. **한국어라는 것 자체가 기능 차이를 만든다.**
초기 리뷰 30~50개를 한국 사용자에게서 빠르게 모을 수 있다는 뜻이고, 초기 별점이 곧
Play의 노출 순위다.

### 차별점 3 — "파일을 절대 잃지 않는다"

**측정 기준:** 아래 4개가 전부 성립한다.
1. 파일 탐색기·Dropbox·Google Drive·카톡에서 `.md`를 탭하면 **바로 열린다**
   (`ACTION_VIEW` + `text/markdown`, `text/plain`, `*/*` 인텐트 필터 + 확장자 매칭)
2. 편집 후 저장하면 **원본 경로에 덮어쓴다.** 새 파일을 만들지 않는다. 파일명 뒤에
   숫자를 붙이지 않는다.
3. 저장에 실패하면 **반드시 사용자에게 보인다.** 조용히 넘어가지 않는다.
   실패 시 본문을 로컬 임시 저장하고 다음 실행 때 복구를 제안한다.
4. 저장 안 된 변경이 있는 상태로 뒤로 가기/앱 종료 시 **확인을 묻는다.**

**경쟁 앱이 못 하는 증거:**
- Simple Markdown GitHub 이슈 `#58 "Can't overwrite file"`이 **2019-11-10에 열려
  2026-07-31 현재까지 열려 있다. 6년 8개월.** `bug`, `help wanted` 라벨이 붙어 있다.
  같은 트래커에 `#90 "Cannot open files from third-party apps"`,
  `#105 "Cannot open .md files in Dropbox"`, `#128` Dropbox 파일 타입 경고가 있다.
- "Half the time it errors out, the other half it saves to an unknown location rather than
  overwriting the original" (Simple Markdown, 2026-06-14)
- Markdown Editor(Adeeteya, 설치 5만)는 저장 시 **`.md` 뒤에 숫자를 붙여** 쓸 수 없는
  파일을 만든다(★2). 다른 사용자는 이 앱으로 **작업 1시간을 날렸다.**
- Open Note ★1: "Accidentally lost my content too many times... the app doesn't ask for
  confirmation to delete your work."
- Markdown Mono ★3: 저장 안 된 파일 경고가 없어 "I just lost a little work".
- Joplin ★4: share-to 기능이 **기존 노트를 무작위로 덮어써서 지운다.**
- 별점 분포가 U자다(§2.6). ★3이 거의 없고 ★5 아니면 ★1이다. 기능 부족이면 ★3이 쌓인다.
  ★1이 쌓인다는 건 **기본 동작이 실패한다는 뜻이다.**

**왜 이게 다운로드로 이어지는가:**
이 카테고리의 ★1은 대부분 "내 글이 없어졌다"다. Simple Markdown 15.1%, Joplin 23.7%,
Markdown Editor & MD Viewer 29.0%가 ★1~2다. 즉 **경쟁 앱을 쓰다 데인 사용자가 이미
시장에 수만 명 쌓여 있고, 그들은 지금도 대안을 찾고 있다.** 이 사람들에게 필요한 건
새 기능이 아니라 "이번엔 안 날아간다"는 확신이다. 그리고 이건 스토어 설명 첫 줄에 쓸 수
있는 약속이다 — "원본 파일에 그대로 덮어씁니다. 저장 실패는 반드시 알려드립니다."
픽셀오아시스에서 이 실패를 이미 겪었다. 저장이 실패해도 아무 안내 없이 넘어가서 사용자가
작업을 잃었고(작업 #21, #37), 그때는 그림 한 장이라 넘어갔다. 마크다운 앱에선 사용자가
**직접 쓴 글**이다. 같은 실패를 하면 그 사용자는 다시 오지 않고, ★1을 남기고, 그 ★1은
영구히 남는다. 반대로 이걸 지키면 **이 카테고리에서 유일하게 U자 분포를 벗어난 앱**이 되고,
별점 4.7 이상은 Play 검색 순위에서 직접적인 무기가 된다. 뷰어 중심 범위를 택한 것이
여기서 유리하게 작용한다 — 편집 기능이 가벼울수록 파일을 망가뜨릴 경로 자체가 적다.

## 8. 블루오션 가설에 대한 판정

사장님 가설: **"마크다운 앱들의 다운로드·활성도가 약해서 블루오션 같다."**

### 판정: 절반은 맞고, 절반은 틀렸다. 그리고 틀린 절반이 더 중요하다.

**맞는 부분 — "다운로드가 약하다"**

순수 뷰어 구역은 실제로 비어 있다. 뷰어만 하면서 설치 1만을 넘긴 앱은
`com.tjapp.markdownviewer` 하나이고 **별점이 2.6**이다.
별점이 정상인 뷰어(Markdown Mono 4.6, Pilcrow, 마크다운 뷰어)는 전부 설치 1천 이하다.
에디터 구역 1위 Simple Markdown도 10만이다 — 픽셀오아시스가 속한 캐주얼 게임 카테고리
기준으로는 작은 숫자다. **"뷰어 중심"이라는 범위 결정은 근거가 있다.**

**틀린 부분 1 — "활성도가 약하다"는 명백히 틀렸다**

조사한 20개 앱 중 **11개가 최근 30일 이내에 업데이트됐다.**
`com.cosmovex.mdvedit`(7/28), `cloud.iothub...`(7/28), `com.nithishgajula.easymarkdown`(7/27),
`md.obsidian`(7/27), `com.ZetaDev.PocketMark`(7/26), `com.yeestudio.nexusnote`(7/26),
`com.dangundad.simplemarkdown`(7/24), `com.pilcrowmd`(7/22), `com.tjapp.markdownviewer`(7/18),
`com.codeshift.bestmarkdown`(7/16), `dev.markdownviewer.app`(7/1).

죽은 시장이 아니다. **매주 누군가 업데이트를 밀고 있는 시장이다.**
사장님이 본 "활성도"는 설치 수를 본 것이지 개발 활동을 본 게 아니다.

**틀린 부분 2 — 블루오션이 아니라 "지금 막 열려서 사람이 몰려드는 좁은 문"이다**

이게 이 조사의 진짜 결론이다.

Simple Markdown이 10,000 → 50,000에 5년 1개월, 50,000 → 100,000에 **4개월 20일**이 걸렸다.
30일 평가 증가율 7.29%는 Obsidian의 3배, Joplin의 7배다.
**수요가 2025년 하반기부터 폭증했다.** 사장님이 "AI 쓰면서 마크다운 파일이 늘었다"고
느낀 그 시점과 정확히 겹친다.

그런데 그걸 느낀 사람이 사장님만이 아니다. Play 검색 결과에는 2026년에 만들어진 것으로
보이는 앱이 줄줄이 있다 — 설치 100+, 500+, 1000+짜리가 10개 넘게 깔려 있고,
그중에는 **`umd - Markdown & AI Monitor`(`com.wsLabs.umd`)**,
**`Kori - AI Notes & Markdown`(`org.yangdai.kori`, $3.49)** 처럼
이름에 대놓고 AI를 붙인 앱도 있다. **AI 마크다운이라는 각도를 이미 다른 사람들도 봤다.**

즉 상황은 이렇다:
- 수요는 커지고 있다 (맞다)
- 1위가 약하다 (맞다 — 10만, ★4.1, ★1~2가 15%)
- **경쟁자가 없다 (틀렸다 — 지금 몰려들고 있는 중이다)**

**그러므로 이건 블루오션이 아니라 타이밍 싸움이다.**
빈 바다가 아니라, 방금 열린 문 앞에 사람들이 줄 서기 시작한 상태다.
2026년에 들어온 신규 앱들이 아직 설치 1천을 못 넘겼다는 것은 아직 늦지 않았다는 뜻이지만,
6~12개월 안에 누군가 하나는 §7의 세 가지를 다 해낼 것이다.
**늦게 잘 만드는 것보다 지금 §7만 정확히 해서 내는 게 낫다.**

**틀린 부분 3 — "약해 보인다"를 "쉽다"로 읽으면 안 된다**

이 시장의 앱들이 약한 이유는 게을러서가 아니다.
Simple Markdown의 `#58 Can't overwrite file`이 6년 8개월째 안 닫혔다.
Obsidian은 2026년 6월에 Android WebView 회귀로 터치 입력이 죽었고,
개발사가 "안드로이드에서 새로 생긴 버그"라고 답할 수밖에 없었다.
**Android의 파일 접근(SAF)과 WebView가 어렵기 때문에 다들 여기서 무너진다.**

우리도 Capacitor를 재사용하기로 확정했으므로 **Obsidian이 맞은 것과 똑같은 WebView
위험을 그대로 안는다.** 픽셀오아시스에서 외부 요인(광고 SDK) 실패가 게임 전체를 영구히
잠근 사고(작업 #24)와 같은 부류다. 이후 문서에서 반드시 다뤄야 한다:
- WebView 버전별 회귀 대응 및 최소 WebView 버전 확인
- 렌더 실패 시 원문(raw) 폴백 화면 — **화면이 절대 비지 않게**
- SAF 영속 권한(`takePersistableUriPermission`) 처리와 권한 소실 시 복구

### 결론 한 줄

> **블루오션은 아니다. 하지만 "1위가 약한데 수요는 급성장 중이고 아직 아무도 §7의
> 세 가지를 다 못 한 시장"이다. 이건 블루오션보다 나은 조건일 수 있다 —
> 수요가 이미 검증됐다는 뜻이니까. 단, 창은 6~12개월이다.**

## 10. 개발 착수 전에 사람이 직접 해야 할 검증

이 조사는 스토어 설명문 기반이다. 아래는 **실기기 확인이 필요하고, 에이전트가 대신 못 한다.**

1. **Play 스토어에서 아래 3개를 설치하고 §5 기능 대조표를 직접 검증한다.**
   - Simple Markdown (`com.wbrawner.simplemarkdown`) — 1위. 표 가로 스크롤이 정말 안 되는지 확인
   - Markdown Viewer (`com.tjapp.markdownviewer`) — 유일한 설치 1만급 순수 뷰어. ★2.6인 이유 확인
   - Markdown Reader — Pilcrow (`com.pilcrowmd`) — 기능상 가장 가까운 경쟁자. 목차·검색 품질 확인
   각 앱에 **같은 테스트 파일**을 넣고 연다. 테스트 파일은 Mermaid 블록, 긴 표(10열),
   KaTeX 수식, 각주, 한글 주석이 든 코드 블록, 한 줄 개행 문단을 전부 포함해야 한다.
2. **한글 코드 블록 폰트 폴백 확인** (§6.2-c). 실기기에서 캡처해서 정렬이 깨지는지 본다.
3. **`word-break: keep-all`이 대상 WebView에서 실제로 동작하는지 확인** (§6.2-b).
