## 1. 사실 확인 기록 (추측이 아니라 실제로 확인한 것)

이 문서의 설계는 아래 확인에 근거한다. 나중에 "왜 이렇게 했나" 싶으면 여기를 봐라.

### 1-1. `@capacitor/filesystem`은 content:// 를 읽을 수는 있으나 쓸 수 없다

공식 문서는 이렇게만 말한다.

> "Additionally, the Filesystem API supports using full `file://` paths, or reading `content://` files on Android."

문장을 잘 봐라. **`reading`** 이라고 못 박혀 있다. 쓰기는 언급이 없다.

문서만으로는 부족해서 실제 구현을 뜯어봤다. `@capacitor/filesystem` 8.0.0의 안드로이드 구현은
`io.ionic.libs:ionfilesystem-android:1.0.0` AAR에 들어 있다. 그 AAR의 `IONFILEContentHelper`
(= content:// 전담 클래스)의 공개 메서드 전부는 다음과 같다.

```
readFile / readFileInChunks / getFileMetadata / deleteFile / copyFile
```

**`saveFile`도 `writeFile`도 없다.** 반면 `IONFILEController`에는 `saveFile`이 있고,
같은 라이브러리에 `IONFILEExceptions$NotSupportedForContentScheme` 예외 클래스가 존재한다.
그리고 Capacitor 플러그인의 `FilesystemErrors.kt`가 그 예외를 이렇게 JS로 변환한다.

```kotlin
is IONFILEExceptions.NotSupportedForContentScheme -> FilesystemErrors.notAllowed(
    methodName,
    notAllowedFor = "content:// URIs"
)
```

즉 `Filesystem.writeFile({ path: "content://..." })`를 호출하면 **에러 코드
`OS-PLUG-FILE-00xx`와 "content:// URIs"가 포함된 메시지로 거부된다.** 조용히 실패하는 게
아니라 명시적으로 거부되므로, 이 경로는 절대 쓸 수 없다.

> **결론**: 되쓰기(저장)는 100% 자체 플러그인으로 해야 한다. 대안 없음.

### 1-2. `@capawesome/capacitor-file-picker`는 영속 권한을 주지 못한다

먼저 플러그인 자체는 멀쩡하다. 확인한 것:

- 최신 버전 **8.0.3**, 배포일 **2026-06-22** (이 문서 작성 시점 기준 약 5주 전) — 살아 있다
- `peerDependencies`: `{"@capacitor/core": ">=8.0.0"}` — **Capacitor 8과 호환된다**
- 라이선스 **MIT**, 저장소 `github.com/capawesome-team/capacitor-plugins`
- 8.0.0(2025-12-17) → 8.0.1 → 8.0.2 → 8.0.3으로 꾸준히 릴리스 중

> 참고: 웹 문서 요약으로는 peerDependency가 `^4.0.0`이라고 잘못 나왔다. npm 레지스트리
> 원본 JSON을 직접 파싱해서 `>=8.0.0`임을 확인했다. **요약을 믿지 말고 원본을 봐라.**

문제는 구현이다. `FilePickerPlugin.java` 원본:

```java
// pickFiles() — 101번째 줄
Intent intent = new Intent(Intent.ACTION_GET_CONTENT);
intent.setType("*/*");
intent.addCategory(Intent.CATEGORY_OPENABLE);
intent.putExtra(Intent.EXTRA_ALLOW_MULTIPLE, limit == 0);
if (limit == 1 && parsedTypes != null && parsedTypes.length > 0) {
    intent.putExtra(Intent.EXTRA_MIME_TYPES, parsedTypes);
}
```

세 가지가 치명적이다.

1. **`ACTION_GET_CONTENT`는 영속 권한을 받을 수 없다.** 이 액션이 주는 URI 권한은
   호출한 태스크가 살아 있는 동안만 유효하다. `ACTION_OPEN_DOCUMENT`여야 영속화가 가능하다.
2. **`takePersistableUriPermission`이 이 파일 어디에도 없다.** `pickDirectory()`는
   `ACTION_OPEN_DOCUMENT_TREE`에 `FLAG_GRANT_PERSISTABLE_URI_PERMISSION`을 붙이지만
   (120~125번째 줄), **플래그만 붙이고 실제로 `takePersistableUriPermission()`을 호출하지
   않는다.** 플래그는 "영속화해도 된다"는 허가일 뿐이고, 실제 영속화는 `ContentResolver`에
   명시적으로 요청해야 한다. 안 하면 프로세스가 죽는 순간 권한이 사라진다.
3. **MIME 필터가 `limit == 1`일 때만 적용된다.** 여러 파일을 고르게 하면
   `setType("*/*")`만 남아서 사진·동영상·APK까지 전부 목록에 뜬다.

> **결론**: 최근 문서 목록을 만들려면 이 플러그인으로는 안 된다. 자체 플러그인 필수.
> 이 플러그인은 **의존성에 넣지 않는다.**

### 1-3. Capacitor 생태계에 SAF 플러그인은 존재하지 않는다

npm 레지스트리를 "capacitor storage access framework", "capacitor saf document uri"로
검색했다. Capacitor 관련으로 나온 것은 secure-storage, preferences, biometric,
file-opener 등이고 **SAF(Storage Access Framework)를 제대로 감싼 플러그인은 없다.**
`@capawesome/capacitor-android-document-file` 같은 이름도 npm에 **존재하지 않는다**(404).

### 1-4. Capacitor의 인텐트 처리는 절반만 된다

`@capacitor/app` 플러그인의 `AppPlugin.java`를 확인했다.

```java
@Override
protected void handleOnNewIntent(Intent intent) {
    super.handleOnNewIntent(intent);
    String action = intent.getAction();
    Uri url = intent.getData();

    if (!Intent.ACTION_VIEW.equals(action) || url == null) {
        return;                       // ← ACTION_SEND는 여기서 전부 버려진다
    }
    JSObject ret = new JSObject();
    ret.put("url", url.toString());
    notifyListeners(EVENT_URL_OPEN, ret, true);
}
```

되는 것:
- `BridgeActivity.onNewIntent()` → `Bridge.onNewIntent()` → 모든 플러그인의
  `handleOnNewIntent()` 호출. **연결은 정상적으로 되어 있다.**
- `Bridge.java` 229번째 줄 `this.intentUri = intent.getData();` — 생성자에서 실행되므로
  **콜드 스타트 시 `App.getLaunchUrl()`이 `content://` URI를 돌려준다.**

안 되는 것:
- **`ACTION_SEND`를 무시한다.** Gmail·카카오톡의 "공유"는 `ACTION_SEND` +
  `EXTRA_STREAM`으로 온다. `intent.getData()`가 null이라 위 코드에서 바로 return된다.
- **`ACTION_EDIT`를 무시한다.**
- `intentUri`는 Bridge 생성자에서 딱 한 번만 설정된다. `onNewIntent`에서 갱신되지 않으므로
  **두 번째 파일부터는 `getLaunchUrl()`이 첫 번째 파일을 계속 돌려준다.**

> **결론**: 인텐트 수신도 자체 플러그인에서 직접 처리한다. `@capacitor/app`의
> `appUrlOpen`에 의존하지 마라.

### 1-5. 확인하지 못한 것 (사람이 확인해야 함)

정직하게 적는다. 아래는 **확인에 실패했다.**

| 항목 | 상황 | 사람이 할 일 |
|---|---|---|
| AOSP의 MIME 테이블에 `.md` → `text/markdown` 매핑이 있는지 | `android.googlesource.com`, `aosp-mirror` GitHub 모두 404. GitHub 코드 검색은 401(인증 필요). **확인 실패.** | 실기기에서 3-6절의 진단 절차를 실행해 실제 MIME을 눈으로 확인 |
| 앱당 영속 URI 권한 개수 상한 | 128개로 알려져 있으나 **버전별 정확한 값을 확인하지 못했다** | 상한에 의존하지 않는 설계를 했다(최근 문서 50개 제한). 확인 불필요 |
| CodeMirror 6의 안드로이드 WebView 한글 IME 조합 상태(2026년 기준) | 확인하지 못했다 | 6-4절 결정(순수 `<textarea>` 사용)이 이 위험을 우회한다 |

## 2. "다른 앱에서 열기"로 .md 받기

### 2-1. 핵심 문제: .md의 MIME 타입은 하나가 아니다

같은 `note.md` 파일인데 보내는 앱마다 MIME이 다르다. 이게 이 앱 최대의 골칫거리다.

| 보내는 쪽 | 넘어오는 MIME | 이유 |
|---|---|---|
| 파일 관리자 (로컬 파일) | `text/markdown` 또는 `text/plain` | 확장자 → MIME 테이블 조회 결과에 의존 |
| 확장자를 모르는 기기 | `application/octet-stream` | MIME 테이블에 `md`가 없으면 이걸로 떨어진다 |
| Gmail 첨부 | `text/plain` 또는 `application/octet-stream` | 첨부 시점의 서버 헤더를 그대로 씀 |
| Google Drive | `text/markdown` / `text/plain` / 빈 값 | Drive가 자체 판단한 값 |
| 카카오톡 | `application/octet-stream`이 많음 | 파일 종류를 따지지 않고 바이너리로 취급 |
| 일부 구형 기기 | `text/x-markdown` | IANA 등록(RFC 7763, `text/markdown`) 이전의 관행적 타입 |

**대응 원칙: 하나도 놓치지 않도록 넓게 잡고, 대신 넓게 잡아서 생기는 부작용을 감수한다.**

특히 `text/plain`을 포함할지가 갈림길이다.

- 넣으면: `.txt` 파일을 열 때도 우리 앱이 후보로 뜬다 (부작용)
- 안 넣으면: **실제 .md 파일의 상당수가 우리 앱으로 열리지 않는다** (치명적)

> **결정: `text/plain`을 넣는다.**
> 이유 — 마크다운은 원래 플레인 텍스트다. `.txt`를 우리 앱으로 열어도 그냥 문단으로
> 잘 렌더링되므로 사용자에게 손해가 없다. 반대로 못 여는 것은 앱의 존재 이유를 없앤다.

### 2-2. AndroidManifest.xml — 그대로 복사해서 써라

`android/app/src/main/AndroidManifest.xml`

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:supportsRtl="true"
        android:theme="@style/AppTheme.NoActionBar">

        <activity
            android:name=".MainActivity"
            android:exported="true"
            android:label="@string/app_name"
            android:launchMode="singleTask"
            android:configChanges="orientation|keyboardHidden|keyboard|screenSize|locale|smallestScreenSize|screenLayout|uiMode"
            android:theme="@style/AppTheme.NoActionBarLaunch">

            <!-- (0) 런처 -->
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>

            <!-- (A) MIME이 제대로 오는 경우: content:// 와 file:// 양쪽 -->
            <!--     같은 intent-filter 안의 여러 <data>는 '짝'이 아니라 '조합'으로 매칭된다. -->
            <!--     아래는 {content, file} x {markdown, x-markdown, plain} = 6가지를 모두 잡는다. -->
            <intent-filter android:label="@string/open_with_label">
                <action android:name="android.intent.action.VIEW" />
                <action android:name="android.intent.action.EDIT" />
                <category android:name="android.intent.category.DEFAULT" />

                <data android:scheme="content" />
                <data android:scheme="file" />

                <data android:mimeType="text/markdown" />
                <data android:mimeType="text/x-markdown" />
                <data android:mimeType="text/plain" />
            </intent-filter>

            <!-- (B) MIME을 모르는 경우(octet-stream 등) - file:// 한정 -->
            <!--     pathPattern으로 확장자를 직접 검사한다. file:// 에서만 신뢰할 수 있다. -->
            <!--     안드로이드 pathPattern의 '.*'는 백트래킹을 하지 않기 때문에 -->
            <!--     경로 중간에 점이 있으면 매칭에 실패한다. 그래서 점 개수만큼 패턴을 늘어놓는다. -->
            <!--     (예: /sdcard/my.docs/note.md 는 '.*\\.md' 하나만으로는 매칭되지 않는다) -->
            <intent-filter android:label="@string/open_with_label">
                <action android:name="android.intent.action.VIEW" />
                <action android:name="android.intent.action.EDIT" />
                <category android:name="android.intent.category.DEFAULT" />

                <data android:scheme="file" />
                <data android:mimeType="*/*" />

                <data android:pathPattern=".*\\.md" />
                <data android:pathPattern=".*\\..*\\.md" />
                <data android:pathPattern=".*\\..*\\..*\\.md" />
                <data android:pathPattern=".*\\..*\\..*\\..*\\.md" />
                <data android:pathPattern=".*\\.markdown" />
                <data android:pathPattern=".*\\..*\\.markdown" />
                <data android:pathPattern=".*\\..*\\..*\\.markdown" />
                <data android:pathPattern=".*\\..*\\..*\\..*\\.markdown" />
                <data android:pathPattern=".*\\.mdown" />
                <data android:pathPattern=".*\\.mkd" />
            </intent-filter>

            <!-- (C) MIME이 아예 없는 인텐트 (type == null) -->
            <!--     mimeType을 지정한 필터는 type이 null인 인텐트와 매칭되지 않으므로 별도로 둔다. -->
            <intent-filter android:label="@string/open_with_label">
                <action android:name="android.intent.action.VIEW" />
                <category android:name="android.intent.category.DEFAULT" />

                <data android:scheme="file" />

                <data android:pathPattern=".*\\.md" />
                <data android:pathPattern=".*\\..*\\.md" />
                <data android:pathPattern=".*\\..*\\..*\\.md" />
                <data android:pathPattern=".*\\.markdown" />
                <data android:pathPattern=".*\\..*\\.markdown" />
            </intent-filter>

            <!-- (D) content:// + octet-stream : 최선의 노력. 기대치를 낮게 잡아라. -->
            <!--     pathPattern을 여기 쓰지 않는 이유는 3절에서 설명한다. -->
            <intent-filter android:label="@string/open_with_label">
                <action android:name="android.intent.action.VIEW" />
                <action android:name="android.intent.action.EDIT" />
                <category android:name="android.intent.category.DEFAULT" />

                <data android:scheme="content" />
                <data android:mimeType="application/octet-stream" />
            </intent-filter>

            <!-- (E) 공유(ACTION_SEND) — Gmail·카카오톡·Drive의 '공유' 버튼 -->
            <intent-filter android:label="@string/share_to_label">
                <action android:name="android.intent.action.SEND" />
                <category android:name="android.intent.category.DEFAULT" />

                <data android:mimeType="text/markdown" />
                <data android:mimeType="text/x-markdown" />
                <data android:mimeType="text/plain" />
                <data android:mimeType="application/octet-stream" />
            </intent-filter>

        </activity>
    </application>

    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="com.android.vending.BILLING" />

    <!-- 저장소 권한은 하나도 선언하지 않는다. 이유는 5절. -->

</manifest>
```

`android/app/src/main/res/values/strings.xml`에 라벨을 추가한다.

```xml
<string name="open_with_label">마크다운으로 열기</string>
<string name="share_to_label">마크다운 뷰어로 보내기</string>
```

### 2-3. 필터 (D)에 대한 솔직한 경고

필터 (D)는 `content://` + `application/octet-stream`을 전부 받는다.
즉 **카카오톡에서 zip·apk·mp3를 탭했을 때도 우리 앱이 후보 목록에 뜰 수 있다.**

이걸 감수하는 이유: 카카오톡으로 받은 .md는 거의 항상 `octet-stream`이고,
`content://` URI에서는 확장자로 거를 방법이 사실상 없다(3절). (D)를 빼면
"카톡으로 받은 md를 못 연다"가 되는데, 이건 한국 사용자에게 치명적이다.

**대신 앱 안에서 방어한다.** 파일을 열자마자 내용을 검사해서 텍스트가 아니면
바로 안내 화면을 띄운다 (5-4절 `looksLikeText()` 참고). 목록에 뜨는 건 막을 수 없지만,
열었을 때 깨진 화면을 보여주는 건 막을 수 있다.

### 2-4. `category.BROWSABLE`을 넣지 않는 이유

**결정: 파일 열기 필터에 `BROWSABLE`을 넣지 않는다.**

`BROWSABLE`은 "브라우저에서 링크를 눌렀을 때 이 액티비티가 뜰 수 있다"는 표시이고,
실질적으로 `http`/`https` 스킴에서만 의미가 있다. 우리는 로컬 파일을 여는 앱이라
브라우저 링크로 진입할 일이 없다. 넣으면 웹페이지가 우리 액티비티를 띄울 수 있는
경로만 생기고 얻는 게 없다.

### 2-5. `launchMode="singleTask"`를 쓰는 이유

**결정: `singleTask`.**

문서 뷰어는 `documentLaunchMode`로 파일마다 창을 띄우는 방식도 있지만,
편집 중인 문서가 여러 창에 흩어지면 "어느 창의 내용이 최신인가" 문제가 생긴다.
가벼운 편집이 목적이므로 인스턴스 하나만 유지하고 `onNewIntent`로 문서를 교체한다.

**단, 반드시 지켜야 할 것**: 편집 중 저장하지 않은 내용이 있는 상태에서 새 인텐트가
오면 문서를 바로 교체하지 말고 확인을 받아라. 안 그러면 사용자 입력이 소리 없이 사라진다.
구현은 4-3절에 있다.

## 3. pathPattern이 content:// 에서 통하지 않는 이유

이걸 모르고 설계하면 "왜 파일 관리자에선 되는데 Drive에선 안 되지?"로 며칠을 날린다.

`pathPattern`은 URI의 **path 부분**에만 적용된다.

`file://` URI의 path는 실제 파일 경로다.

```
file:///storage/emulated/0/Documents/note.md
                                     ^^^^^^^ path 끝이 .md → pathPattern 매칭 성공
```

그런데 `content://` URI의 path는 **프로바이더가 정한 불투명한 문서 ID**다.

```
content://com.android.externalstorage.documents/document/primary%3ADocuments%2Fnote.md
                                               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   path = /document/primary:Documents/note.md 를 URL 인코딩한 것.
   '/'가 %2F로 인코딩되어 있어서 패턴 매칭이 기대대로 동작하지 않는다.

content://com.google.android.apps.docs.storage/document/acc%3D1%3Bdoc%3Dencoded%3D...
   Google Drive. 문서 ID에 확장자가 아예 없다. .md로 끝나지 않는다.

content://media/external/file/1234
   MediaStore. 숫자 ID뿐. 확장자 정보 없음.

content://gmail-ls/lee%40gmail.com/messages/42/attachments/0.1/BEST/false
   Gmail 첨부. 확장자 없음.
```

**정리:**

| 스킴 | 매칭 근거 | pathPattern |
|---|---|---|
| `file://` | 확장자 (시스템이 확장자로 MIME 추론) | **동작한다** |
| `content://` | `ContentResolver.getType()`이 돌려주는 MIME | **동작하지 않는다고 봐라** |

그래서 매니페스트가 이렇게 나뉜 것이다.

- `file://` → pathPattern으로 확장자 검사 (필터 B, C)
- `content://` → MIME으로만 매칭 (필터 A, D)

**`content://`에 pathPattern을 붙이면, 운 좋게 `externalstorage.documents` 같은
일부 프로바이더에서 우연히 걸릴 뿐 Drive·Gmail에서는 전부 실패한다.**
"어떤 기기에선 되는데 어떤 기기에선 안 되는" 최악의 버그가 되므로 아예 쓰지 않는다.

### 3-6. 실기기 MIME 진단 절차 (사람이 직접)

1-5절에서 적었듯 AOSP의 MIME 테이블 확인에 실패했다. 실기기에서 직접 봐야 한다.
개발 초기에 **반드시** 한 번 돌려라. 여기서 나온 값이 매니페스트가 맞는지 알려준다.

**준비**: `note.md` 파일 하나를 만들어 기기의 `Download` 폴더에 넣고,
Gmail로 자신에게 첨부해서 보내고, 카카오톡으로 나에게 보내고, Drive에 업로드해 둔다.

**절차** (PC에서 USB 디버깅 연결 상태로):

1. 터미널에서 로그를 연다.
   ```bash
   adb logcat -c && adb logcat -s MdFile:V ActivityTaskManager:I
   ```
2. 앱을 설치한 상태에서, 기기의 파일 관리자로 `Download/note.md`를 탭한다.
3. "앱 선택" 창이 뜨는지 본다.
   - **우리 앱이 보이면**: 선택해서 연다. 로그에 `MdFile: opened uri=... mime=...`가
     찍힌다. 그 `mime=` 값을 적어 둔다.
   - **우리 앱이 안 보이면**: 매니페스트 필터가 그 MIME을 못 잡은 것이다.
     `ActivityTaskManager` 로그에 `START u0 {act=android.intent.action.VIEW
     typ=<타입> dat=<URI>}` 형태로 실제 인텐트가 찍힌다. 거기 `typ=`가 진짜 MIME이다.
     그 값을 필터 (A)의 `<data android:mimeType="...">`에 추가하라.
4. Gmail 첨부 → 카카오톡 → Google Drive 순으로 2~3을 반복한다.
5. 4곳의 MIME을 표로 정리해 두고, 필터 (A)/(D)가 전부 커버하는지 확인한다.

**이 절차를 건너뛰면 출시 후에 "안 열려요" 리뷰로 알게 된다.**
픽셀오아시스에서 실패가 조용히 지나가서 나중에 비싸게 알아낸 일이 여러 번 있었다
(작업 #21 "저장 실패 무음 문제", #37 "이미지 로드·처리 실패의 무음 종료").
같은 실수를 반복하지 마라.

### 4-2. MdFilePlugin.java (전체)

```java
package com.marklet.md.mdfile;

import android.app.Activity;
import android.content.ContentResolver;
import android.content.Intent;
import android.content.UriPermission;
import android.database.Cursor;
import android.net.Uri;
import android.os.Build;
import android.os.ParcelFileDescriptor;
import android.provider.DocumentsContract;
import android.provider.OpenableColumns;
import android.util.Log;

import androidx.activity.result.ActivityResult;

import com.getcapacitor.JSArray;
import com.getcapacitor.JSObject;
import com.getcapacitor.Plugin;
import com.getcapacitor.PluginCall;
import com.getcapacitor.PluginMethod;
import com.getcapacitor.annotation.ActivityCallback;
import com.getcapacitor.annotation.CapacitorPlugin;

import java.io.ByteArrayOutputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;

@CapacitorPlugin(name = "MdFile")
public class MdFilePlugin extends Plugin {

    private static final String TAG = "MdFile";

    /** 마크다운 문서로 허용할 최대 크기. 이 이상은 웹뷰 렌더링이 버티지 못한다. */
    private static final long MAX_BYTES = 8L * 1024 * 1024; // 8MB

    /** 콜드 스타트로 받은 URI. JS가 getPendingOpen()으로 한 번 가져가면 비운다. */
    private Uri pendingUri;
    /** ACTION_SEND로 파일이 아닌 '텍스트'가 공유된 경우. */
    private String pendingText;

    // ────────────────────────────────────────────────────────────
    // 인텐트 수신
    // ────────────────────────────────────────────────────────────

    @Override
    public void load() {
        super.load();
        // 콜드 스타트: 액티비티를 띄운 인텐트를 여기서 붙잡는다.
        // @capacitor/app 의 getLaunchUrl()은 ACTION_SEND를 못 받으므로 직접 처리한다.
        captureIntent(getActivity().getIntent(), false);
    }

    @Override
    protected void handleOnNewIntent(Intent intent) {
        super.handleOnNewIntent(intent);
        // 앱이 이미 떠 있는 상태에서 새 파일이 들어온 경우.
        captureIntent(intent, true);
    }

    /**
     * @param notify true면 JS로 이벤트를 쏜다(앱 실행 중). false면 보관만 한다(콜드 스타트).
     */
    private void captureIntent(Intent intent, boolean notify) {
        if (intent == null) return;

        String action = intent.getAction();
        Uri uri = null;
        String sharedText = null;

        if (Intent.ACTION_VIEW.equals(action) || Intent.ACTION_EDIT.equals(action)) {
            uri = intent.getData();
        } else if (Intent.ACTION_SEND.equals(action)) {
            uri = getStreamExtra(intent);
            if (uri == null) {
                // 파일이 아니라 순수 텍스트를 공유한 경우 (예: 메모 앱에서 텍스트 공유)
                CharSequence cs = intent.getCharSequenceExtra(Intent.EXTRA_TEXT);
                if (cs != null) sharedText = cs.toString();
            }
        }

        if (uri == null && sharedText == null) return;

        // 중요: 액티비티의 현재 인텐트를 갱신해 둔다.
        // 이렇게 해야 이후 회전/복원 시 getIntent()가 옛 인텐트를 돌려주지 않는다.
        if (notify) getActivity().setIntent(intent);

        Log.i(TAG, "captureIntent action=" + action + " uri=" + uri
                + " mime=" + (uri != null ? getContext().getContentResolver().getType(uri) : "-"));

        if (notify) {
            JSObject ev = (uri != null) ? describe(uri) : new JSObject();
            if (sharedText != null) ev.put("sharedText", sharedText);
            // 두 번째 인자 true = 리스너가 아직 없으면 붙을 때까지 보관(retain)
            notifyListeners("mdFileOpen", ev, true);
        } else {
            pendingUri = uri;
            pendingText = sharedText;
        }
    }

    @SuppressWarnings("deprecation")
    private static Uri getStreamExtra(Intent intent) {
        if (Build.VERSION.SDK_INT >= 33) {
            return intent.getParcelableExtra(Intent.EXTRA_STREAM, Uri.class);
        }
        return intent.getParcelableExtra(Intent.EXTRA_STREAM);
    }

    /** 콜드 스타트로 들어온 문서를 JS가 가져간다. 한 번 가져가면 비워진다. */
    @PluginMethod
    public void getPendingOpen(PluginCall call) {
        JSObject ret = new JSObject();
        if (pendingUri != null) {
            ret = describe(pendingUri);
            pendingUri = null;
        }
        if (pendingText != null) {
            ret.put("sharedText", pendingText);
            pendingText = null;
        }
        call.resolve(ret);
    }

    // ────────────────────────────────────────────────────────────
    // 읽기
    // ────────────────────────────────────────────────────────────

    @PluginMethod
    public void read(PluginCall call) {
        String uriStr = call.getString("uri");
        if (uriStr == null) { call.reject("uri가 필요합니다", "EINVAL"); return; }

        Uri uri = Uri.parse(uriStr);
        ContentResolver cr = getContext().getContentResolver();

        try (InputStream is = cr.openInputStream(uri)) {
            if (is == null) { call.reject("파일을 열 수 없습니다", "ENOENT"); return; }

            ByteArrayOutputStream bos = new ByteArrayOutputStream();
            byte[] buf = new byte[8192];
            int n;
            long total = 0;
            while ((n = is.read(buf)) != -1) {
                total += n;
                if (total > MAX_BYTES) { call.reject("파일이 너무 큽니다", "ETOOBIG"); return; }
                bos.write(buf, 0, n);
            }

            JSObject ret = describe(uri);
            ret.put("content", decodeUtf8(bos.toByteArray()));
            call.resolve(ret);

        } catch (SecurityException e) {
            // 영속 권한이 없거나 만료된 URI. JS가 '다시 열기'를 안내해야 한다.
            call.reject("이 파일에 접근할 권한이 없습니다", "EPERM", e);
        } catch (IOException | RuntimeException e) {
            call.reject(String.valueOf(e.getMessage()), "EIO", e);
        }
    }

    /** UTF-8로 디코드하고 BOM을 제거한다. 윈도우에서 만든 .md에 BOM이 흔하다. */
    private static String decodeUtf8(byte[] bytes) {
        int off = 0;
        if (bytes.length >= 3
                && (bytes[0] & 0xFF) == 0xEF
                && (bytes[1] & 0xFF) == 0xBB
                && (bytes[2] & 0xFF) == 0xBF) {
            off = 3;
        }
        return new String(bytes, off, bytes.length - off, StandardCharsets.UTF_8);
    }

    // ────────────────────────────────────────────────────────────
    // 쓰기  ← @capacitor/filesystem 이 못 하는 부분
    // ────────────────────────────────────────────────────────────

    @PluginMethod
    public void write(PluginCall call) {
        String uriStr = call.getString("uri");
        String content = call.getString("content");
        if (uriStr == null || content == null) {
            call.reject("uri와 content가 필요합니다", "EINVAL");
            return;
        }

        Uri uri = Uri.parse(uriStr);
        byte[] data = content.getBytes(StandardCharsets.UTF_8);
        ContentResolver cr = getContext().getContentResolver();

        ParcelFileDescriptor pfd = null;
        try {
            // "rwt" = read-write-truncate. 기존 내용을 확실히 지우고 쓴다.
            // 이걸 안 하고 "w"로 열면, 새 내용이 더 짧을 때 뒤에 옛 내용이 남는다.
            // (5000자 문서를 100자로 줄여 저장하면 뒤에 4900자가 그대로 남는 사고)
            try {
                pfd = cr.openFileDescriptor(uri, "rwt");
            } catch (Exception noTruncate) {
                // 일부 프로바이더(클라우드 계열)는 "rwt"를 지원하지 않는다.
                Log.w(TAG, "rwt 미지원, w로 재시도: " + noTruncate.getMessage());
                pfd = cr.openFileDescriptor(uri, "w");
            }

            if (pfd == null) { call.reject("쓰기용으로 열 수 없습니다", "EACCES"); return; }

            FileOutputStream fos = new FileOutputStream(pfd.getFileDescriptor());
            try {
                // "w"로 열렸을 경우를 대비해 명시적으로 잘라낸다.
                fos.getChannel().truncate(0);
            } catch (IOException truncErr) {
                Log.w(TAG, "truncate 미지원: " + truncErr.getMessage());
            }

            fos.write(data);
            fos.flush();

            try {
                // 디스크까지 확실히 내려보낸다. 여기서 실패해도 치명적이지 않다.
                pfd.getFileDescriptor().sync();
            } catch (Exception syncErr) {
                Log.w(TAG, "sync 미지원(클라우드 프로바이더일 수 있음): " + syncErr.getMessage());
            }
            // 주의: fos.close()를 부르지 않는다. fos를 닫으면 pfd의 FD가 함께 닫혀
            //       아래 pfd.close()가 예외를 던진다. FD 소유권은 pfd에 있다.

            JSObject ret = new JSObject();
            ret.put("bytesWritten", data.length);
            ret.put("uri", uri.toString());
            call.resolve(ret);

        } catch (SecurityException e) {
            call.reject("이 파일에 쓸 권한이 없습니다", "EPERM", e);
        } catch (UnsupportedOperationException e) {
            // Drive 등 일부 프로바이더가 쓰기 자체를 거부하는 경우
            call.reject("이 위치에는 저장할 수 없습니다", "EREADONLY", e);
        } catch (IOException | RuntimeException e) {
            call.reject(String.valueOf(e.getMessage()), "EIO", e);
        } finally {
            if (pfd != null) {
                try { pfd.close(); } catch (IOException ignored) { }
            }
        }
    }

    // ────────────────────────────────────────────────────────────
    // SAF 파일 선택 (ACTION_OPEN_DOCUMENT) + 영속 권한
    // ────────────────────────────────────────────────────────────

    @PluginMethod
    public void pickFile(PluginCall call) {
        Intent intent = new Intent(Intent.ACTION_OPEN_DOCUMENT);
        intent.addCategory(Intent.CATEGORY_OPENABLE);
        // setType은 넓게, EXTRA_MIME_TYPES로 좁힌다.
        // octet-stream을 넣어야 카카오톡/Drive에서 받은 md가 목록에 뜬다.
        intent.setType("*/*");
        intent.putExtra(Intent.EXTRA_MIME_TYPES, new String[]{
                "text/markdown",
                "text/x-markdown",
                "text/plain",
                "application/octet-stream"
        });
        // 이 세 플래그가 있어야 나중에 takePersistableUriPermission이 성공한다.
        intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION
                | Intent.FLAG_GRANT_WRITE_URI_PERMISSION
                | Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION);

        startActivityForResult(call, intent, "pickFileResult");
    }

    @ActivityCallback
    private void pickFileResult(PluginCall call, ActivityResult result) {
        if (call == null) return;

        Intent data = result.getData();
        if (result.getResultCode() != Activity.RESULT_OK || data == null || data.getData() == null) {
            JSObject ret = new JSObject();
            ret.put("cancelled", true);
            call.resolve(ret);
            return;
        }

        Uri uri = data.getData();
        boolean persisted = persist(uri, data.getFlags());

        JSObject ret = describe(uri);
        ret.put("cancelled", false);
        ret.put("persisted", persisted);
        call.resolve(ret);
    }

    @ActivityCallback
    private void pickFolderResult(PluginCall call, ActivityResult result) {
        if (call == null) return;

        Intent data = result.getData();
        if (result.getResultCode() != Activity.RESULT_OK || data == null || data.getData() == null) {

    /** 폴더 안의 마크다운 파일 목록. 하위 폴더는 depth 제한으로 재귀 탐색한다. */
    @PluginMethod
    public void listFolder(PluginCall call) {
        String uriStr = call.getString("uri");
        int maxDepth = call.getInt("maxDepth", 3);
        if (uriStr == null) { call.reject("uri가 필요합니다", "EINVAL"); return; }

        Uri tree = Uri.parse(uriStr);
        try {
            String rootDocId = DocumentsContract.getTreeDocumentId(tree);
            List<JSObject> out = new ArrayList<>();
            walk(tree, rootDocId, 0, maxDepth, out);

            JSArray arr = new JSArray();
            for (JSObject o : out) arr.put(o);

            JSObject ret = new JSObject();
            ret.put("files", arr);
            call.resolve(ret);
        } catch (SecurityException e) {
            call.reject("폴더 권한이 만료되었습니다", "EPERM", e);
        } catch (Exception e) {
            call.reject(String.valueOf(e.getMessage()), "EIO", e);
        }
    }

    private void walk(Uri tree, String docId, int depth, int maxDepth, List<JSObject> out) {
        if (depth > maxDepth || out.size() > 2000) return;

        Uri children = DocumentsContract.buildChildDocumentsUriUsingTree(tree, docId);
        String[] proj = {
                DocumentsContract.Document.COLUMN_DOCUMENT_ID,
                DocumentsContract.Document.COLUMN_DISPLAY_NAME,
                DocumentsContract.Document.COLUMN_MIME_TYPE,
                DocumentsContract.Document.COLUMN_SIZE,
                DocumentsContract.Document.COLUMN_LAST_MODIFIED
        };

        try (Cursor c = getContext().getContentResolver()
                .query(children, proj, null, null, null)) {
            if (c == null) return;
            while (c.moveToNext()) {
                String childId = c.getString(0);
                String name = c.getString(1);
                String mime = c.getString(2);

                if (DocumentsContract.Document.MIME_TYPE_DIR.equals(mime)) {
                    walk(tree, childId, depth + 1, maxDepth, out);
                    continue;
                }
                if (!isMarkdownName(name)) continue;

                JSObject o = new JSObject();
                o.put("uri", DocumentsContract
                        .buildDocumentUriUsingTree(tree, childId).toString());
                o.put("name", name);
                o.put("mimeType", mime);
                o.put("size", c.isNull(3) ? -1 : c.getLong(3));
                o.put("lastModified", c.isNull(4) ? 0 : c.getLong(4));
                out.add(o);
            }
        } catch (Exception e) {
            Log.w(TAG, "폴더 탐색 실패 docId=" + docId + " : " + e.getMessage());
        }
    }

    /** 폴더 목록에서는 MIME을 믿을 수 없으므로 파일 이름으로 거른다. */
    private static boolean isMarkdownName(String name) {
        if (name == null) return false;
        String n = name.toLowerCase();
        return n.endsWith(".md") || n.endsWith(".markdown")
                || n.endsWith(".mdown") || n.endsWith(".mkd") || n.endsWith(".txt");
    }

    // ────────────────────────────────────────────────────────────
    // 영속 권한 관리
    // ────────────────────────────────────────────────────────────

    /**
     * 권한을 영구 보관한다. 이게 없으면 앱을 껐다 켠 뒤 URI가 무효가 된다.
     * @capawesome/capacitor-file-picker 가 빠뜨린 바로 그 호출이다.
     */
    private boolean persist(Uri uri, int grantFlags) {
        int take = grantFlags
                & (Intent.FLAG_GRANT_READ_URI_PERMISSION | Intent.FLAG_GRANT_WRITE_URI_PERMISSION);
        if (take == 0) take = Intent.FLAG_GRANT_READ_URI_PERMISSION;
        try {
            getContext().getContentResolver().takePersistableUriPermission(uri, take);
            return true;
        } catch (SecurityException e) {
            // ACTION_SEND/ACTION_VIEW로 받은 URI는 대개 영속화가 불가능하다. 정상 상황이다.
            Log.w(TAG, "영속 권한 불가: " + uri + " (" + e.getMessage() + ")");
            return false;
        }
    }

    /** 현재 앱이 들고 있는 영속 권한 전체. 앱 시작 시 최근 목록과 대조한다. */
    @PluginMethod
    public void getPersistedUris(PluginCall call) {
        JSArray arr = new JSArray();
        for (UriPermission p : getContext().getContentResolver().getPersistedUriPermissions()) {
            JSObject o = new JSObject();
            o.put("uri", p.getUri().toString());
            o.put("read", p.isReadPermission());
            o.put("write", p.isWritePermission());
            o.put("persistedTime", p.getPersistedTime());
            arr.put(o);
        }
        JSObject ret = new JSObject();
        ret.put("uris", arr);
        call.resolve(ret);
    }

    /** 최근 목록에서 지울 때 권한도 같이 반납한다. 상한에 걸리지 않게 하는 위생 작업. */
    @PluginMethod
    public void releaseUri(PluginCall call) {
        String uriStr = call.getString("uri");
        if (uriStr == null) { call.reject("uri가 필요합니다", "EINVAL"); return; }
        try {
            getContext().getContentResolver().releasePersistableUriPermission(
                    Uri.parse(uriStr),
                    Intent.FLAG_GRANT_READ_URI_PERMISSION | Intent.FLAG_GRANT_WRITE_URI_PERMISSION);
        } catch (Exception e) {
            Log.w(TAG, "권한 반납 실패(이미 없을 수 있음): " + e.getMessage());
        }
        call.resolve();
    }

    // ────────────────────────────────────────────────────────────
    // 새 이름으로 저장 (ACTION_CREATE_DOCUMENT)
    // ────────────────────────────────────────────────────────────

    /** 원본이 읽기 전용일 때의 탈출구. 저장 실패 시 반드시 이 경로를 제공해야 한다. */
    @PluginMethod
    public void createFile(PluginCall call) {
        String suggestedName = call.getString("name", "untitled.md");
        Intent intent = new Intent(Intent.ACTION_CREATE_DOCUMENT);
        intent.addCategory(Intent.CATEGORY_OPENABLE);
        intent.setType("text/markdown");
        intent.putExtra(Intent.EXTRA_TITLE, suggestedName);
        intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION
                | Intent.FLAG_GRANT_WRITE_URI_PERMISSION
                | Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION);
        startActivityForResult(call, intent, "createFileResult");
    }

    @ActivityCallback
    private void createFileResult(PluginCall call, ActivityResult result) {
        if (call == null) return;
        Intent data = result.getData();
        if (result.getResultCode() != Activity.RESULT_OK || data == null || data.getData() == null) {
            JSObject ret = new JSObject();
            ret.put("cancelled", true);
            call.resolve(ret);
            return;
        }
        Uri uri = data.getData();
        boolean persisted = persist(uri, data.getFlags());
        JSObject ret = describe(uri);
        ret.put("cancelled", false);
        ret.put("persisted", persisted);
        call.resolve(ret);
    }

    // ────────────────────────────────────────────────────────────
    // 메타데이터
    // ────────────────────────────────────────────────────────────

    /** URI 하나에 대한 이름/크기/MIME/쓰기가능 여부를 모은다. */
    private JSObject describe(Uri uri) {
        ContentResolver cr = getContext().getContentResolver();
        JSObject o = new JSObject();
        o.put("uri", uri.toString());

        String name = null;
        long size = -1;

        if ("content".equals(uri.getScheme())) {
            try (Cursor c = cr.query(uri,
                    new String[]{OpenableColumns.DISPLAY_NAME, OpenableColumns.SIZE},
                    null, null, null)) {
                if (c != null && c.moveToFirst()) {
                    int ni = c.getColumnIndex(OpenableColumns.DISPLAY_NAME);
                    int si = c.getColumnIndex(OpenableColumns.SIZE);
                    if (ni >= 0 && !c.isNull(ni)) name = c.getString(ni);
                    if (si >= 0 && !c.isNull(si)) size = c.getLong(si);
                }
            } catch (Exception e) {
                Log.w(TAG, "메타데이터 조회 실패: " + e.getMessage());
            }
        }
        if (name == null) name = uri.getLastPathSegment();

        o.put("name", name == null ? "문서" : name);
        o.put("size", size);
        o.put("mimeType", safeType(cr, uri));
        o.put("writable", isWritable(uri));
        return o;
    }

    private static String safeType(ContentResolver cr, Uri uri) {
        try { return cr.getType(uri); } catch (Exception e) { return null; }
    }

    /**
     * 실제로 쓸 수 있는 문서인지 판단한다.
     * 쓰기 모드로 열어 보는 방식은 절대 쓰면 안 된다 — 그 자체로 파일이 잘려나간다.
     * 반드시 FLAG_SUPPORTS_WRITE 플래그로만 판단한다.
     */
    private boolean isWritable(Uri uri) {
        try {
            if (!DocumentsContract.isDocumentUri(getContext(), uri)) return false;
            try (Cursor c = getContext().getContentResolver().query(uri,
                    new String[]{DocumentsContract.Document.COLUMN_FLAGS}, null, null, null)) {
                if (c != null && c.moveToFirst() && !c.isNull(0)) {
                    int flags = c.getInt(0);
                    return (flags & DocumentsContract.Document.FLAG_SUPPORTS_WRITE) != 0;
                }
            }
        } catch (Exception e) {
            Log.w(TAG, "쓰기 가능 여부 확인 실패: " + e.getMessage());
        }
        return false;
    }

    private String treeDisplayName(Uri tree) {
        try {
            Uri doc = DocumentsContract.buildDocumentUriUsingTree(
                    tree, DocumentsContract.getTreeDocumentId(tree));
            try (Cursor c = getContext().getContentResolver().query(doc,
                    new String[]{DocumentsContract.Document.COLUMN_DISPLAY_NAME},
                    null, null, null)) {
                if (c != null && c.moveToFirst() && !c.isNull(0)) return c.getString(0);
            }
        } catch (Exception ignored) { }
        return "폴더";
    }
}
```

### 4-5. 앱 시작 시 문서 진입 흐름

콜드 스타트와 실행 중 진입은 **경로가 다르다.** 둘 다 처리해야 한다.

```ts
import { MdFile, type MdDocument } from './plugins/md-file';

export async function initDocumentEntry(openDocument: (doc: MdDocument) => void) {
  // (1) 실행 중 진입: 리스너를 '먼저' 붙인다.
  //     네이티브가 retain=true로 이벤트를 보관하므로 늦게 붙어도 놓치지 않지만,
  //     먼저 붙이는 편이 안전하다.
  await MdFile.addListener('mdFileOpen', async (doc) => {
    // 저장하지 않은 편집이 있으면 먼저 확인받는다.
    // 이걸 빠뜨리면 사용자가 쓰던 내용이 소리 없이 사라진다.
    if (hasUnsavedChanges() && !(await confirmDiscard())) return;
    openDocument(doc);
  });

  // (2) 콜드 스타트 진입
  const pending = await MdFile.getPendingOpen();
  if (pending?.uri) {
    openDocument(pending as MdDocument);
  } else if (pending?.sharedText) {
    openSharedText(pending.sharedText);
  } else {
    showHomeScreen();   // 그냥 아이콘으로 실행한 경우
  }
}
```

> `@capacitor/app`의 `appUrlOpen`은 **쓰지 않는다.** 1-4절에서 확인했듯
> `ACTION_SEND`를 버리고, `getLaunchUrl()`은 두 번째 파일부터 낡은 값을 돌려준다.

## 5. 저장 — 원본을 망가뜨리지 않는 순서

### 5-1. 왜 이렇게까지 조심해야 하나

사용자의 문서는 **우리가 만든 게 아니다.** 픽셀오아시스는 최악의 경우 게임 진행도가
날아가는 정도였지만(작업 #21 "저장 실패 무음 문제 해소"), 여기서 실수하면
**사용자가 몇 년간 써 온 원본 노트가 사라진다.** 되돌릴 방법이 없다.

`content://` URI에는 **원자적 rename이 없다.** 임시 파일에 쓰고 바꿔치기하는
일반적인 안전 기법을 쓸 수 없다. 프로바이더가 다른 앱 소유라 우리가 통제할 수 없기 때문이다.
**그래서 "쓰기 전 백업"만이 유일한 방어선이다.**

### 5-2. 저장 순서 (이 순서를 지켜라)

```
1. 쓰기 가능 여부 확인       writable === false 면 즉시 '새 이름으로 저장'으로 유도
2. 원본을 읽어서 앱 캐시에 백업   ← 실패하면 저장을 진행하지 않는다
3. 쓰기                      MdFile.write()
4. 다시 읽어서 검증            크기·내용 비교
5-a. 검증 성공                백업을 '직전 버전'으로 승격하고 종료
5-b. 어느 단계든 실패          백업을 근거로 복구를 제안 + '새 이름으로 저장' 제공
```

**2번에서 실패하면 3번으로 넘어가지 마라.** 백업 없이 쓰는 것은
안전벨트 없이 운전하는 것과 같다.

### 5-3. 구현

`src/services/save.ts`

```ts
import { Filesystem, Directory, Encoding } from '@capacitor/filesystem';
import { MdFile, type MdDocument } from '../plugins/md-file';

export type SaveResult =
  | { ok: true; bytesWritten: number }
  | { ok: false; reason: 'readonly' | 'backup-failed' | 'write-failed' | 'verify-failed';
      message: string; backupPath?: string };

/** URI를 파일 이름으로 쓸 수 있게 만든다. */
function backupName(uri: string): string {
  let h = 5381;
  for (let i = 0; i < uri.length; i++) h = ((h * 33) ^ uri.charCodeAt(i)) >>> 0;
  return `backup/${h.toString(36)}.md`;
}

export async function saveDocument(doc: MdDocument, content: string): Promise<SaveResult> {
  // ── 1. 쓰기 가능 여부
  if (!doc.writable) {
    return { ok: false, reason: 'readonly',
      message: '이 파일은 여기서 수정할 수 없습니다. 새 이름으로 저장해 주세요.' };
  }

  const path = backupName(doc.uri);

  // ── 2. 백업 (앱 전용 저장소이므로 @capacitor/filesystem 으로 충분하다)
  try {
    const original = await MdFile.read({ uri: doc.uri });
    await Filesystem.mkdir({ path: 'backup', directory: Directory.Data, recursive: true })
      .catch(() => { /* 이미 있으면 통과 */ });
    await Filesystem.writeFile({
      path, directory: Directory.Data,
      data: original.content ?? '', encoding: Encoding.UTF8,
    });
  } catch (e) {
    // 백업 실패 = 저장 중단. 여기서 멈추는 게 원본을 지키는 길이다.
    return { ok: false, reason: 'backup-failed',
      message: '원본을 백업하지 못해 저장을 중단했습니다. 파일이 그대로 남아 있습니다.' };
  }

  // ── 3. 쓰기
  let bytesWritten = 0;
  try {
    const res = await MdFile.write({ uri: doc.uri, content });
    bytesWritten = res.bytesWritten;
  } catch (e: any) {
    return { ok: false, reason: 'write-failed', backupPath: path,
      message: describeWriteError(e) };
  }

  // ── 4. 검증: 정말 그 내용이 들어갔는지 되읽어 본다.
  //     Drive처럼 비동기 동기화를 하는 프로바이더에서 쓰기가 조용히 무시되는 경우를 잡는다.
  try {
    const back = await MdFile.read({ uri: doc.uri });
    if ((back.content ?? '') !== content) {
      return { ok: false, reason: 'verify-failed', backupPath: path,
        message: '저장은 되었지만 내용이 일치하지 않습니다. 클라우드 동기화 중일 수 있습니다.' };
    }
  } catch {
    return { ok: false, reason: 'verify-failed', backupPath: path,
      message: '저장 후 확인에 실패했습니다. 파일을 다시 열어 내용을 확인해 주세요.' };
  }

  return { ok: true, bytesWritten };
}

function describeWriteError(e: any): string {
  switch (e?.code) {
    case 'EPERM':     return '파일에 쓸 권한이 없습니다. 파일을 다시 열어 주세요.';
    case 'EREADONLY': return '이 위치에는 저장할 수 없습니다. 새 이름으로 저장해 주세요.';
    case 'EIO':       return '저장 중 오류가 발생했습니다. 저장 공간을 확인해 주세요.';
    default:          return `저장에 실패했습니다. (${e?.message ?? '알 수 없는 오류'})`;
  }
}
```

**저장 실패는 절대 조용히 넘어가면 안 된다.** 픽셀오아시스에서 실제로 겪은 문제다
(작업 #21). 실패하면 화면에 확실히 띄우고, 반드시 `새 이름으로 저장`
(`MdFile.createFile()`) 버튼을 함께 보여줘라. 출구 없는 에러 화면은
작업 #24("광고 실패 시 게임 영구 잠김")와 같은 종류의 사고다.

### 5-4. 텍스트가 아닌 파일 방어

필터 (D) 때문에 zip이나 이미지가 들어올 수 있다. 열자마자 검사한다.

```ts
/** 널 바이트가 있거나 치환문자가 과하면 텍스트가 아니라고 본다. */
export function looksLikeText(content: string): boolean {
  if (content.length === 0) return true;
  const sample = content.slice(0, 4096);
  // 널 바이트는 바이너리라는 확실한 신호다.
  if (sample.indexOf(String.fromCharCode(0)) !== -1) return false;

  // UTF-8 디코딩에 실패한 바이트는 U+FFFD(치환 문자)가 된다. 5%를 넘으면 텍스트가 아니다.
  let bad = 0;
  for (const ch of sample) if (ch === '�') bad++;
  return bad / sample.length < 0.05;
}
```

`false`면 렌더링하지 말고 "이 파일은 텍스트 문서가 아닙니다"를 보여준다.

### 5-5. 클라우드(Google Drive·OneDrive) 저장의 위험

`content://` URI가 항상 로컬 파일을 가리키는 건 아니다. Drive의 URI에 쓰면
프로바이더가 네트워크로 업로드한다. 여기서 오는 위험:

| 위험 | 증상 | 대응 |
|---|---|---|
| 비동기 업로드 | `write()`는 성공했는데 서버 반영이 늦거나 실패 | 4단계 검증에서 잡는다. 실패 시 백업 안내 |
| `"rwt"` 미지원 | `openFileDescriptor(uri,"rwt")`가 예외 | 플러그인이 `"w"` + `truncate(0)`로 폴백 |
| `sync()` 미지원 | `SyncFailedException` | 경고 로그만 남기고 진행 (치명적 아님) |
| 오프라인 편집 충돌 | 다른 기기에서 수정한 내용을 덮어씀 | **우리가 막을 수 없다.** 아래 참고 |
| 문서가 이동/삭제됨 | `EPERM` 또는 `ENOENT` | 최근 목록에서 '찾을 수 없음' 표시 |

> **충돌 해결은 이 앱의 범위 밖이다.** 뷰어 중심 + 가벼운 편집이 확정된 범위이므로
> 3-way 병합 같은 건 만들지 않는다. 대신 **Drive 계열 URI에 저장할 때는
> "클라우드 문서입니다. 다른 기기에서 동시에 편집하지 마세요."를 한 번 안내한다.**
> URI의 authority에 `com.google.android.apps.docs`가 들어 있으면 클라우드로 간주한다.

### 6-1. 저장소는 `@capacitor/preferences`를 쓴다

**결정: `@capacitor/preferences` (8.0.1, MIT).**

이유 — 안드로이드에서 `SharedPreferences`에 저장되므로 웹뷰 데이터와 수명이 분리된다.
`localStorage`는 웹뷰 저장소라서 시스템이 저장공간을 회수하거나 사용자가
설정에서 "캐시 삭제"를 누를 때 함께 날아갈 수 있다. 최근 문서 목록이 사라지면
사용자는 파일을 다시 찾아야 하는데, 이건 이 앱에서 가장 아픈 실패다.
IndexedDB는 같은 웹뷰 저장소 위에 있으면서 코드만 복잡해지므로 쓰지 않는다.

### 6-2. 무엇을 저장하는가

**URI 문자열을 저장한다. 단, 그것만으로는 부족하다.**

```ts
export interface RecentDoc {
  uri: string;           // content:// 전체 문자열
  name: string;          // 표시 이름 (URI에서 다시 못 얻을 수 있으므로 따로 저장)
  lastOpened: number;    // epoch ms
  persisted: boolean;    // takePersistableUriPermission 성공 여부
  snapshotPath?: string; // persisted가 false일 때 저장해 둔 사본 경로
  size: number;
  source: 'picker' | 'intent' | 'folder';
}
```

### 6-3. URI는 재부팅 후에도 유효한가 — 조건부로 그렇다

이게 이 기능의 핵심이고, 대부분의 앱이 여기서 틀린다.

| 진입 경로 | 영속화 가능? | 재부팅 후 |
|---|---|---|
| `ACTION_OPEN_DOCUMENT` (우리 `pickFile`) | **가능** | **유효하다** |
| `ACTION_OPEN_DOCUMENT_TREE` (우리 `pickFolder`) | **가능** | **유효하다** |
| `ACTION_CREATE_DOCUMENT` (우리 `createFile`) | **가능** | **유효하다** |
| `ACTION_VIEW` (다른 앱에서 열기) | **대개 불가능** | **무효** |
| `ACTION_SEND` (공유) | **대개 불가능** | **무효** |
| `ACTION_GET_CONTENT` (기성 picker) | **불가능** | **무효** |

`takePersistableUriPermission()`을 호출해야만 영속화된다. 호출했다면 그 권한은
**재부팅 후에도 살아남는다.** 이게 SAF가 주는 보장이다.

**단, 영속 권한도 아래 상황에서는 무효가 된다.** 코드가 항상 이걸 감당해야 한다.

- 사용자가 원본 파일을 삭제하거나 이름을 바꿈 / 다른 폴더로 옮김
- 파일을 제공하던 앱이 삭제되거나 데이터가 초기화됨
- SD 카드가 빠짐
- 사용자가 시스템 설정에서 권한을 회수함

→ 이 경우 `read()`가 `EPERM` 또는 `ENOENT`로 거부된다. **반드시 처리해라.**

### 6-4. 영속화가 안 되는 URI는 사본을 남긴다

`ACTION_VIEW`/`ACTION_SEND`로 들어온 문서는 URI를 저장해 봐야 다음 실행에서 못 연다.
그렇다고 최근 목록에서 빼면 "카톡으로 받은 문서가 목록에 없다"가 된다.

**결정: 영속화에 실패하면 즉시 내용을 앱 내부 저장소에 사본으로 남기고,
최근 목록에는 `읽기 전용 사본` 배지를 달아 보여준다.**

사용자가 그 항목을 탭하면:
1. 먼저 원래 URI로 열어 본다 (같은 세션이면 성공한다)
2. 실패하면 사본을 읽어 보여주고, 상단에 "사본을 보고 있습니다. 원본을 수정하려면
   [파일 열기]로 다시 선택해 주세요"를 띄운다

### 6-5. 구현

`src/services/recents.ts`

```ts
import { Preferences } from '@capacitor/preferences';
import { Filesystem, Directory, Encoding } from '@capacitor/filesystem';
import { MdFile, type MdDocument } from '../plugins/md-file';

const KEY = 'recentDocs';
const MAX = 50;   // 영속 URI 권한에는 앱당 상한이 있다. 넉넉히 아래로 잡는다.

export interface RecentDoc {
  uri: string; name: string; lastOpened: number;
  persisted: boolean; snapshotPath?: string; size: number;
  source: 'picker' | 'intent' | 'folder';
}

export async function loadRecents(): Promise<RecentDoc[]> {
  const { value } = await Preferences.get({ key: KEY });
  if (!value) return [];
  try { return JSON.parse(value) as RecentDoc[]; } catch { return []; }
}

async function saveRecents(list: RecentDoc[]): Promise<void> {
  await Preferences.set({ key: KEY, value: JSON.stringify(list) });
}

export async function rememberDoc(
  doc: MdDocument, content: string, source: RecentDoc['source'],
): Promise<void> {
  const list = (await loadRecents()).filter((r) => r.uri !== doc.uri);

  let snapshotPath: string | undefined;
  if (!doc.persisted) {
    // 다시 못 열 URI다. 지금 사본을 만들어 둔다.
    snapshotPath = `snapshot/${Date.now()}-${doc.name}`;
    try {
      await Filesystem.mkdir({ path: 'snapshot', directory: Directory.Data, recursive: true })
        .catch(() => {});
      await Filesystem.writeFile({
        path: snapshotPath, directory: Directory.Data,
        data: content, encoding: Encoding.UTF8,
      });
    } catch { snapshotPath = undefined; }
  }

  list.unshift({
    uri: doc.uri, name: doc.name, lastOpened: Date.now(),
    persisted: !!doc.persisted, snapshotPath, size: doc.size, source,
  });

  // 넘치는 항목은 권한까지 반납해서 상한에 걸리지 않게 한다.
  for (const dropped of list.slice(MAX)) {
    if (dropped.persisted) await MdFile.releaseUri({ uri: dropped.uri }).catch(() => {});
    if (dropped.snapshotPath) {
      await Filesystem.deleteFile({ path: dropped.snapshotPath, directory: Directory.Data })
        .catch(() => {});
    }
  }

  await saveRecents(list.slice(0, MAX));
}

/**
 * 앱 시작 시 1회 실행. 저장된 목록과 실제 권한을 대조한다.
 * 사용자가 파일을 지웠거나 권한이 회수된 항목을 표시하기 위한 것.
 */
export async function reconcileRecents(): Promise<RecentDoc[]> {
  const list = await loadRecents();
  const { uris } = await MdFile.getPersistedUris();
  const live = new Set(uris.map((u) => u.uri));

  const merged = list.map((r) => ({ ...r, persisted: live.has(r.uri) }));
  await saveRecents(merged);
  return merged;
}

/** 최근 항목 열기: 원본 → 사본 순으로 시도한다. */
export async function openRecent(
  r: RecentDoc,
): Promise<{ doc: MdDocument; content: string; fromSnapshot: boolean } | null> {
  try {
    const doc = await MdFile.read({ uri: r.uri });
    return { doc, content: doc.content ?? '', fromSnapshot: false };
  } catch {
    if (!r.snapshotPath) return null;
    try {
      const f = await Filesystem.readFile({
        path: r.snapshotPath, directory: Directory.Data, encoding: Encoding.UTF8,
      });
      const doc: MdDocument = {
        uri: r.uri, name: r.name, size: r.size,
        mimeType: 'text/markdown', writable: false, persisted: false,
      };
      return { doc, content: f.data as string, fromSnapshot: true };
    } catch { return null; }
  }
}
```

### 6-6. 폴더는 별도로 관리한다

폴더(tree URI)는 영속 권한이 확실히 잡히므로 최근 문서와 분리해서
"내 폴더" 목록으로 둔다. 앱을 열 때마다 `listFolder()`로 갱신하면
사용자가 PC에서 새로 만든 .md도 자동으로 나타난다. **이게 이 앱의 킬러 기능이다** —
경쟁 앱들이 대부분 파일 하나씩만 여는 방식이라 여기서 차별화된다.

## 7. 안드로이드 저장소 정책 (targetSdk 36)

### 7-1. 결론: 저장소 권한을 하나도 선언하지 않는다

매니페스트에 아래 어느 것도 넣지 마라.

```xml
<!-- 전부 불필요하다. 넣지 마라. -->
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" />
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" />
<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE" />
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
```

**SAF(`ACTION_OPEN_DOCUMENT`, `ACTION_OPEN_DOCUMENT_TREE`)와 인텐트로 전달받은
`content://` URI는 권한이 전혀 필요 없다.** 사용자가 파일 선택 화면에서 직접
고르는 행위 자체가 권한 부여이기 때문이다.

### 7-2. 각 권한이 지금 어떤 상태인가

| 권한 | targetSdk 36에서의 상태 |
|---|---|
| `READ_EXTERNAL_STORAGE` | Android 13(API 33)부터 **효력이 없다.** 미디어(이미지/영상/오디오)는 `READ_MEDIA_*`로 분리됐고, **.md 같은 일반 문서에는 원래부터 이 권한으로 접근할 수 없었다.** 선언해도 얻는 게 없다 |
| `WRITE_EXTERNAL_STORAGE` | Android 11(API 30)부터 무시된다 |
| `READ_MEDIA_IMAGES/VIDEO/AUDIO` | 미디어 전용. 마크다운은 미디어가 아니므로 무관 |
| `MANAGE_EXTERNAL_STORAGE` | 아래 7-3 |

### 7-3. MANAGE_EXTERNAL_STORAGE는 요청하지 않는다

Google 공식 문서에서 확인한 내용이다.

> "Request the `MANAGE_EXTERNAL_STORAGE` permission **only when your app can't
> effectively make use of the more privacy-friendly APIs**, such as the Storage
> Access Framework or the Media Store API."

허용되는 앱 범주도 명시되어 있다.

> "File managers / Backup and restore apps / Anti-virus apps / Document management
> apps / On-device file search / Disk and file encryption / Device-to-device data migration"

그리고 결정적 조건:

> "Your app's usage of the permission must fall within permitted uses and
> **must be directly tied to the core functionality of the app**."

마크다운 뷰어를 "document management app"이라고 주장할 여지는 있다. 하지만:

1. **SAF로 전부 가능하다.** 위 인용의 첫 문장이 그대로 우리 상황이다 —
   더 사생활 친화적인 API로 충분한데 요청하면 반려 사유가 된다.
2. 권한 선언 양식(Permissions Declaration Form) 작성 + **사용 장면 시연 영상 제출**이
   필요하고, 심사가 길어지며 앱 업데이트마다 발목을 잡는다.
3. 픽셀오아시스에서 가장 오래 걸린 게 광고·데이터 안전 관련 심사 대응이었다.
   두 번째 앱에서 같은 늪에 다시 들어갈 이유가 없다.

> **결정: 요청하지 않는다. 논의 끝.**

### 7-4. 덤: 데이터 안전(Data Safety) 신고가 거의 비어 있게 된다

광고가 없고(확정 사항), 저장소 권한도 없고, 파일 내용을 서버로 보내지 않으므로
Play Console의 데이터 안전 양식에서 수집·공유할 항목이 사실상 없다.

**단, 팁 인앱결제 때문에 "구매 내역"은 신고해야 한다.**
Google Play 결제 시스템이 처리하는 부분이라 앱이 직접 수집하지 않더라도,
결제 기능이 있으면 해당 항목을 확인해야 한다. 정확한 분류는 Play Console
양식에서 직접 확인하라 — **이 부분은 확인하지 못했다.**

또한 파일 내용을 앱 밖으로 내보내지 않는다는 사실을 **스토어 설명과 개인정보처리방침에
명시적으로 써라.** "문서는 기기를 벗어나지 않습니다"는 이 카테고리에서 강력한 셀링포인트다.

## 8. 위험 판정

### 8-1. 위험 순위

**1위 — 저장(되쓰기). 위험도: 높음**

`@capacitor/filesystem`이 `content://` 쓰기를 지원하지 않는다는 것을 바이트코드로
확인했다(1-1절). 자체 플러그인 없이는 **불가능**하다.
플러그인을 만든 뒤에도 남는 위험: 프로바이더별 `"rwt"` 지원 편차, Drive의 비동기 업로드,
truncate 미지원으로 인한 파일 뒤쪽 잔여 데이터.

→ 4-2절 플러그인 + 5-2절 저장 순서(백업 → 쓰기 → 검증)로 완화된다.
**남는 위험: 중간.** 프로바이더별 실기기 테스트가 반드시 필요하다.

**2위 — .md의 MIME 혼돈. 위험도: 높음, 그리고 완전 해결 불가**

우리가 통제할 수 없는 영역이다. 보내는 앱이 무슨 MIME을 붙일지는 그쪽 마음이다.
`text/plain`과 `application/octet-stream`을 넓게 받는 것으로 대부분 커버되지만,
**"어떤 앱에서는 우리 앱이 목록에 안 뜬다"는 상황은 완전히 없앨 수 없다.**
이건 Capacitor의 문제가 아니라 안드로이드 전체의 문제이고, 네이티브로 만들어도 똑같다.

→ 3-6절 실기기 진단을 **개발 첫 주에** 반드시 실행해라. 나중에 하면 비싸다.
**남는 위험: 중간.** 대신 앱 안의 파일 선택기(SAF)를 항상 제공해서 우회로를 준다.

**3위 — 최근 문서 목록. 위험도: 중간 → 낮음**

기성 플러그인으로는 불가능(1-2절)하지만, 원인과 해법이 명확하다.
`ACTION_OPEN_DOCUMENT` + `takePersistableUriPermission`이면 끝난다.
→ **남는 위험: 낮음.**

**4위 — 인텐트 수신. 위험도: 낮음**

`@capacitor/app`이 `ACTION_SEND`를 버리지만, 우리 플러그인의
`load()` / `handleOnNewIntent()`로 완전히 대체된다.
Capacitor의 Bridge → 플러그인 전달 경로 자체는 정상 동작함을 소스로 확인했다.
→ **남는 위험: 낮음.**

**5위 — 큰 문서의 웹뷰 렌더링. 위험도: 중간**

Capacitor의 진짜 약점은 파일 접근이 아니라 **여기**다.
수 MB짜리 마크다운을 HTML로 렌더링하면 저사양 기기에서 눈에 띄게 느리다.
→ 완화: 플러그인에서 8MB 상한(`MAX_BYTES`)을 걸었다. 추가로 긴 문서는
가상 스크롤 또는 청크 렌더링이 필요하다. **이건 별도 문서에서 다뤄야 한다.**

**6위 — 편집 중 한글 IME. 위험도: 중간, 그러나 회피 가능**

안드로이드 웹뷰의 `contenteditable` 기반 커스텀 에디터(CodeMirror, Monaco 등)는
한글 조합 중 커서가 튀거나 글자가 중복되는 문제가 오래 알려져 있다.
**2026년 현재 CodeMirror 6의 상태는 확인하지 못했다.**

> **결정: 편집은 순수 `<textarea>`로 구현한다.**
> 이유 — `<textarea>`는 브라우저 네이티브 입력 경로를 그대로 타므로 한글 조합이
> 안정적이다. 범위가 "가벼운 편집"으로 확정되어 있어 문법 하이라이팅 같은
> 고급 기능이 필요 없다. 위험을 감수할 이유가 없다.

### 8-2. 스택을 바꿔야 하는가 — 아니다

**결론: Capacitor를 유지한다.**

지금 바꾸지 않는 이유:

1. **네이티브 구멍의 크기가 작고 명확하다.** 필요한 것은 Java 파일 1개(약 300줄)뿐이고,
   그 코드는 이 문서 4-2절에 이미 다 적혀 있다. 미지의 영역이 아니다.
2. **웹뷰가 이기는 부분이 훨씬 크다.** 마크다운 렌더링(markdown-it + 확장),
   수식(KaTeX), 다이어그램(Mermaid), 코드 하이라이팅, 표 — JS 생태계가 압도적이다.
   네이티브로 가면 이걸 전부 다시 구하거나 만들어야 한다.
   실제로 안드로이드 네이티브 마크다운 렌더러는 선택지가 빈약하다.
3. **픽셀오아시스의 절차를 그대로 재사용할 수 있다** — 서명, AAB 빌드, Play 배포,
   인앱결제. 두 번째 앱을 만드는 동기 자체가 그것이었다.

**바꿔야 했을 조건 (해당하지 않음)**: `content://` 를 웹뷰에서 아예 읽을 수 없었다면
심각했을 것이다. 하지만 읽기는 `@capacitor/filesystem`으로도 되고,
우리 플러그인으로는 더 확실하게 된다.

```jsonc
}
```

**`@capawesome/capacitor-file-picker`는 넣지 않는다.** 이유는 1-2절.

## 9. 사람이 직접 확인해야 할 항목

에이전트가 확인할 수 없어서 넘기는 것들이다. **체크하고 넘어가라.**

- [ ] **3-6절 실기기 MIME 진단**을 파일관리자 / Gmail / 카카오톡 / Google Drive
      4곳에서 실행하고, 실제 MIME 값을 표로 기록한다. 필터에 빠진 게 있으면 추가한다.
- [ ] `.md` 저장 테스트를 4곳에서 각각 수행한다. 특히 **긴 문서를 짧게 줄여서 저장**한 뒤
      파일 끝에 옛 내용이 남지 않는지 확인한다 (truncate 검증).
- [ ] **재부팅 테스트**: SAF로 파일을 열고 → 기기를 재부팅 → 최근 목록에서 그 파일이
      정상적으로 열리는지 확인한다. 안 되면 `takePersistableUriPermission`이
      실패하고 있는 것이다 (logcat의 "영속 권한 불가" 경고 확인).
- [ ] Google Drive 문서를 **오프라인 상태에서 저장**했을 때의 동작을 확인한다.
- [ ] Play Console 데이터 안전 양식에서 **팁 인앱결제로 인한 "구매 내역" 신고 여부**를
      확인한다 (7-4절, 확인하지 못함).
- [ ] 편집 UI를 `<textarea>`로 만든 뒤 **한글 조합 입력**을 실기기에서 확인한다
      (삼성 키보드 / Gboard 양쪽).
