## 2. 파서를 markdown-it 14.3.0으로 정한 이유

### 2.1 marked를 떨어뜨린 결정적 이유 — 원시 HTML을 끌 수 없다

marked 18.0.7을 실제로 돌려본 결과다.

```
=== marked 18.0.7 기본 설정 ===
"<script>alert(1)</script>"      -> "<script>alert(1)</script>"        // 그대로 통과
"<img src=x onerror=alert(1)>"   -> "<img src=x onerror=alert(1)>"     // 그대로 통과
"[a](javascript:alert(1))"       -> "<p><a href=\"javascript:alert(1)\">a</a></p>"  // 링크로 생성됨
"<iframe src=//evil></iframe>"   -> "<iframe src=//evil></iframe>"     // 그대로 통과

marked가 제공하는 옵션 전체:
async, breaks, extensions, gfm, hooks, pedantic, renderer, silent, tokenizer, walkTokens
```

**`html` 관련 옵션이 목록에 없다.** marked는 v8에서 `sanitize` 옵션을 제거했고, 이후로는
"DOMPurify를 쓰라"는 입장이다. 즉 marked를 쓰면 **DOMPurify가 유일한 방어선**이 된다.
DOMPurify에 우회 기법이 하나 나오면 그날로 뚫린다.

markdown-it은 `html: false` 하나로 원시 HTML을 전부 텍스트로 이스케이프한다.
같은 벡터 24개를 markdown-it `html:false` **단독**으로 돌렸을 때 **24개 전부 차단**됐다(5.2절 표).
DOMPurify는 그 위에 얹는 2차 방어선이 된다. 이 앱은 **남이 만든 .md를 여는 게 주기능**이므로
방어선이 하나뿐인 구조는 받을 수 없다.

### 2.2 속도 — marked가 조금 빠르지만 차이가 결정적이지 않다

Node v22, 최소 3회 중 최소값:

| 문서 | markdown-it 14.3.0 | markdown-it 15.0.0 | marked 18.0.7 |
|---|---|---|---|
| 50KB | 10ms | 13ms | 8ms |
| 500KB | 53ms | 92ms | 50ms |
| 1MB | 96ms | 144ms | 92ms |
| 5MB | 492ms | 737ms | 470ms |

marked가 5MB에서 22ms(4%) 빠르다. 안전성을 포기할 만한 차이가 아니다.

### 2.3 번들 크기 — marked가 작지만 감당 가능한 차이다

esbuild minify + gzip 실측:

| 구성 | min | **gzip** | brotli |
|---|---|---|---|
| markdown-it 14.3.0 코어 | 145KB | **52.0KB** | 43KB |
| markdown-it 15.0.0 코어 | 111KB | **46.8KB** | 41KB |
| marked 18.0.7 코어 | 41KB | **12.4KB** | 11KB |

marked가 40KB 작다. 하지만 각주·체크박스·수식 플러그인을 marked용으로 따로 붙이면 그 격차가 줄고,
무엇보다 2.1절의 안전성 문제를 못 덮는다.

### 2.4 왜 최신 15.0.0이 아니라 14.3.0인가

markdown-it 15.0.0은 **2026-07-30 배포 = 이 문서 작성 하루 전**이다. 두 가지 이유로 뺀다.

**첫째, 측정상 느리다.** linkify를 끄고 비교해도 15.0.0이 일관되게 느렸다(1MB 문서):

| 설정 | 15.0.0 | 14.3.0 |
|---|---|---|
| linkify=true, breaks=true | 156ms | **88ms** |
| linkify=false, breaks=true | 107ms | **63ms** |
| linkify=false, breaks=false | 108ms | **57ms** |

15.0.0이 약 70% 느리다. 갓 나온 릴리스의 회귀인지 구조 변경 때문인지는 **확인 못 했다.**

**둘째, 파괴적 변경이 있다.** 공식 CHANGELOG 기준:
- `linkify-it` v6로 올라가면서 fuzzy link 제거, 유니코드 문장부호가 링크를 끊음 → **한국어 문서에서 자동 링크 동작이 달라질 수 있다**
- `markdown-it/lib/*` 서브패스 export 제거 → 이를 참조하는 플러그인이 깨진다
- 링크 검증 메서드가 속성에서 프로토타입 메서드로 이동
- TypeScript로 마이그레이션, 타입 내장(= `@types/markdown-it` 불필요)

**확인한 것**: 15.0.0에서도 anchor / footnote / task-lists / katex 플러그인은 전부 정상 동작했고,
`md.validateLink = fn` 덮어쓰기도 15.0.0에서 그대로 동작했다. 즉 15로 못 갈 이유는 "느리다 + 하루밖에 안 됐다"뿐이다.

**재검토 시점**: 2026년 10월 이후 15.1.x가 나오고 속도 회귀가 잡히면 다시 본다. 그 전엔 14.3.0을 고정한다.

## 3. XSS 방어 — 확정 설정

### 3.1 왜 이게 이 앱에서 특히 중요한가

Capacitor 웹뷰 안에서 스크립트가 실행되면 `window.Capacitor.Plugins`에 접근할 수 있다.
즉 **파일 읽기·쓰기·공유가 전부 노출된다.** 브라우저에서의 XSS보다 피해가 크다.
사용자가 카카오톡으로 받은 남의 `.md`를 여는 게 이 앱의 정상 사용 시나리오이므로, 신뢰할 수 없는 입력이 기본값이다.

### 3.2 실측: 무엇이 뚫리고 무엇이 막히는가

벡터 24개를 렌더 후 **DOM으로 파싱해서** 위험 태그·`on*` 속성·위험 URL이 살아있는지 검사했다
(문자열 정규식이 아니라 실제 DOM 검사 — 이스케이프된 텍스트를 오탐하지 않기 위해).

| 구성 | 결과 |
|---|---|
| `html:true`, DOMPurify 없음 | **뚫림** — `<script>`, `<img onerror>`, `<iframe>`, `<a href=javascript:>`, `<details ontoggle>` 전부 살아남음 |
| `html:true` + DOMPurify | 8/8 차단 |
| **`html:false`, DOMPurify 없음** | **24/24 차단** |
| **`html:false` + validateLink 교체 + DOMPurify** ← **채택** | **24/24 차단** |

검사한 벡터: 원시 `<script>` / `<img onerror>` / `<svg onload>` / `<details ontoggle>` /
마크다운 링크의 `javascript:`(대소문자 변형·앞 공백 변형 포함) / 이미지 `javascript:` /
이미지 속성 탈출 `![i](x" onerror="alert(1))` / `<iframe>` / `formaction` / MathML 안 `<script>` /
`<object data=base64>` / `data:text/html` / `file://` / KaTeX `\href{javascript:}` / KaTeX `\htmlData` /
`capacitor://` 스킴 / 코드펜스 안의 `<script>`.

### 3.3 반드시 알아야 할 발견 — markdown-it 기본값은 `capacitor://`를 통과시킨다

`validateLink`를 덮어쓰지 **않은** 순정 markdown-it 14.3.0 출력이다.

```
입력: [a](javascript:alert(1)) [b](vbscript:x) [c](data:text/html,x) [d](file:///etc/passwd) [e](capacitor://localhost/x)

출력: <p>[a](javascript:alert(1)) [b](vbscript:x) [c](data:text/html,x) [d](file:///etc/passwd)
      <a href="capacitor://localhost/x">e</a></p>
```

`javascript:` · `vbscript:` · `data:text/html` · `file://`는 기본 `validateLink`가 막는다.
그런데 **`capacitor://localhost/...`는 링크로 만들어진다.** markdown-it은 Capacitor를 모르니 당연하다.

악성 `.md`가 `[여기를 누르세요](capacitor://localhost/...)`를 심어두면 사용자가 탭했을 때
웹뷰가 앱 내부 오리진으로 이동한다. **그래서 `validateLink` 교체는 선택이 아니라 필수다.**
아래 허용 목록 방식(allowlist)은 이 벡터를 막는다(실측 확인).

### 3.4 확정 코드 — `src/markdown/sanitize.ts`

```ts
import DOMPurify from 'dompurify';

/**
 * 링크 허용 목록.
 * 차단 목록(blocklist)이 아니라 허용 목록으로 간다 — capacitor://, intent://, content:// 같은
 * 안드로이드/Capacitor 고유 스킴을 일일이 나열할 수 없기 때문이다.
 * markdown-it 기본 validateLink는 capacitor:// 를 통과시킨다(실측). 반드시 이걸로 덮어쓴다.
 */
const SAFE_URL = /^(?:https?:|mailto:|tel:|#|\.{0,2}\/)/i;

export function isSafeUrl(url: string): boolean {
  return SAFE_URL.test(url.trim());
}

/**
 * DOMPurify 설정.
 * markdown-it html:false 가 이미 원시 HTML을 막으므로 이건 2차 방어선이다.
 * 파서 자체 취약점(과거 markdown-it/linkify-it에 CPU 고갈 CVE가 있었다)이나
 * highlight.js·KaTeX가 뱉는 HTML을 걸러내는 역할.
 */
export const PURIFY_CONFIG = {
  // KaTeX가 MathML(<math>, <semantics>, <annotation>)을 뱉으므로 mathMl 프로필이 필요하다.
  USE_PROFILES: { html: true, mathMl: true, svg: true },
  ADD_TAGS: ['annotation', 'semantics'],
  // KaTeX는 인라인 style로 글자 위치를 잡는다. style을 지우면 수식이 깨진다.
  ADD_ATTR: [
    'align', 'style', 'tabindex', 'aria-hidden', 'encoding', 'display',
    'checked', 'disabled', 'start', 'colspan', 'rowspan',
  ],
  FORBID_TAGS: [
    'script', 'style', 'iframe', 'object', 'embed', 'form', 'input',
    'base', 'link', 'meta', 'template', 'noscript', 'audio', 'video', 'source',
  ],
  FORBID_ATTR: ['srcset', 'formaction', 'ping', 'target', 'autofocus', 'loading'],
  ALLOW_DATA_ATTR: false,
  ALLOWED_URI_REGEXP: SAFE_URL,
} as const;

export function sanitize(html: string): string {
  return DOMPurify.sanitize(html, PURIFY_CONFIG) as unknown as string;
}
```

**주의 — `FORBID_TAGS`에 `style`이 있다.** `<style>` **태그**를 막는 것이고,
`ADD_ATTR`의 `style`은 **속성**이다. 둘은 다르다. 속성 쪽을 지우면 KaTeX 수식이 무너진다.
DOMPurify는 style 속성값 자체를 CSS 파서로 검사하므로 `style="background:url(javascript:...)"`는
속성을 허용해도 막힌다(실측 확인).

### 3.5 확정 코드 — 파서 인스턴스 `src/markdown/renderer.ts`

```ts
import MarkdownIt from 'markdown-it';
import anchor from 'markdown-it-anchor';
import footnote from 'markdown-it-footnote';
import taskLists from 'markdown-it-task-lists';
import { isSafeUrl } from './sanitize';
import { highlightCode } from './highlight';

/**
 * CJS/ESM 상호운용 래퍼.
 * 이 플러그인들은 번들러·환경에 따라 함수 / {default:fn} / {default:{default:fn}} 로 들어온다.
 * @vscode/markdown-it-katex 는 실제로 2중 래핑되어 있어서(실측) 이 처리가 없으면
 * "plugin.apply is not a function" 으로 죽는다.
 */
// eslint-disable-next-line @typescript-eslint/no-explicit-any
export function unwrapPlugin(m: any): any {
  if (typeof m === 'function') return m;
  if (typeof m?.default === 'function') return m.default;
  return m?.default?.default;
}

/** 한글 헤딩을 그대로 살리는 슬러그 생성기 */
function slugify(s: string): string {
  return encodeURIComponent(
    String(s).trim().toLowerCase().replace(/\s+/g, '-').replace(/[?!.,:;'"()[\]{}]/g, ''),
  );
}

export function createMarkdownIt(): MarkdownIt {
  const md = new MarkdownIt({
    html: false,       // ★ 절대 true 로 바꾸지 마라. 이게 1차 방어선이다.
    linkify: true,     // 맨 URL 자동 링크. 비용 1MB당 +25ms(실측). AI 문서에 URL이 많아 켠다.
    breaks: true,      // 한 줄 개행 = <br>. 7장 참조.
    typographer: false,// 한국어에 스마트 따옴표는 이득이 없고 CPU만 쓴다.
    highlight: highlightCode,
  });

  // ★ 반드시 덮어쓴다 — 기본값은 capacitor:// 를 통과시킨다(3.3절 실측).
  md.validateLink = isSafeUrl;

  md.use(unwrapPlugin(anchor), { permalink: false, slugify });
  md.use(unwrapPlugin(footnote));
  md.use(unwrapPlugin(taskLists), { enabled: false, label: true });
  //                                 ^ 뷰어에서는 체크박스를 읽기 전용으로. 편집 모드에서만 true.

  return md;
}
```

### 3.6 3차 방어선 — CSP

`index.html`에 넣는다. 인라인 스크립트를 못 쓰게 되므로 Vite 빌드는 인라인 스크립트가
나오지 않도록 `build.cssCodeSplit` 기본값을 유지하고 스크립트를 외부 파일로 뽑아야 한다.

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self';
               script-src 'self';
               style-src 'self' 'unsafe-inline';
               img-src 'self' data: https:;
               font-src 'self';
               connect-src 'self';
               object-src 'none';
               base-uri 'none';
               form-action 'none';
               frame-ancestors 'none'">
```

- `style-src`에 `'unsafe-inline'`이 필요한 이유: KaTeX가 인라인 style을 쓴다. 이건 스크립트 실행과 무관하다.
- `img-src`에 `https:`를 넣은 이유: 원격 이미지를 쓴 문서를 정상 표시하기 위해서다.
  **이건 문서가 열릴 때 외부로 요청이 나간다는 뜻**이므로, 설정에 **"원격 이미지 불러오기"(기본 꺼짐)** 토글을 두고
  꺼져 있으면 `img-src 'self' data:`만 쓰도록 한다. 개인정보 관점에서 기본 꺼짐이 맞다.
- **이 CSP는 실제 안드로이드 WebView에서 검증하지 못했다.** 기기 테스트 항목이다(8장).

## 4. 성능 — 5MB 마크다운을 열면 무슨 일이 벌어지는가

### 4.1 그냥 렌더하면: 8초 + 문서 끝에 도달 불가

데스크톱 Chromium 148에서 fetch → 파싱 → 살균 → `innerHTML` → 레이아웃까지 실측:

| 문서 | 파싱 | 살균 | DOM 삽입 | 레이아웃 | **합계** | DOM 노드 | scrollHeight |
|---|---|---|---|---|---|---|---|
| 50KB | 35ms | 19ms | 3ms | 65ms | **122ms** | 2,348 | 335K px |
| 500KB | 156ms | 145ms | 34ms | 357ms | **692ms** | 23,402 | 3.34M px |
| 1MB | 297ms | 358ms | 70ms | 875ms | **1,600ms** | 46,766 | 6.68M px |
| **5MB** | 1,540ms | 1,676ms | 456ms | 4,403ms | **8,074ms** | 233,282 | **33,554,432 px** |

**데스크톱에서 8초다.** 중저가 안드로이드 기기에서 몇 배가 될지는 측정하지 못했다.

### 4.2 더 심각한 문제 — Chromium의 스크롤 높이 한계

5MB 문서의 `scrollHeight`가 **정확히 33,554,432 = 2^25**로 나온 게 우연이 아니다.
마크다운과 무관하게 순수 CSS로 확인했다:

```
빈 div 높이 지정 → document.documentElement.scrollHeight 실측 (Chromium 148)
height:10,000,000px  → 10,000,032   (정상)
height:33,500,000px  → 33,500,032   (정상)
height:40,000,000px  → 33,554,432   ← 잘림
height:80,000,000px  → 33,554,432   ← 잘림
height:200,000,000px → 33,554,432   ← 잘림
```

**Chromium은 스크롤 높이를 2^25 px에서 하드 클램프한다.**
5MB 문서를 한 번에 DOM에 넣으면 이 한계에 딱 걸린다 = **문서 뒷부분에 스크롤로 도달할 수 없다.**
"느리다"가 아니라 **"문서 일부를 못 본다"**는 기능 결함이다.

측정한 선형 관계 (본 테스트 문서 기준, 본문 폭 720px / 17px / 줄간격 1.75):

| 소스 크기 | scrollHeight | 2^25 한계 대비 |
|---|---|---|
| 500KB | 3.40M px | 10.1% |
| 1MB | 6.80M px | 20.3% |
| 2MB | 13.59M px | 40.5% |
| 3MB | 20.37M px | 60.7% |
| 5MB | 33.55M px | **100% (클램프)** |

대략 **소스 1MB당 2^25의 20%**를 먹는다. 문서 성격(코드 비중, 표 개수)에 따라 달라지므로 정확한 상수는 아니다.

### 4.3 확정 대책 — 토큰 1회 파싱 + 청크 렌더 + `content-visibility`

두 가지 방식을 놓고 실제로 비교했다.

- **A안**: 소스 텍스트를 빈 줄 기준으로 잘라 청크별로 `md.render()` 호출
- **B안**: `md.parse()`로 문서 전체를 **한 번만** 토큰으로 만들고, 토큰 배열을 잘라 `md.renderer.render()` 호출

**A안은 정확성에서 탈락했다.** 각주 정의와 참조 링크 정의가 다른 청크에 있으면 연결이 끊긴다:

```
문서: 각주 참조[^1] 그리고 참조링크 [텍스트][ref]
      ...(중간에 문단 200개)...
      [^1]: 각주 정의
      [ref]: https://example.com

A안(소스 분할) 각주 링크 생성:   false   ← 깨짐
A안(소스 분할) 참조 링크 생성:   false   ← 깨짐
B안(토큰 분할) 각주 링크 생성:   true
B안(토큰 분할) 참조 링크 생성:   true
```

markdown-it은 참조 정의·각주 정의를 `env` 객체에 모은다. 문서를 한 번에 파싱해야 `env`가 완성된다.
**B안을 채택한다.**

**B안 성능 실측** (markdown-it 14.3.0, 살균·DOM 삽입 포함, `content-visibility: auto` 적용):

| 문서 | 토큰 수 | 파싱 1회 | **첫 화면까지** | 청크 중앙값 | 청크 최대 | 전체 완료 | scrollHeight |
|---|---|---|---|---|---|---|---|
| 1MB | 103,448 | 153ms | **157ms** | 1ms | 19ms | 879ms | 1.07M px |
| 2MB | 206,597 | 324ms | **326ms** | 1ms | 28ms | 1,853ms | 2.13M px |
| 5MB | 516,044 | 880ms | **909ms** | 1ms | **58ms** | 4,756ms | **5.31M px** |

단일 렌더와 비교하면:

| 5MB 문서 | 단일 렌더 | B안 |
|---|---|---|
| 첫 화면까지 | 8,074ms | **909ms (8.9배 개선)** |
| 전체 완료 | 8,074ms | **4,756ms (1.7배 개선)** |
| 최장 프레임 블로킹 | 8,074ms | **58ms** |
| scrollHeight | 33.55M px (**클램프, 끝에 도달 불가**) | 5.31M px (여유) |

**최장 블로킹 58ms**가 핵심이다. 100ms 아래면 사용자는 멈춤을 인지하지 못한다.

**정직하게 밝히는 한계 두 가지**

1. `content-visibility: auto` + `contain-intrinsic-size`는 화면 밖 섹션의 높이를 **추정값**으로 잡는다.
   그래서 **스크롤바 길이가 처음엔 부정확하고 스크롤하면서 보정된다.** 사용자가 문서 전체를 끝까지 훑으면
   실제 높이가 반영되면서 2^25 한계에 다시 근접할 수 있다. **이 시나리오는 측정하지 못했다.**
   그래서 4.4절의 크기 상한을 함께 둔다 — 두 대책은 세트다.
2. 위 측정에서 5MB가 청크 3,535개로 쪼개졌다. 섹션 요소가 그만큼 생긴다는 뜻이다.
   `TOKENS_PER_CHUNK`를 600 정도로 올려 청크 수를 1/5로 줄이는 튜닝이 필요하다.
   **어느 값이 최적인지는 기기에서 측정해야 한다.**

### 4.4 확정 — 문서 크기 상한과 사용자 안내

| 소스 크기 | 동작 |
|---|---|
| ~512KB | 청크 렌더, 안내 없음 |
| 512KB ~ 2MB | 청크 렌더, 하단에 "긴 문서를 불러오는 중" 진행 표시 |
| 2MB ~ 4MB | 열기 전 확인 다이얼로그: "이 문서는 N MB입니다. 여는 데 시간이 걸리고 기기가 느려질 수 있습니다. [열기] [취소]" |
| 4MB 초과 | **열지 않는다.** "이 문서는 N MB로 너무 큽니다. 안드로이드 화면 엔진의 한계로 문서 끝까지 표시할 수 없습니다. [텍스트로만 보기] [취소]" |

**4MB로 자른 근거**: 4MB면 2^25 한계의 약 81%(측정한 선형 관계 기준)로 안전 여유가 남는다.
5MB는 실측에서 정확히 100%에 걸려 문서 끝에 도달할 수 없었다.

"텍스트로만 보기"는 마크다운 파싱 없이 원문을 `<pre>`로 보여주는 경로다.
**단, 이 경로도 같은 2^25 한계를 받는다.** 그래서 여기서도 청크 렌더를 써야 한다. 파싱 비용만 없어진다.

### 4.5 왜 워커를 안 쓰는가 (그리고 언제 다시 볼 것인가)

- 파싱만 워커로 보낼 수 있다. **DOMPurify는 DOM이 필요해서 일반 워커에서 못 돈다.**
- 5MB 기준 파싱 880ms, 살균은 청크당 1ms로 이미 잘게 쪼개져 있다.
  파싱만 워커로 빼면 880ms의 메인 스레드 블로킹이 사라지지만, 5MB 소스 문자열을 워커로
  postMessage 하는 복사 비용과 토큰 배열을 되돌려 받는 비용이 새로 생긴다.
  **이 왕복 비용은 측정하지 못했다.**
- **v1에서는 워커를 쓰지 않는다.** 파싱 880ms 구간은 스켈레톤 UI로 덮는다.
  기기 실측에서 파싱이 2초를 넘으면 그때 워커를 도입한다(8장 항목).

### 4.6 확정 코드 — `src/markdown/render-pipeline.ts`

```ts
import type MarkdownIt from 'markdown-it';
import type Token from 'markdown-it/lib/token.mjs';
import { sanitize } from './sanitize';

/** 청크 하나에 들어갈 최상위 토큰 수. 기기 실측 후 조정할 것 (4.3절 한계 2번). */
const TOKENS_PER_CHUNK = 600;

/**
 * 토큰 배열을 nesting 균형이 맞는 지점에서만 자른다.
 * depth가 0인 지점 = 최상위 블록 경계이므로 여기서 잘라야 태그가 안 깨진다.
 */
function sliceTokens(tokens: Token[], perChunk = TOKENS_PER_CHUNK): Array<[number, number]> {
  const ranges: Array<[number, number]> = [];
  let start = 0;
  let depth = 0;
  for (let i = 0; i < tokens.length; i++) {
    depth += tokens[i].nesting;
    if (depth === 0 && i - start + 1 >= perChunk) {
      ranges.push([start, i + 1]);
      start = i + 1;
    }
  }
  if (start < tokens.length) ranges.push([start, tokens.length]);
  return ranges;
}

/** 다음 프레임까지 양보. 숨은 탭에서 rAF가 멈추므로 setTimeout 폴백을 함께 둔다. */
function yieldToBrowser(): Promise<void> {
  return new Promise((resolve) => {
    let done = false;
    const finish = () => { if (!done) { done = true; resolve(); } };
    requestAnimationFrame(finish);
    setTimeout(finish, 32);
  });
}

export interface RenderResult {
  headings: Array<{ level: number; text: string; id: string }>;
  cancel: () => void;
}

/**
 * 문서를 한 번만 파싱하고 토큰 슬라이스를 프레임마다 하나씩 DOM에 붙인다.
 * 첫 청크는 양보 없이 즉시 붙여서 첫 화면을 빨리 띄운다.
 */
export function renderProgressive(
  md: MarkdownIt,
  source: string,
  container: HTMLElement,
): RenderResult {
  const env: Record<string, unknown> = {};
  const tokens = md.parse(source, env);   // ★ 전체 1회 파싱 — env(각주·참조 정의)를 완성시킨다
  const ranges = sliceTokens(tokens);

  container.replaceChildren();

  let cancelled = false;

  const renderRange = (index: number): HTMLElement => {
    const [a, b] = ranges[index];
    const html = md.renderer.render(tokens.slice(a, b), md.options, env);
    const section = document.createElement('section');
    section.className = 'md-chunk';
    if (index > 0) {
      // 화면 밖 청크는 레이아웃을 건너뛴다. 이게 2^25 클램프와 레이아웃 비용을 동시에 줄인다.
      section.style.contentVisibility = 'auto';
      section.style.containIntrinsicSize = 'auto 1500px';
    }
    section.innerHTML = sanitize(html);
    return section;
  };

  // 첫 청크는 동기로 — 첫 화면을 최대한 빨리
  container.appendChild(renderRange(0));

  void (async () => {
    for (let i = 1; i < ranges.length; i++) {
      if (cancelled) return;
      await yieldToBrowser();
      if (cancelled) return;
      container.appendChild(renderRange(i));
    }
  })();

  return {
    headings: extractHeadings(tokens),
    cancel: () => { cancelled = true; },
  };
}

/** 목차용 헤딩 추출 — [[toc]] 플러그인 대신 토큰에서 직접 뽑는다(6.5절) */
export function extractHeadings(tokens: Token[]): Array<{ level: number; text: string; id: string }> {
  const out: Array<{ level: number; text: string; id: string }> = [];
  for (let i = 0; i < tokens.length; i++) {
    const t = tokens[i];
    if (t.type !== 'heading_open') continue;
    const inline = tokens[i + 1];
    out.push({
      level: Number(t.tag.slice(1)),          // h2 -> 2
      text: inline?.content ?? '',
      id: t.attrGet('id') ?? '',              // markdown-it-anchor가 붙여준 id
    });
  }
  return out;
}
```

## 5. 확장 기능 — 쓸지 말지 확정

### 5.1 GFM 표 · 취소선 · 자동 링크 → **markdown-it 내장, 추가 라이브러리 없음**

실제 출력으로 확인했다. 별도 플러그인이 필요 없다.

```
입력:  | a | b |
       |---|---|
       | 1 | 2 |
출력:  <table><thead><tr><th>a</th><th>b</th></tr></thead><tbody>...</tbody></table>

입력:  ~~취소선~~ https://example.com
출력:  <s>취소선</s> <a href="https://example.com">https://example.com</a>
```

- 표: 내장. `align` 속성이 붙으므로 DOMPurify `ADD_ATTR`에 `align`을 넣어뒀다.
- 취소선: 내장. `~~x~~` → `<s>`.
- 자동 링크: `linkify: true`. **비용 실측 1MB당 +25ms(63ms → 88ms, 약 40% 증가).**
  그래도 켠다 — AI 생성 문서에는 맨 URL이 흔하고, 탭해서 열 수 없으면 뷰어로서 답답하다.

### 5.2 GFM 체크박스 → **markdown-it-task-lists 2.1.1, 뷰어에서는 읽기 전용**

```
입력:  - [ ] 할 일
       - [x] 한 일
출력:  <ul class="contains-task-list">
         <li class="task-list-item"><label><input class="task-list-item-checkbox" type="checkbox"> 할 일</label></li>
         <li class="task-list-item"><label><input class="task-list-item-checkbox" checked="" type="checkbox"> 한 일</label></li>
       </ul>
```

**주의 두 가지.**

1. 이 플러그인은 **2018-03-06 이후 갱신이 없다.** 그럼에도 markdown-it 14.3.0과 15.0.0 양쪽에서
   정상 동작하는 걸 실제로 확인했다. 마크다운 문법이 바뀌지 않으니 방치돼도 문제없다.
   대안이 없으므로 쓴다. 깨지면 로직이 30줄 수준이라 직접 포팅 가능하다.
2. **`<input>`은 3.4절 `FORBID_TAGS`에 들어 있어서 DOMPurify가 지운다.**
   뷰어에서는 이게 오히려 맞다 — 읽기 전용이니 진짜 `<input>`이 필요 없다.
   **체크박스는 CSS로 그린다**(6.6절 스타일). 편집 모드에서 토글을 지원할 때는
   `<input>`을 살리는 대신 소스 텍스트의 `[ ]`↔`[x]`를 직접 고치고 다시 렌더하는 방식으로 간다.
   그래야 DOMPurify 설정을 느슨하게 만들지 않아도 된다.

옵션은 `{ enabled: false, label: true }`로 고정한다. `label: true`여야 글자를 탭해도 반응하는 구조가 된다.

### 5.3 코드 하이라이트 → **highlight.js 11.11.1, core + 언어 12개**

언어 수에 따른 gzip 실측:

| 구성 | min | **gzip** | brotli |
|---|---|---|---|
| `lib/core`만 (언어 0개) | 20.7KB | **8.4KB** | 7.6KB |
| **core + 언어 12개 ← 채택** | 72.3KB | **22.8KB** | 20.4KB |
| `lib/common` (언어 37개) | 157.9KB | **52.4KB** | 37.8KB |
| 전체 (언어 190개+) | 1,055.2KB | **307.1KB** | 238.3KB |

**언어 12개로 확정.** 목록과 근거:

```
javascript, typescript, python, java, kotlin, bash,
json, yaml, xml(=html), sql, css, markdown
```

- `kotlin`·`java`: 안드로이드 개발 문서
- `json`·`yaml`·`bash`: AI가 만드는 문서에서 압도적으로 흔하다 (설정 파일, 명령어)
- `markdown`: 마크다운 문법을 설명하는 문서가 이 앱 사용자층에 많을 것으로 본다 — **이건 가정이지 측정이 아니다**
- `xml`은 highlight.js에서 HTML을 겸한다

**등록 안 된 언어는 하이라이트 없이 이스케이프된 평문**으로 나온다. 깨지지 않는다.
언어 추가 요청이 들어오면 그때 늘린다. `common`(37개)까지 가도 +30KB라 여유는 있다.

**Shiki 4.3.1은 gzip 1,641KB로 측정됐다.** 전체 스택의 9배다. 검토 대상이 아니다.
Prism 1.30.0은 코어가 gzip 7KB로 더 작지만, 언어를 `Prism.languages` 전역에 꽂는 방식이라
번들러가 필요한 언어만 남기기 어렵다. highlight.js는 `lib/core` + 개별 언어 import가 깔끔히 분리된다(위 표의 8.4KB가 근거).

**확정 코드 — `src/markdown/highlight.ts`**

```ts
import hljs from 'highlight.js/lib/core';
import javascript from 'highlight.js/lib/languages/javascript';
import typescript from 'highlight.js/lib/languages/typescript';
import python from 'highlight.js/lib/languages/python';
import java from 'highlight.js/lib/languages/java';
import kotlin from 'highlight.js/lib/languages/kotlin';
import bash from 'highlight.js/lib/languages/bash';
import json from 'highlight.js/lib/languages/json';
import yaml from 'highlight.js/lib/languages/yaml';
import xml from 'highlight.js/lib/languages/xml';
import sql from 'highlight.js/lib/languages/sql';
import css from 'highlight.js/lib/languages/css';
import markdown from 'highlight.js/lib/languages/markdown';

const LANGUAGES = { javascript, typescript, python, java, kotlin, bash,
                    json, yaml, xml, sql, css, markdown };

for (const [name, lang] of Object.entries(LANGUAGES)) {
  hljs.registerLanguage(name, lang);
}

// 흔한 별칭 — hljs가 자체 별칭을 갖지만 자주 쓰는 것만 명시적으로 보강
hljs.registerAliases(['js'], { languageName: 'javascript' });
hljs.registerAliases(['ts'], { languageName: 'typescript' });
hljs.registerAliases(['py'], { languageName: 'python' });
hljs.registerAliases(['sh', 'shell', 'zsh', 'console'], { languageName: 'bash' });
hljs.registerAliases(['html'], { languageName: 'xml' });
hljs.registerAliases(['yml'], { languageName: 'yaml' });
hljs.registerAliases(['md'], { languageName: 'markdown' });

/**
 * markdown-it 의 highlight 옵션.
 * 빈 문자열을 반환하면 markdown-it 이 알아서 이스케이프 처리한다 — 그게 안전한 기본 동작이다.
 * 여기서 반환한 HTML 은 markdown-it 이 이스케이프하지 않고 그대로 넣지만,
 * 최종적으로 DOMPurify 를 통과하므로 안전하다.
 */
export function highlightCode(str: string, lang: string): string {
  if (!lang) return '';
  const name = lang.trim().toLowerCase().split(/[\s,{]/)[0];  // ```ts {1,3} 같은 표기 대응
  if (!hljs.getLanguage(name)) return '';
  try {
    return hljs.highlight(str, { language: name, ignoreIllegals: true }).value;
  } catch {
    return '';
  }
}

### 5.4 수식 → **KaTeX 0.18.1 + @vscode/markdown-it-katex 1.1.2, 지연 로딩**

**쓴다. 단 지연 로딩한다.**

- KaTeX JS: gzip **75.4KB** (실측)
- KaTeX CSS: 24.7KB
- KaTeX 폰트: **woff2 20개 = 296KB** (실측). `dist/fonts` 폴더 전체는 1.2MB지만 ttf/woff를 빼고 **woff2만 넣는다.**

합계 약 400KB. 수식 없는 문서가 대부분일 텐데 상시 로딩할 크기가 아니다.

**MathJax를 뺀 이유**: KaTeX보다 크고 렌더가 비동기라 4.6절 청크 파이프라인과 얽힌다.
KaTeX는 동기 렌더라 `md.render()` 안에서 끝난다.

**플러그인 선택 이유**: `markdown-it-texmath`는 마지막 배포가 2022-05-28로 오래됐다.
`@vscode/markdown-it-katex` 1.1.2는 2025-07-07 배포이고 VS Code가 실사용 중이라 유지가 보장된다.

**반드시 알아야 할 함정 — 이 패키지는 export가 2중 래핑돼 있다.**

```
import('@vscode/markdown-it-katex') 결과:
  exports: ['__esModule', 'default']
  default 타입: object      ← 함수가 아니다
  default 의 키: ['default'] ← 진짜 함수는 여기
```

`md.use(katexPlugin)`을 그냥 호출하면 **`plugin.apply is not a function`으로 죽는다.**
실제로 겪었다. 3.5절 `unwrapPlugin()`을 반드시 거쳐라.

**확정 코드 — `src/markdown/math.ts`**

```ts
import type MarkdownIt from 'markdown-it';
import { unwrapPlugin } from './renderer';

/** 문서에 수식이 있는지 값싸게 판정. 오탐이 나도 400KB를 한 번 더 받을 뿐 깨지지 않는다. */
export function looksLikeMath(source: string): boolean {
  return /(\$\$[\s\S]*?\$\$)|(\$[^\s$][^$\n]*\$)|\\\(|\\\[|\\begin\{/.test(source);
}

let mathLoaded = false;

/** 수식이 있을 때만 KaTeX 를 붙인다. md 인스턴스를 그 자리에서 확장한다. */
export async function ensureMath(md: MarkdownIt): Promise<void> {
  if (mathLoaded) return;
  const [katexPlugin] = await Promise.all([
    import('@vscode/markdown-it-katex'),
    import('katex/dist/katex.min.css'),
  ]);
  md.use(unwrapPlugin(katexPlugin), {
    throwOnError: false,   // 깨진 수식 때문에 문서 전체가 죽으면 안 된다
    errorColor: '#cc0000',
    strict: false,         // 한글이 수식 안에 들어와도 경고만 (실측: 한글 입력 시 경고 발생)
    trust: false,          // ★ \href, \htmlData 등 HTML 생성 명령 차단. 절대 true 로 바꾸지 마라
  });
  mathLoaded = true;
}
```

`trust: false`가 기본값이지만 **명시적으로 적는다.** `true`로 두면 `\href{javascript:...}`가
링크로 만들어진다. 실측에서 `trust:false` + DOMPurify 조합은 이 벡터를 막았다.

Vite에서 폰트를 woff2만 남기려면 `katex/dist/katex.min.css`를 그대로 import하면
Vite가 참조된 woff2만 번들에 넣는다. **ttf/woff 참조가 CSS에 남아 있으면 같이 딸려온다** —
빌드 후 `dist/assets`에 `.ttf`가 있는지 반드시 확인해라. 있으면 CSS에서 해당 `src` 항목을 제거한 사본을 쓴다.

### 5.8 YAML frontmatter → **js-yaml 4.1.1로 파싱해서 접이식 표로 보여준다**

**숨기지 않는다. 기본 접힘 상태의 표로 보여준다.**

- 완전히 숨기면: AI 문서의 `title`·`date`·`tags`가 사라진다. 뷰어에서 제목을 못 본다.
- 원문 그대로 보여주면: `---` 사이 YAML이 마크다운 문법상 `<hr>`이나 헤딩으로 오인돼 화면이 지저분해진다.
- **접이식 표**: 기본은 문서 제목만 보이고, 탭하면 전체 키/값이 표로 펼쳐진다. 둘 다 만족한다.

`markdown-it-front-matter`(0.2.4)를 안 쓰는 이유: 이 플러그인은 frontmatter를 **버리기만** 하고
파싱한 값을 돌려주지 않는다. 어차피 값을 써야 하니 직접 잘라내는 게 낫다.

**확정 코드 — `src/markdown/frontmatter.ts`** (아래 정규식·스키마는 실제로 돌려서 확인했다)

```ts
import yaml from 'js-yaml';

export interface ParsedDocument {
  frontmatter: Record<string, unknown> | null;
  body: string;
}

// ﻿ = BOM. 윈도우에서 만든 파일에 붙어 있으면 매치가 실패하므로 함께 처리한다.
const FRONTMATTER_RE = /^﻿?---\r?\n([\s\S]*?)\r?\n---\r?\n?/;

export function parseDocument(source: string): ParsedDocument {
  const m = FRONTMATTER_RE.exec(source);
  if (!m) return { frontmatter: null, body: source };

  try {
    const data = yaml.load(m[1], {
      // ★ CORE_SCHEMA 로 고정. DEFAULT_SCHEMA 는 커스텀 태그를 받는다.
      //    실측: CORE_SCHEMA 는 !!js/function 을 "unknown tag" 로 거부한다.
      schema: yaml.CORE_SCHEMA,
      json: true,
    });
    if (data === null || typeof data !== 'object' || Array.isArray(data)) {
      return { frontmatter: null, body: source };
    }
    return { frontmatter: data as Record<string, unknown>, body: source.slice(m[0].length) };
  } catch {
    // YAML 이 깨졌으면 frontmatter 없는 것으로 취급. 문서는 정상적으로 열려야 한다.
    return { frontmatter: null, body: source };
  }
}
```

실측 결과:

```
입력: ---
      title: 테스트 문서
      tags: [a, b]
      date: 2026-07-31
      nested:
        k: v
      ---

      # 본문

파싱: {"title":"테스트 문서","tags":["a","b"],"date":"2026-07-31","nested":{"k":"v"}}
본문: "\n# 본문\n내용"

악성 YAML `a: !!js/function "function(){return 1}"`
  → CORE_SCHEMA 에서 차단됨: "unknown tag !<tag:yaml.org,2002:js/function>"
```

**측정했지만 대책이 없는 것**: YAML 앵커 폭탄(billion laughs)은 `CORE_SCHEMA`에서도 **통과했다**
(테스트한 5단 중첩은 0ms에 끝나 무해했다). 더 깊은 중첩으로 메모리를 터뜨릴 수 있는지는 **확인하지 못했다.**
방어로 **frontmatter 블록이 64KB를 넘으면 파싱하지 않고 건너뛴다.** 정상 frontmatter는 1KB를 넘지 않는다.

```ts
// parseDocument 안, yaml.load 호출 직전에 넣을 것
if (m[1].length > 64 * 1024) return { frontmatter: null, body: source.slice(m[0].length) };
```

**js-yaml 5.2.2가 나와 있다**(2026-07-23). 6주도 안 된 메이저 버전이라 **쓰지 않는다.**
4.1.1은 `load()`가 이미 안전한 스키마를 쓰고(구 `safeLoad`와 동일), 검증도 마쳤다.

## 6. 한국어 처리

### 6.1 `breaks: true` — **기본값으로 켠다**

마크다운 표준(CommonMark)은 한 줄 개행을 공백으로 취급한다. 하지만:

- 한국어 문서, 특히 AI가 만든 문서는 문장마다 개행하고 그게 화면에도 반영되길 기대한다.
- 개행이 무시되면 문단이 한 덩어리로 뭉쳐서, 사용자는 "앱이 문서를 잘못 읽었다"고 판단한다.
- `breaks:false`가 맞는 경우는 표준 준수가 중요한 발행용 문서인데, **이 앱은 뷰어**다.

**성능 비용은 없다.** 실측(markdown-it 14.3.0, 1MB, linkify 끔): `breaks:false` 57ms vs `breaks:true` 63ms.
6ms 차이는 무시할 수준이다.

**설정에 토글을 둔다**: "줄바꿈 그대로 표시" — 기본 켜짐. 표준 동작을 원하는 사용자를 위해 끌 수 있게 한다.
토글을 바꾸면 `md` 인스턴스를 새로 만들고 다시 렌더한다(`md.set({ breaks })`로도 가능하다).

### 6.2 폰트 — **시스템 폰트만 쓴다. 웹폰트를 번들하지 않는다.**

Pretendard(한국어 웹폰트로 가장 널리 쓰인다) 실측:

```
Pretendard-Regular.woff2 (Regular 1개 weight만)  = 748KB
가변 폰트 woff2 전체                              = 약 2.0MB
```

**Regular 하나가 748KB다.** Bold까지 넣으면 1.5MB — 확정 JS 스택 전체(gzip 173KB)의 9배다.
읽기 앱에서 본문 폰트가 예쁜 건 가치가 있지만, **1.5MB를 주고 살 만큼은 아니다.**
한글은 음절 수가 많아서 서브셋으로도 크게 못 줄인다.

안드로이드는 Noto Sans CJK KR을 시스템에 갖고 있고, `sans-serif`가 한글에서 여기로 폴백된다.
품질이 충분하다.

**확정 폰트 스택**

```css
:root {
  /* 본문 — 시스템 폰트. -apple-system 은 iOS 대응(향후 확장 대비), 안드로이드에서는 Roboto→Noto Sans KR */
  --md-font-body:
    -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
    "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;

  /* 코드 — 안드로이드는 monospace 가 Droid Sans Mono/Roboto Mono 로 간다.
     한글이 섞이면 시스템이 알아서 Noto Sans KR 로 폴백하므로 마지막에 넣는다. */
  --md-font-code:
    ui-monospace, "SFMono-Regular", "Roboto Mono", "DejaVu Sans Mono",
    Consolas, monospace, "Noto Sans KR";
}
```

**확인 못 한 것**: 실제 안드로이드 기기에서 `monospace`가 어떤 폰트로 잡히는지, 그리고 코드 블록 안
한글이 등폭으로 정렬되는지는 **검증하지 못했다.** 기기 테스트 항목이다(8장).
한글은 어차피 등폭 폰트에서도 2칸을 차지해 정렬이 완벽하진 않다. 코드 안 한글은 주석이 대부분이라 큰 문제는 아니다.

### 6.3 한국어 줄바꿈 규칙

```css
.md-body {
  word-break: keep-all;      /* ★ 한국어에서 단어 중간을 끊지 않는다. 이거 없으면 어절이 잘려 읽기 나빠진다 */
  overflow-wrap: break-word; /* 단, 긴 URL·긴 영단어는 끊어야 화면 밖으로 안 나간다 */
  line-break: normal;
}

/* 코드 블록은 반대 — 줄바꿈하지 않고 가로 스크롤 */
.md-body pre {
  white-space: pre;
  overflow-x: auto;
  word-break: normal;
  -webkit-overflow-scrolling: touch;
}

/* 표도 가로 스크롤. 모바일에서 표가 화면을 밀어내는 게 흔한 사고다 */
.md-body .table-scroll { overflow-x: auto; }
.md-body table { border-collapse: collapse; width: max-content; min-width: 100%; }
```

`word-break: keep-all`은 한국어 렌더 품질에서 가장 체감이 큰 한 줄이다. 반드시 넣어라.

표는 `<table>`을 `<div class="table-scroll">`로 감싸야 한다. markdown-it 출력에는 이 래퍼가 없으므로
렌더 후 DOM에서 감싼다.

```ts
/** 청크를 DOM 에 붙인 직후 호출 — 표를 가로 스크롤 컨테이너로 감싼다 */
export function wrapTables(section: HTMLElement): void {
  for (const table of section.querySelectorAll('table')) {
    if (table.parentElement?.classList.contains('table-scroll')) continue;
    const wrap = document.createElement('div');
    wrap.className = 'table-scroll';
    table.replaceWith(wrap);
    wrap.appendChild(table);
  }
}
```

**체크박스 `checked` 클래스 붙이기** — markdown-it-task-lists는 `<input checked>`로 표시하는데
DOMPurify가 `<input>`을 지우므로 그 전에 `<li>`에 클래스를 옮겨야 한다.
`sanitize()` 호출 **전에** 문자열 치환으로 처리한다.

```ts
/** DOMPurify 가 <input> 을 지우기 전에 체크 상태를 <li> 클래스로 옮긴다 */
function liftTaskCheckedState(html: string): string {
  return html.replace(
    /<li class="task-list-item([^"]*)"><label><input([^>]*\bchecked\b[^>]*)>/g,
    '<li class="task-list-item$1 checked"><label><input$2>',
  );
}
```

**이 정규식은 실제로 돌려서 검증했다.** `enabled: false`(뷰어 기본) / `enabled: true`(편집 모드)
양쪽에서 정상 동작하고, 대문자 `[X]`도 처리된다.

```
enabled:false 원본
<li class="task-list-item"><label><input class="task-list-item-checkbox" disabled="" type="checkbox"> 할 일</label></li>
<li class="task-list-item"><label><input class="task-list-item-checkbox" checked="" disabled="" type="checkbox"> 한 일</label></li>

정규식 적용 후
<li class="task-list-item"><label>...            ← 미완료, 클래스 그대로
<li class="task-list-item checked"><label>...    ← 완료, checked 추가됨
```

**플러그인 버그 하나 주의**: `enabled: true`일 때 출력이
`<input class="task-list-item-checkbox"type="checkbox">`로 **속성 사이 공백이 빠진다.**
(2018년 이후 방치된 플러그인이라 그렇다.) HTML 파서는 이걸 관대하게 처리하므로 실사용에 지장은 없고,
위 정규식도 `[^>]*`로 받으므로 영향받지 않는다. 다만 출력 문자열을 다른 정규식으로 다룰 일이 생기면 기억해라.

### 7.4 다크모드 전환 방식

- **3단계: 시스템 따름 / 항상 밝게 / 항상 어둡게.** 기본은 "시스템 따름".
- `document.documentElement.dataset.theme = 'dark' | 'light'`로 전환. `prefers-color-scheme` 미디어쿼리만
  쓰면 앱 안에서 강제 전환을 못 한다.
- **전환 애니메이션을 넣지 마라.** 색상 트랜지션은 5MB 문서에서 전체 리페인트를 유발한다.
- `<meta name="theme-color">`와 Capacitor StatusBar 색도 함께 바꿔야 상단 바가 따로 논다는 인상을 안 준다.

```ts
import { StatusBar, Style } from '@capacitor/status-bar';

export async function applyTheme(mode: 'system' | 'light' | 'dark'): Promise<void> {
  const dark = mode === 'dark'
    || (mode === 'system' && window.matchMedia('(prefers-color-scheme: dark)').matches);
  document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  document.querySelector('meta[name="theme-color"]')
    ?.setAttribute('content', dark ? '#16181C' : '#FBFBF9');
  try {
    await StatusBar.setStyle({ style: dark ? Style.Dark : Style.Light });
    await StatusBar.setBackgroundColor({ color: dark ? '#16181C' : '#FBFBF9' });
  } catch {
    /* 웹 미리보기에서는 StatusBar 플러그인이 없다 — 무시 */
  }
}
```

```js
// npm run build 뒤에 실행. 예산 초과 시 exit 1 로 빌드를 실패시킨다.
const fs = require('fs');
const path = require('path');
const zlib = require('zlib');

const DIST = path.join(__dirname, '..', 'dist', 'assets');
const BUDGET_INITIAL_JS_KB = 200;   // 지연 청크 제외
const LAZY_CHUNKS = ['katex'];      // 이름에 이 문자열이 들어가면 초기 로딩에서 제외

let initial = 0;
const rows = [];
for (const f of fs.readdirSync(DIST)) {
  if (!f.endsWith('.js')) continue;
  const gz = zlib.gzipSync(fs.readFileSync(path.join(DIST, f))).length / 1024;
  const lazy = LAZY_CHUNKS.some((n) => f.includes(n));
  if (!lazy) initial += gz;
  rows.push([f, gz.toFixed(1), lazy ? '지연' : '초기']);
}
rows.sort((a, b) => Number(b[1]) - Number(a[1]));
for (const [f, kb, kind] of rows) console.log(`  ${kind}  ${kb.padStart(7)}KB  ${f}`);
console.log(`\n초기 JS 합계(gzip): ${initial.toFixed(1)}KB / 예산 ${BUDGET_INITIAL_JS_KB}KB`);

if (initial > BUDGET_INITIAL_JS_KB) {
  console.error(`\n✗ 번들 예산 초과: ${initial.toFixed(1)}KB > ${BUDGET_INITIAL_JS_KB}KB`);
  process.exit(1);
}
console.log('✓ 번들 예산 통과');
```

`package.json`에 연결:

  }
}

## 10. 확인하지 못한 것 / 기기에서 반드시 측정할 것

**추측을 사실처럼 쓰지 않기 위해 남긴다. 구현 에이전트는 이 항목을 측정하고 이 문서를 갱신해라.**

### 10.1 이 세션에서 확인하지 못한 것

1. **안드로이드 WebView 실제 성능.** 4장 숫자는 전부 데스크톱 Chromium 148이다.
   중저가 안드로이드 기기의 배수를 모른다. 4.4절 크기 상한(4MB)은 데스크톱 기준 2^25 클램프에서 나온 값이고,
   **기기가 느려서 그보다 낮춰야 할 가능성이 크다.**
2. **CSP가 안드로이드 WebView에서 의도대로 동작하는지.** Capacitor는 `capacitor://localhost` 오리진에서
   앱을 서빙하므로 `default-src 'self'`의 의미가 브라우저와 다를 수 있다. 실제 기기에서 검증해야 한다.
3. **`monospace` 폰트가 안드로이드에서 무엇으로 잡히는지**, 코드 블록 안 한글 정렬 상태.
4. **7.2절 대비비 숫자.** 목표값으로 적었고 실제 계산기로 검증하지 않았다.
5. **AAB 기준 용량.** Capacitor 8 빈 프로젝트의 AAB 크기를 측정하지 않았다. 8.2절 8MB는 목표치다.
6. **YAML 앵커 폭탄의 상한.** 5단 중첩은 무해했으나 더 깊은 중첩은 시험하지 않았다. 64KB 상한으로 회피했다.
7. **markdown-it 15.0.0이 왜 70% 느린지.** 갓 나온 릴리스의 회귀인지 구조 변경 때문인지 원인을 파악하지 못했다.
8. **`content-visibility` 섹션을 전부 펼친 뒤 2^25 클램프에 다시 걸리는지.** 4.3절 한계 1번.
9. **워커로 파싱을 옮길 때의 postMessage 왕복 비용.** 4.5절.
10. **`@types/js-yaml` 4.0.9 버전.** 설치·검증하지 않았다.
11. **WebSearch 도구가 이 세션에서 오류를 냈다.** 버전·크기 정보는 WebSearch 대신 npm 레지스트리 직접 조회와
    실제 패키지 설치·측정으로 확보했다. 라이브러리 커뮤니티 평판이나 최근 이슈 트래커 동향은 조사하지 못했다.

## 11. 절대 하지 말 것 (요약)

1. **`html: true`로 바꾸지 마라.** 1차 방어선이다. 어떤 이유로도 켜지 마라.
2. **`md.validateLink` 덮어쓰기를 빼지 마라.** 기본값은 `capacitor://`를 통과시킨다(3.3절 실측).
3. **DOMPurify를 "markdown-it이 이미 막으니까"라며 빼지 마라.** 파서 CVE가 실제로 있었다.
4. **KaTeX `trust`를 `true`로 바꾸지 마라.**
5. **Mermaid를 "지연 로딩하면 되니까"라며 넣지 마라.** 936KB는 지연 로딩해도 936KB다.
6. **한국어 웹폰트를 번들하지 마라.** Regular 하나가 748KB다.
7. **문서 전체를 한 번에 `innerHTML`에 넣지 마라.** 2^25 px 클램프에 걸려 문서 끝을 못 본다.
8. **소스 텍스트를 잘라서 청크마다 `md.render()`를 부르지 마라.** 각주와 참조 링크가 깨진다(4.3절 실측).
9. **버전에 `^`를 붙이지 마라.** 전부 정확히 고정한다.
10. **이 문서의 성능 숫자를 안드로이드 숫자로 인용하지 마라.** 전부 데스크톱 Chromium이다.
