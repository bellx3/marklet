## 1-1. 오늘 시작해야 하는 두 가지

### (A) 판매자 계정 (결제 프로필)

인앱결제를 팔려면 필수다. 없으면 **인앱 상품 메뉴가 회색으로 비활성**이다.

1. https://play.google.com/console/ 접속 → 좌측 맨 아래 **설정 → 결제 프로필**
2. **판매자 계정 만들기** 클릭
3. 화면에서 묻는 것: 이름 · 주소 · 전화번호 · **사업자 여부**
   - 개인으로 시작해도 된다. 나중에 사업자로 전환할 수 있다
4. 세금 정보 입력. 미국 세금 양식(개인이면 **W-8BEN**)이 포함된다
5. 은행 계좌 등록 (외화 수취가 되는 계좌)
6. **소액 입금 확인**: Google이 몇 백 원을 입금하고, 그 금액을 콘솔에 입력해야 확인이 끝난다.
   며칠 걸린다

> 픽셀오아시스에서 **가장 오래 걸린 인적 절차**가 이것이었다. 기다리는 동안 개발을 계속하면 된다.
> 이미 픽셀오아시스로 판매자 계정이 만들어져 있다면 **같은 개발자 계정 안에서는 다시 만들지 않는다.**
> 결제 프로필은 앱 단위가 아니라 개발자 계정 단위다. 그 경우 이 절은 건너뛴다.

### (B) 프로덕션 액세스 요건 — **확인 완료(2026-08-03). 걸린다. 이것이 일정의 임계 경로다**

> **2026-08-03 Play Console 에서 직접 확인했다. 두 번째 앱에도 적용된다.**
> 화면에 이 문구가 떠 있었다:
>
> > "아직 프로덕션에 액세스할 수 없습니다. 프로덕션을 신청하기 전에 수행해야 할 조치를
> > 알아보려면 고객센터를 방문하세요. 준비가 되었을 때 대시보드에서 프로덕션 액세스
> > 권한을 신청하면 됩니다."
>
> **픽셀오아시스가 이미 프로덕션에 게시되어 있어도 소용없다.** 아래 요건을 새로 채워야 한다.
> (초판은 이 항목을 "계정 단위인지 앱 단위인지 확인하지 못했다"로 남겨 뒀다. 확인됐다.)

**그래서 순서가 바뀐다. 완성한 뒤에 테스트를 시작하면 14일을 통째로 기다린다.**

| 순서 | |
|---|---|
| 1 | `01_제품_결정서.md` D1~D4로 **빈 껍데기라도 서명된 AAB**를 만든다 |
| 2 | **비공개 테스트 트랙에 올리고 테스터 12명 옵트인** ← 여기서 14일 시계가 시작된다 |
| 3 | 그 14일 동안 D5~D18 개발을 계속한다 |
| 4 | 시계가 끝나면 프로덕션 액세스 신청 → 승인 → 프로덕션 제출 |

Google 정책 원문(2026-07-31 확인):

> "Before you can apply to publish your app to production, you need to run a closed test which meets our criteria."
> "When you apply for production access, at least 12 testers must be opted-in to your closed test."
> — 적용 대상은 **"personal accounts created after November 13, 2023"**

그리고 기준은 이렇다: **12명 이상이 최근 14일 동안 연속으로 옵트인**되어 있어야 한다.
중간에 빠졌다 다시 들어오면 합계가 14일이어도 인정되지 않는다.

**진행 상황을 보는 곳 (콘솔에서):**

1. Play Console → 앱을 만든 뒤 → 좌측 **테스트 및 출시 → 프로덕션**
2. 화면 상단의 **"프로덕션 액세스 신청"**(Apply for production access) 카드
   - 카드가 **회색/비활성**이면 아직 14일 요건을 못 채운 것이다
   - 카드가 **눌리면** 요건을 채운 것이다. 신청하고 승인을 기다린다
3. **테스트 및 출시 → 테스트 → 비공개 테스트**에서 현재 옵트인한 테스터 수를 볼 수 있다
4. 대시보드에도 같은 취지의 작업 항목이 뜬다

> **12명 옵트인에서 틀리기 쉬운 것 세 가지.**
> - **설치만으로는 인정되지 않는다.** 각자 자기 구글 계정으로 **"테스터로 참여" 링크**를
>   눌러야 한다. APK를 보내 주고 깔라고 하면 0명으로 잡힌다.
> - **12명은 서로 다른 구글 계정**이어야 한다.
> - **중간에 빠졌다 다시 들어오면 14일이 처음부터 다시 시작된다.** 합계 14일은 인정되지
>   않는다. 그래서 **테스터에게 "앱을 지워도 되지만 테스터 참여는 풀지 말아 달라"고
>   미리 말해 둬야 한다.**
>
> 12명 모집이 개발보다 오래 걸릴 수 있다. **사람 모으는 일은 D1부터 시작해라.**

> 메뉴 이름이 `인앱 상품` 이 아니라 **`일회성 제품`** 이고, 상품 안에

**★★ 제품 ID와 구매 옵션 ID는 허용 문자가 다르다.**

### 1단계 — 상품 세부정보

1. **제품 ID** (위 표)
2. **이름**·**설명**. 언어는 `기본값 – 영어(미국)` 이므로 **영어로 넣는다.**
   한국어는 나중에 `번역 추가`로 붙이면 되고, 내부 테스트에는 없어도 된다.
   - 이름 상한 **55자**, 설명 상한 **200자**
   - 설명(en): `Buy the developer a coffee. Adds a supporter badge in Settings. Nothing in the app is locked.`
   - 설명(ko): `개발자에게 커피 한 잔을 보냅니다. 설정 화면에 후원자 표시가 붙습니다. 기능 제한은 없습니다.`
3. 아이콘 — **건너뛴다**(필수 아님). 태그 — **비운다**
4. 제품 세금 카테고리 `디지털 앱 판매` 그대로. 연령 등급 비움. 결제 위치 제한 없음

> 없는 걸 준다고 적으면 정책 위반이고, 결제한 사람이 아무 변화도 못 느껴 환불과 ★1로 돌아온다.
> 지금 문구는 **실제 동작에 맞춰 다시 쓴 것**이다.

### 2단계 — 구매 옵션 및 가격

1. **구매 옵션 ID** (위 표), **구매 유형 `구입`** 그대로
2. 가격 — **더 이상 자동 환산이 아니다.** 표의 가격이 전부 `-` 인 채로는 아무 데서도 못 산다.

만들고 나면 구매 옵션 줄에 **`이전 버전과의 호환성`** 배지가 붙는다. **이게 중요하다.**

우리 결제 플러그인(cordova-plugin-purchase 13.18)은 `구매 옵션` 모델을 모르는 세대다.
저 배지는 **옛 방식(`store.get('tip_coffee')`)으로도 조회된다**는 뜻이다.
배지가 없는 상품은 앱에서 그 버튼만 비활성으로 남는다.

> **소모성/비소모성은 콘솔에서 고르는 값이 아니다.** 소모성인지는
> **앱이 구매를 consume 하는지**로 정해진다. 코드에서 `ProductType.CONSUMABLE`로
> 등록하고 `finish()`를 부르면 consume된다. 이걸 틀리면 두 번째 후원에서
> `ITEM_ALREADY_OWNED`(에러 7)가 나고 **재후원이 통째로 막힌다.**
> (형제 문서 `07_조사_픽셀오아시스_자산.md` 5-4절에 플러그인 소스로 확인한 근거가 있다.)

> **순수 기부는 심사에서 걸릴 수 있다.** 그래서 아주 작은 감사 표시(후원자 배지)를 돌려주고,
> 설명에 "기능 제한은 없습니다"를 명시한다. 사실이면서 동시에 기부로만 읽히는 것을 막는다.

# 2. 서명 키 — 잃으면 앱이 죽는다

## 2-1. 키스토어 생성

**파일 이름 `marklet-upload-key.keystore`, 별칭 `marklet`으로 고정한다.**
`02_기술_설계서.md` 4-9절의 `keystore.properties.example`과 같은 값이어야 한다 —
두 문서가 다른 이름을 쓰면 `storeFile`이 없는 파일을 가리켜 릴리스 빌드가 그 자리에서 죽는다.

`android/app/` 디렉터리에서 실행한다.

```bash
cd android/app
keytool -genkeypair -v \
  -keystore marklet-upload-key.keystore \
  -alias marklet \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -storetype PKCS12
```

**`-storepass` / `-keypass`를 명령줄에 쓰지 마라.** 셸 히스토리에 평문으로 남는다.
위처럼 생략하면 keytool이 대화식으로 묻는다.

화면에서 보게 되는 것 (실제 순서, 한국어 JDK 기준):

1. `키 저장소 비밀번호 입력:` → 친다. **화면에 아무 글자도 안 보인다. 정상이다**
2. `새 비밀번호 다시 입력:`
3. `이름과 성을 입력하십시오.` → `marklet` 정도면 된다
4. `조직 단위 이름을 입력하십시오.` → 그냥 Enter
5. 조직 / 구·군·시 / 시·도 → Enter
6. `두 자리 국가 코드를 입력하십시오.` → `KR`
7. `CN=marklet, ..., C=KR이(가) 맞습니까? [아니오]:` → **`y`** 입력
8. 완료. `marklet-upload-key.keystore` 파일이 생긴다

`-validity 10000`은 약 27년이다. **업로드 키는 만료되면 안 된다.** 짧게 잡지 마라.

## 2-2. `android/keystore.properties`

```properties
storeFile=app/marklet-upload-key.keystore
storePassword=<위에서 정한 비밀번호>
keyAlias=marklet
keyPassword=<위와 같은 값>
```

`storeFile` 경로는 **`android/` 디렉터리 기준**이다.

**`storePassword`와 `keyPassword`가 같은 값인 것이 정상이다.**
JDK 9부터 keytool 기본 형식은 PKCS12이고, **PKCS12는 키별 비밀번호를 지원하지 않는다.**
`-keypass`로 다른 값을 줘도 keytool이 무시하고 경고만 낸다. 이 PC에서 실제로 확인한 경고 문구:

```
경고: 다른 저장소 및 키 비밀번호는 PKCS12 KeyStores에 대해 지원되지 않습니다.
사용자가 지정한 -keypass 값을 무시하는 중입니다.
```

다르게 적어 두면 그 자체가 나중에 혼란을 만든다.

그리고 커밋되는 템플릿 `android/keystore.properties.example`을 같이 만든다:

```properties
# 릴리스 서명 자격증명 템플릿
#
# 사용법:
#   1. 이 파일을 keystore.properties로 복사
#   2. 실제 값으로 채우기
#   3. keystore.properties와 키스토어 파일은 절대 커밋하지 말 것
#
# 이 파일이 없으면 릴리스 빌드가 서명 없이 생성됩니다.
# storeFile 경로는 android/ 디렉터리 기준입니다.
storeFile=app/marklet-upload-key.keystore
storePassword=YOUR_STORE_PASSWORD
keyAlias=YOUR_KEY_ALIAS
keyPassword=YOUR_KEY_PASSWORD
```

## 2-3. 검증 — `keytool -list`를 믿지 마라

**이걸 모르면 "비밀번호가 맞다"고 확인해 놓고 빌드에서 실패한다.**

`keytool -list`는 **인증서 목록을 읽을 뿐 개인 키를 건드리지 않는다.**
그래서 **store 비밀번호만 검증되고 key 비밀번호는 전혀 확인되지 않는다.**

이 PC에서 직접 실험해 확인했다 (JDK 21, 실험 후 파일 삭제):

```bash
# store=STORE111, key=KEY222 로 JKS 키스토어 생성
keytool -genkeypair -storetype JKS -keystore j.keystore -alias a \
  -keyalg RSA -keysize 2048 -validity 100 -storepass STORE111 -keypass KEY222 -dname "CN=t"

# (1) -list 는 store 비밀번호만으로 성공한다  → key 비번은 검사되지 않았다
keytool -list -keystore j.keystore -storepass STORE111          # exit 0

# (2) 개인 키를 실제로 쓰는 명령만이 key 비밀번호를 검증한다
keytool -certreq -alias a -keystore j.keystore -storepass STORE111 -keypass WRONGPW   # exit 1
keytool -certreq -alias a -keystore j.keystore -storepass STORE111 -keypass KEY222    # exit 0
```

> ### ★ 더 나은 검증 방법 (2026-08-03 실제로 이렇게 했다)
>
> `-certreq` 는 비밀번호를 명령줄이나 프롬프트로 넣어야 한다. **그럴 필요 없이
> `npm run build:aab` 로 릴리스 번들을 만들고 서명을 검증하는 쪽이 낫다.**
>
> - Gradle 이 `keystore.properties` 를 **자기가 읽어** 서명하므로 사람이(또는 에이전트가)
>   비밀번호를 입력하거나 볼 일이 없다.
> - **서명은 개인 키를 실제로 사용한다.** 따라서 성공하면 store·key 비밀번호가
>   **둘 다** 맞다는 뜻이다 — `-list` 함정을 그대로 우회한다.
> - 덤으로 `storeFile` 경로와 `keyAlias` 가 맞는지까지 한 번에 검증된다.
>
> ```bash
> npm run build:aab
> # 그다음 서명 검증 — 비밀번호가 필요 없다
> jarsigner -verify -verbose:summary android/app/build/outputs/bundle/release/app-release.aab
> #   → "jar verified." 가 나와야 한다
> jarsigner -verify -verbose -certs <위 파일> | grep X.509
> #   → CN 이 키스토어를 만들 때 넣은 값과 같아야 한다
> ```
>
> **2026-08-03 실행 결과:** `jar verified.` / `X.509, CN=baeksejong, ..., C=KR` /
> AAB 3.8MB(서명 전 3.7MB). 에이전트가 비밀번호를 보지 않고 검증을 마쳤다.

**아래 `-certreq` 방법도 유효하다 (백업본 복원 검증처럼 빌드를 돌릴 수 없을 때):**

```bash
keytool -certreq -alias marklet \
  -keystore android/app/marklet-upload-key.keystore \
  -storepass "<store 비밀번호>" -keypass "<key 비밀번호>" > /dev/null
echo $?     # 0이면 두 비밀번호가 모두 맞다
```

> **왜 이 함정이 중요한가.** 픽셀오아시스에서 비밀번호가 유출돼 회전(교체)을 검토했을 때,
> `-list`로 "확인됐다"고 판단하면 **key 비밀번호가 반쪽만 바뀐 상태를 통과시킨다.**
> 그러면 `gradlew bundleRelease`가 서명 단계에서만 실패하고, 그때는 원인이 비밀번호라는 것도
> 바로 안 보인다.

지문도 함께 기록해 둔다 (Play Console의 업로드 키 지문과 대조할 때 쓴다):

```bash
keytool -list -v -keystore android/app/marklet-upload-key.keystore -alias marklet | grep -i "SHA-256"
```

## 2-5. 실제로 일어난 유출 사고와 회전 절차

**픽셀오아시스 커밋 `ada4447` (2026-07-31), 제목 "보안: 커밋된 임시 메모에서 키스토어 비밀번호 제거".**

### 무엇이 잘못됐나

`.docs/_temp.md`가 git에 **추적된 채** 키스토어 비밀번호와 키 비밀번호를 **평문으로** 담고 있었다.
`origin/master`에도 올라가 있었고 **9개 커밋에 걸쳐** 남아 있었다.
그 파일은 1.0.7 시절 Android Studio 수동 빌드 절차를 적어 둔 작업 메모였다.
**누가 악의로 넣은 게 아니다.** 빌드하면서 임시로 적어 둔 것이 그대로 커밋된 것이다.

이게 이 사고의 핵심이다 — **"조심하자"로는 막히지 않는다.** 작업 메모는 원래 자격증명이 섞인다.

### 피해 범위 확인 (이 순서를 그대로 따라라)

```bash
# 1) 저장소가 공개인지 확인 → 픽셀오아시스는 비공개였다 (비인증 GitHub API 조회가 404)
# 2) 키 파일 자체가 커밋된 적이 있는지 — 전체 이력에서 "추가" 이벤트를 찾는다
git log --all --diff-filter=A --format="%h %s" -- \
  "*.keystore" "*.jks" "android/keystore.properties" "android/play-service-account.json"
#    → 0건

# 3) 지금 실제로 무시되고 있는지
git check-ignore -v android/keystore.properties android/play-service-account.json
#    → 두 줄 다 규칙에 걸림
```

**결론: 유출된 것은 비밀번호 문자열뿐이고 키스토어 파일 자체는 안전했다.**
파일이 없으면 비밀번호만으로는 서명할 수 없다. 그래도 원격 이력에 남아 있으므로 교체 대상이다.

### 회전(교체) 절차

Play 앱 서명을 쓰고 있으면 **업로드 키만 바꾸면 된다.** 앱 서명 키는 Google이 갖고 있어
사용자 설치본에는 영향이 없다.

1. 새 키스토어를 만든다 (2-1절)
2. Play Console → **설정 → 앱 무결성 → 앱 서명 → 업로드 키 재설정 요청**
3. 새 키의 인증서를 내보내 첨부한다:
   ```bash
   keytool -export -rfc -keystore new-key.keystore -alias marklet -file upload_certificate.pem
   ```
4. Google 승인을 기다린다 (수 일)
5. 승인되면 `android/keystore.properties`를 새 값으로 바꾼다
6. **2-3절의 `-certreq` 검증을 새 값으로 다시 돌린다** (반쪽 교체 방지)
7. 옛 비밀번호를 쓰는 문서·메모를 전부 지운다


작업 메모를 **`.docs/_temp.md` 한 곳으로 몰고 그 파일을 통째로 무시한다.**
비밀번호를 어디에 적을지 고민하지 않아도 되게 만드는 것이 요점이다.

# 4. 데이터 안전(Data Safety) 양식

## 4-1. 답의 근거 — "수집"의 정의부터 확인했다

Google 공식 문서 원문(2026-07-31 확인):

> **"Collect" means transmitting data from your app off a user's device.**

> "User data accessed by your app that is only processed locally on the user's device
> and not sent off device does not need to be disclosed."

**"기기 밖으로 전송"이 수집이다.** 기기 안에서만 처리하는 것은 신고 대상이 아니다.
이 앱은 문서 내용도, 파일 이름도, 설정도 전송하지 않는다. 그래서 **전 항목 "수집 안 함"** 이다.

결제에 대해서도 명시적 면제가 있다. 같은 문서:

> 결제 서비스(PayPal, Google Pay, Google Play's billing system 등)가 수집하는 데이터는,
> **"Your app never accesses this information; and The payment service collects this
> information directly from the user, and collection is governed by that service's terms"**
> 두 조건을 만족하면 신고하지 않아도 된다.

우리 앱은 두 조건을 모두 만족한다. 앱이 받는 것은 상품 ID와 거래 ID뿐이고, 그것도 기기 밖으로
나가지 않는다.

> **이것이 형제 문서 `06_조사_파일처리.md` 7-4절이 "확인하지 못했다"고 남긴
> 질문의 답이다.** 팁 인앱결제 때문에 "구매 내역"을 신고할 필요는 **없다.**
> 단, 나중에 서버(예: 후원자 목록 동기화)를 붙이는 순간 답이 바뀐다.

## 5-2. 각 문항의 답

> **먼저 밝힌다.** IARC 설문의 **정확한 문항 문구는 이번 세션에서 확인하지 못했다.**
> Google 도움말 페이지에는 설문 본문이 실려 있지 않고, 설문은 Play Console 로그인 뒤에만 열린다.
> 아래는 **픽셀오아시스에서 같은 설문을 통과한 기록**과 IARC 유틸리티 카테고리의 알려진
> 문항 구성을 근거로 한 것이다. 화면 문구가 다르면 **의미가 같은 문항**을 찾아 아래 원칙대로 답해라.

| 문항 (의미 기준) | 답 | 이유 |
|---|---|---|
| 폭력적 콘텐츠를 포함하나요? | 아니요 | 앱 자체는 문서를 표시할 뿐이다 |
| 성적인 콘텐츠·노출이 있나요? | 아니요 | |
| 욕설·비속어가 포함되나요? | 아니요 | |

## 5-3. "사용자 생성 콘텐츠" 문항 — 이 앱에서 가장 헷갈리는 지점

**사용자가 임의의 문서를 여는 앱이다. 그러면 UGC 앱인가? 아니다.**

IARC와 Google Play가 묻는 것은 **"사용자들 사이에서 콘텐츠가 오가는가"** 이다.
정확히는 이런 것들이다: 게시판, 댓글, 프로필, 채팅, 업로드한 파일이 다른 사용자에게 보이는 것.

이 앱은:

- 서버가 없다. 콘텐츠를 호스팅하지 않는다
- 다른 사용자라는 개념이 존재하지 않는다. 계정도 없다
- 사용자는 **자기 기기에 있는 자기 파일**을 자기만 본다
- 앱이 만드는 것은 그 파일의 화면 표시일 뿐이다

**→ 답은 "아니요"다.** 워드 문서 뷰어가 UGC 앱이 아닌 것과 같은 이유다.

**바뀌는 조건 (지금은 해당 없음, 만들지 마라):**

- 문서를 공유 링크로 만들어 주는 기능 → **그 순간 UGC 앱이 된다.** 신고 항목이 늘고,
  Play의 UGC 정책(신고 기능·차단 기능·중재 정책 문서화)이 통째로 적용된다
- 앱 안에서 다른 사용자의 문서를 볼 수 있는 갤러리·샘플 공유
- 댓글·평점을 앱 안에서 주고받는 기능

## 5-4. "제한 없는 인터넷 브라우저"에 "아니요"라고 답하는 근거

문서 안의 링크를 누르면 브라우저가 열린다. 그런데 이건 **인앱 브라우저를 제공하는 것과 다르다.**

- 우리는 `@capacitor/browser`로 **시스템 브라우저(Custom Tabs)** 를 연다.
  주소창도, 임의 URL 입력도 앱 안에 없다
- 사용자가 앱 안에서 임의의 주소를 입력해 웹을 돌아다닐 수 없다
- 링크는 **사용자가 연 자기 문서 안에 있던 것**이다

**구현 조건이 붙는다.** 아래를 지켜야 이 답이 참이 된다.

1. 웹뷰 안에서 외부 링크가 열리면 안 된다. `<a>` 클릭을 가로채 `Browser.open()`으로 넘긴다
2. `capacitor.config.json`에 **`server.allowNavigation`을 넣지 않는다**
   (픽셀오아시스 설정에도 없다 — 형제 문서 1-2절에서 실제로 확인된 사실이다)
3. 링크를 열기 전에 `http:` / `https:` / `mailto:` 만 허용한다.
   `javascript:` 같은 스킴은 거른다 (`05_조사_렌더링스택.md`의 `validateLink` 오버라이드)

## 5-5. 등급이 바뀌면 다시 해야 한다

Google 원문:

> "all app updates where there has been a change to your content or features that would
> affect the responses to the questionnaire"

즉 **팁 IAP를 떼거나 붙일 때, 공유 기능을 추가할 때 설문을 다시 제출해야 한다.**
설문을 안 하면 앱이 "등급 미정(Unrated)"이 되고, 그 상태는 **앱 삭제 사유**가 된다.

# 6. 스토어 등재

## 6-1. 언어 — 기본 en-US, 한국어 추가. 둘 다 쓴다.

**결정: 기본 언어 `en-US`, 추가 언어 `ko-KR`. 두 개만.**

근거는 픽셀오아시스에서 실측한 것이다. `store/ANALYTICS.md`에 남아 있는 값:

| 지표 (28일, 휴대기기) | 값 |
|---|---|
| 기기 노출수 | 155 (−57%) |
| 설치 | 2 |
| 스토어 등재 전환율 | 11.32% |

그리고 최근 90일 노출 대부분이 **브라질·인도·우즈베키스탄·이집트**에서 왔다.
픽셀오아시스의 기본 언어는 `ko-KR`이다. **그 사람들은 한국어 설명을 읽고 있었다.**

Play의 폴백 규칙 (Android Publisher API `edits.details`로 확인된 사실):

| 기기 언어 | 기본 ko-KR일 때 보는 것 | 기본 en-US일 때 보는 것 |
|---|---|---|
| 한국어 | ko-KR | **ko-KR** (등재가 있으므로) |
| 영어 | en-US | en-US |
| 포르투갈어·스페인어·아랍어 | **ko-KR** ← 문제 | **en-US** |

**기본을 en-US로 잡으면 한국 사용자는 그대로 한국어를 보고, 나머지 전 세계는 한국어 대신
영어를 본다.** 마크다운 뷰어는 개발자·학생용 도구라 해외 비중이 픽셀오아시스보다 크다.
그리고 **기본 언어는 나중에 바꾸기가 번거롭다.** 앱 만들기 화면에서 처음부터 en-US로 잡아라.

> **이미지는 언어별로 따로 올리지 않으면 기본 언어 것이 재사용된다.**
> (픽셀오아시스에서 API로 확인 — en-US 등재의 이미지 개수가 0인 것이 정상이었다.)
> 즉 스크린샷은 **en-US에만** 올리면 된다. 한국어 스크린샷을 따로 만들 여력이 생기면
> 그때 ko-KR에 추가한다.

**언어를 추가하는 위치:** Play Console → **사용자 늘리기 → 스토어 실적 → 기본 스토어 등록정보**
→ 상단 **"수정할 언어 선택"** 에서 `한국어(대한민국) – ko-KR` 추가.

> **콘솔의 "AI로 번역 가져오기"를 쓰지 마라.** 아래 한국어 문구는 번역이 아니라
> 한국 검색어를 겨냥해 새로 쓴 것이다. 기계 번역으로 덮으면 검색어가 날아간다.

**픽셀오아시스에서 실제로 정책에 걸렸거나 걸릴 뻔한 것들:**

- **없는 기능을 쓰면 메타데이터 정책 위반이다.** 픽셀오아시스는 실제로 한 번 걸렀다 —

- **가격을 설명에 쓰지 마라.** 통화·지역별로 다르고 바뀌면 거짓이 된다
  (그래서 아래 문구에 "₩1,500" 같은 표현이 하나도 없다)

**줄바꿈은 보존된다.** 콘솔의 **애셋 리뷰** 화면이 자세한 설명의 줄바꿈을 접어서 한 덩어리로

```text
· 저장소 권한을 아예 요청하지 않습니다. 사용자가 파일을 고르는 것이 곧 권한입니다

문서를 읽고, 그리고, 저장하는 모든 일이 기기 안에서 끝납니다.

■ 인터넷 없이도

전부 기기 안에서 처리되므로 지하철에서도, 비행기에서도, 신호가 약한 곳에서도 그대로 열립니다.

■ 후원

모든 기능은 무료이고 잠긴 것은 없습니다. 도움이 되었다면 설정에서 가볍게 후원하실 수 있고, 설정 화면에 후원자 표시가 붙습니다. 후원하지 않아도 빠지는 기능은 없습니다.

혼자 만드는 앱입니다. 의견을 보내면 사람이 직접 읽습니다: contact@example.com
```

> **이 문구를 그대로 게시하기 전에 반드시 확인할 것.**
> 위 문장은 전부 **형제 문서들에서 v1.0 범위로 확정된 기능**만 담았다. 그래도 출시 시점에
> 하나라도 빠졌다면 **그 문장을 지우고 게시해라.** 9장 체크리스트에 대조 항목을 넣어 두었다.
> 특히 초성 검색과 Mermaid는 구현 난이도가 있는 항목이다.
>
> **2026-08-03 정비에서 고친 것 두 가지.**
> - 초판은 "체크박스를 체크하고"(en: "tick a checkbox")라고 썼는데, **뷰어의 체크박스는

## 6-7. 출시 노트 (What's new)

**GPP가 자동으로 올린다.** 파일 위치가 정해져 있다:

```
android/app/src/main/play/release-notes/en-US/default.txt
android/app/src/main/play/release-notes/ko-KR/default.txt
```

**언어 디렉터리 이름은 Play의 등재 언어와 정확히 같아야 한다.** 픽셀오아시스는
`release-notes/ko-KR/default.txt` 하나만 두고 있었다 (기본 언어가 ko-KR이었기 때문).
**새 앱은 기본이 en-US이므로 `en-US/`가 반드시 있어야 하고, ko-KR도 같이 둔다.**

첫 출시용 초안 (각 500자 이내):

`en-US/default.txt`
```text
First release.

• Opens .md files from other apps, or from the built-in file picker
• Mermaid diagrams, KaTeX math, GFM tables with sideways scrolling, footnotes, task lists, highlighted code
• Saves back to the original file, and tells you when a save fails
• Table of contents, find in document, dark mode, eight text sizes
• Works offline. Nothing is sent off your device.
```

`ko-KR/default.txt`
```text
첫 출시입니다.

• 다른 앱에서 md 파일을 눌러 바로 열 수 있습니다
• 머메이드 다이어그램, 수식, 가로 스크롤되는 표, 각주, 체크박스, 코드 색칠
• 개행 유지가 기본이라 엔터를 친 대로 줄이 바뀝니다
• 저장은 원본 파일에 그대로 덮어쓰고, 실패하면 반드시 알려드립니다
• 목차, 문서 내 검색(초성 지원), 어두운 테마, 여덟 단계 글자 크기
• 인터넷 없이 동작하고 문서는 기기를 벗어나지 않습니다
```

> **왜 등재 문구는 `play/listings/`에 두지 않는가.**
> GPP는 `android/app/src/main/play/listings/<lang>/` 아래의 제목·설명도 업로드할 수 있다.
> **두지 마라.** 그렇게 하면 `npm run publish:internal`처럼 **내부 트랙에만 올리는 작업에서도
> 실제 공개 스토어 문구가 교체된다.** 출시 노트는 트랙(출시 단위)에 붙는 값이라 안전하지만
> 등재 문구는 앱 전체에 하나뿐인 공개 정보다. 픽셀오아시스는 이 이유로 등재 문구를
> `store/` 디렉터리에 두고 **콘솔에서 수동 반영**했다. 같은 구조를 쓴다:
> ```
> store/
>   en-US/{title,short-description,full-description}.txt
>   ko-KR/{title,short-description,full-description}.txt
>   assets/{app-icon-512.png, feature-graphic-1024x500.png}
> ```

## 6-8. 이미지 규격 (Google 공식 문서에서 확인, 2026-07-31)

| 자산 | 규격 | 개수 |
|---|---|---|
| 앱 아이콘 | **512 × 512 px**, **32비트 PNG (알파 포함)**, 최대 **1024KB** | 1 |
| 그래픽 이미지(피처 그래픽) | **1024 × 500 px**, **JPEG 또는 24비트 PNG (알파 없음)** | 1 |

| 10인치 태블릿 | 16:9 또는 9:16, 1,080 ~ 7,680px | **4장** |

권장 해상도: 세로 **1080 × 1920**, 가로 **1920 × 1080** (Google이 추천 노출 자격 기준으로 명시한 값).

> **주의 — 아이콘 알파 채널.**
> 픽셀오아시스의 `store/README.md`에는 아이콘이 "512x512, 알파 없음"으로 적혀 있는데,
> **Google 공식 문서는 아이콘을 "32-bit PNG (with alpha)"로 명시한다.**
> 알파 없는 PNG도 업로드는 되지만, 공식 규격을 따라 **알파 포함 32비트 PNG**로 만들어라.
> 알파를 요구하지 않는 것은 **피처 그래픽**(24비트, 알파 없음)이다. 둘을 헷갈리기 쉽다.

> **태블릿 스크린샷을 비워 두지 마라.** 픽셀오아시스는 오랫동안 7인치·10인치가 비어 있었고,
> 그 때문에 **태블릿·Chromebook 노출에서 빠지고 Play의 대화면 품질 평가에서도 불리했다.**
> 마크다운 뷰어는 태블릿에서 특히 잘 쓰이는 종류의 앱이다. 처음부터 채워라.

## 6-9. 스크린샷 — 무엇을 몇 번째에 둘 것인가

**목록에서는 보통 앞 3장까지만 보인다. 그 3장이 전부를 결정한다.**
그리고 **브랜드 히어로 화면을 1번에 두지 마라 — 예쁘지만 무슨 앱인지 말해주지 않는다.**
(픽셀오아시스는 히어로를 8번으로 내리는 것이 등재 개선 작업의 첫 항목이었다.)

### 휴대전화 8장

| # | 화면 | 왜 이 순서인가 |
|---|---|---|
| **1** | **Mermaid 다이어그램이 그려진 문서** | 경쟁 앱 어느 것도 같은 그림을 못 건다. Mermaid를 설명문에 명시한 뷰어는 조사한 20개 중 설치 500+ 짜리 하나뿐이다 |
| **2** | **열이 많은 표가 가로로 스크롤되는 화면** (손가락 또는 스크롤 힌트 포함) | 설치 10만짜리 1위 앱이 표 오른쪽을 못 보여준다는 한국어 리뷰가 실제로 있다. 이건 "우리는 된다"를 3초에 보여준다 |
| **3** | **한국어 문서 — 개행 그대로 + 어절 단위 줄바꿈** | 한국 사용자 이탈의 첫 순간을 없앤 화면. before/after 대비로 만들면 더 강하다 |

| 6 | 목차 서랍 + 문서 내 검색(초성 입력 상태) | 목차·검색을 갖춘 상위권 앱이 없다 |

| 8 | 다른 앱의 "연결 프로그램" 목록에 앱이 뜬 화면 또는 최근 문서 목록 | "내 파일이 열린다"는 약속의 증거 |

### 태블릿 4장 (7인치·10인치 각각, **가로 모드로 찍는다**)

| # | 화면 |
|---|---|
| 1 | 목차가 펼쳐진 채 문서를 읽는 화면 (넓은 화면의 이점이 보인다) |
| 2 | Mermaid 다이어그램 |
| 3 | 넓은 표 |
| 4 | 어두운 테마 |

### 캡처 절차 (에뮬레이터, 사람 없이도 된다)

```bash
# 1) 태블릿 에뮬레이터 (픽셀오아시스는 Medium_Tablet 2560x1600, 320dpi, API 35를 썼다)
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd Medium_Tablet -no-boot-anim

# 2) 디버그 APK 설치 (패키지가 .debug라 스토어 본앱과 충돌하지 않는다)
adb -s emulator-5554 install -r android/app/build/outputs/apk/debug/app-debug.apk

# 3) 가로 고정
adb -s emulator-5554 shell settings put system accelerometer_rotation 0
adb -s emulator-5554 shell settings put system user_rotation 1
#    user_rotation: 0=세로, 1=가로(왼쪽), 3=가로(오른쪽)

# 4) 테스트 문서를 넣는다
adb -s emulator-5554 push docs/screenshot-demo.md /sdcard/Download/demo.md
adb -s emulator-5554 shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Download/demo.md

# 5) 캡처 — exec-out 이어야 한다
adb -s emulator-5554 exec-out screencap -p > build/store/shot-01.png
```

**`exec-out`이 아니면 안 된다.** `adb shell screencap -p > f.png`는 Windows에서 줄바꿈이
CRLF로 변환되어 **PNG가 깨진다.** `exec-out`은 바이너리를 그대로 흘린다.

**`Medium_Tablet`은 2560×1600 = 16:10이라 Play가 요구하는 16:9가 아니다.**
좌우에 여백을 덧대 16:9로 맞춰라 (잘라내면 화면 아래쪽 조작 안내가 잘린다 — 픽셀오아시스에서
실제로 겪은 것이다). 배경이 흰색에 가까운 UI 화면은 여백을 덧대도 이어져 보인다.

### 업로드 전 필수 확인

**폭 200px로 줄여서 봐라.** 목록에서 그 정도 크기로 나온다.
**그 크기에서 무슨 화면인지 모르겠으면 다시 찍는 게 맞다.**

스크린샷용 데모 문서는 **저장소에 커밋해 둬라** (`docs/screenshot-demo.md`).
다음 버전에서 같은 화면을 다시 찍어야 하는데, 그때 같은 문서가 없으면 그림이 달라진다.

## 6-10. 효과 판정 — 바로 늘지 않는 것이 정상이다

**문구 변경은 검색 색인 갱신에 며칠 ~ 2주 걸린다.**
2주 뒤 **사용자 늘리기 → 내 Play 실적**에서 `기기 노출수`를 본다.
출시 직후 며칠의 숫자로 판단하지 마라.

픽셀오아시스에서 얻은 교훈 하나 더: **병목은 전환율이 아니라 노출이었다.**
노출 155 → 등재 방문 18 → 설치 2. 전환율을 두 배로 올려도 설치는 2 → 4다.
노출이 10배면 같은 전환율로 20이다. **그래서 이름·간단한 설명·자세한 설명 세 곳
(= Play 검색 색인의 표면)을 처음부터 꽉 채워라.** 픽셀오아시스는 자세한 설명이
797/4000자로 80% 비어 있었다.

# 7. 빌드·배포 파이프라인

여기 있는 파일은 **그대로 복사해 쓸 수 있는 전문**이다.

## 7-1. `package.json` 스크립트

```json
{
    "scripts": {
        "dev": "vite",
        "dev:device": "node scripts/dev-device.cjs",
        "build": "vite build",
        "build:android": "npm run build && npm run sync:android",
        "build:aab": "node scripts/build-aab.cjs",
        "release": "npm run build:android && npm run build:aab",
        "publish:internal": "npm run build:android && node scripts/publish.cjs internal",
        "publish:production": "npm run build:android && node scripts/publish.cjs production",
        "sync:android": "npx cap sync android && node scripts/remove-flatdir.cjs",
        "open:android": "npx cap open android",
        "logcat": "node scripts/logcat.cjs",
        "play:status": "node scripts/play-status.cjs",
        "lint": "eslint src --ext .ts",
        "test": "vitest"
    }
}
```

| 스크립트 | 하는 일 |
|---|---|
| `build:aab` | **서명된 릴리스 AAB 생성.** Android Studio 없이 CLI만으로. JDK 자동 탐색 포함 |
| `publish:internal` | 빌드 후 내부 테스트 트랙 업로드 |
| `publish:production` | 빌드 후 프로덕션 업로드. `yes` 확인 프롬프트가 뜬다. **서비스 계정에 권한을 주지 않았으므로 실제로는 실패한다 — 그게 의도다**(함정 5) |
| `play:status` | Play Console을 열지 않고 각 트랙의 상태·버전코드·배포비율 조회 |

**스크립트 파일 확장자는 `.cjs`여야 한다.** `package.json`에 `"type": "module"`이 있어서
`.js`로 두면 `require`가 죽는다.

## 7-2. `android/app/build.gradle` — 서명·버전·업로드 블록

```groovy
apply plugin: 'com.android.application'

// ---------------------------------------------------------------------------
// 버전: package.json을 단일 소스로 사용합니다.
// versionName은 그대로, versionCode는 major*10000 + minor*100 + patch로 계산합니다.
// (예: 1.0.15 -> 10015) 같은 버전을 두 번 올릴 수 없으므로 재배포 시 patch를 올리세요.
// ---------------------------------------------------------------------------
def packageJson = new groovy.json.JsonSlurper().parseText(rootProject.file('../package.json').text)
def appVersionName = packageJson.version
def (verMajor, verMinor, verPatch) = appVersionName.tokenize('.').collect { it.toInteger() }
def appVersionCode = verMajor * 10000 + verMinor * 100 + verPatch

// ---------------------------------------------------------------------------
// 서명 자격증명: 추적되지 않는 keystore.properties에서 읽습니다.
// 파일이 없으면 릴리스 빌드가 서명 없이 생성됩니다 (디버그 빌드는 영향 없음).
// ---------------------------------------------------------------------------
def keystorePropertiesFile = rootProject.file('keystore.properties')
def keystoreProperties = new Properties()
def hasSigningConfig = keystorePropertiesFile.exists()
if (hasSigningConfig) {
    keystorePropertiesFile.withInputStream { keystoreProperties.load(it) }
} else {
    logger.warn("⚠️ keystore.properties가 없어 릴리스 빌드가 서명되지 않습니다. keystore.properties.example을 참고하세요.")
}

android {
    namespace "com.marklet.md"
    compileSdk rootProject.ext.compileSdkVersion
    defaultConfig {
        applicationId "com.marklet.md"
        minSdkVersion rootProject.ext.minSdkVersion
        targetSdkVersion rootProject.ext.targetSdkVersion
        versionCode appVersionCode
        versionName appVersionName
        testInstrumentationRunner "androidx.test.runner.AndroidJUnitRunner"
        aaptOptions {
            ignoreAssetsPattern '!.svn:!.git:!.ds_store:!*.scc:.*:!CVS:!thumbs.db:!picasa.ini:!*~'
        }
    }
    signingConfigs {
        release {
            if (hasSigningConfig) {
                storeFile rootProject.file(keystoreProperties['storeFile'])
                storePassword keystoreProperties['storePassword']
                keyAlias keystoreProperties['keyAlias']
                keyPassword keystoreProperties['keyPassword']
            }
        }
    }
    buildTypes {
        release {
            if (hasSigningConfig) {
                signingConfig signingConfigs.release
            }
            minifyEnabled false
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
        debug {
            // Play 앱 서명을 사용하므로 스토어 설치본과 서명이 달라 덮어쓸 수 없습니다.
            // 패키지명을 분리해 스토어 버전을 지우지 않고 나란히 설치·테스트합니다.
            applicationIdSuffix ".debug"
            versionNameSuffix "-debug"
        }
    }
}

repositories {
    google()
    mavenCentral()
}

dependencies {
    implementation fileTree(include: ['*.jar'], dir: 'libs')
    implementation "androidx.appcompat:appcompat:$androidxAppCompatVersion"
    implementation "androidx.coordinatorlayout:coordinatorlayout:$androidxCoordinatorLayoutVersion"
    implementation "androidx.core:core-splashscreen:$coreSplashScreenVersion"
    implementation project(':capacitor-android')
    testImplementation "junit:junit:$junitVersion"
    androidTestImplementation "androidx.test.ext:junit:$androidxJunitVersion"
    androidTestImplementation "androidx.test.espresso:espresso-core:$androidxEspressoCoreVersion"
    implementation "androidx.activity:activity:$androidxActivityVersion"
    implementation project(':capacitor-cordova-android-plugins')
}

// ---------------------------------------------------------------------------
// Play Console 업로드 자동화 (Gradle Play Publisher)
//
// 서비스 계정 키(play-service-account.json)가 있을 때만 활성화됩니다.
// ---------------------------------------------------------------------------
def playCredentialsFile = rootProject.file('play-service-account.json')
if (playCredentialsFile.exists()) {
    apply plugin: 'com.github.triplet.play'

    play {
        serviceAccountCredentials.set(playCredentialsFile)
        defaultToAppBundles.set(true)
        // 기본은 내부 테스트 트랙 — 프로덕션 배포는 --track production으로 지정
        track.set('internal')
        releaseStatus.set(com.github.triplet.gradle.androidpublisher.ReleaseStatus.COMPLETED)
    }
} else {
    logger.lifecycle("ℹ️ play-service-account.json이 없어 Play 업로드 태스크가 비활성화되었습니다.")
}

apply from: 'capacitor.build.gradle'
```

**이 파일의 핵심 세 가지**

1. **버전 단일 소스화.** `package.json`의 `version`만 고치면 둘 다 따라온다.
   `versionCode = major*10000 + minor*100 + patch` → `1.0.0` = `10000`, `1.2.3` = `10203`
2. **`keystore.properties`가 없어도 빌드가 죽지 않는다.** 경고만 내고 서명 없는 AAB가 나온다.
   이게 없으면 새 PC에서 clone 직후 `gradlew`가 무조건 실패해 원인 찾는 데 시간이 든다
3. **`releaseStatus = COMPLETED`** — 업로드하는 순간 그 트랙에 **100% 즉시** 반영된다.
   그래서 서비스 계정에 프로덕션 권한을 주면 안 된다(함정 5)

## 7-5. `scripts/build-aab.cjs`

```js
#!/usr/bin/env node

/**
 * 릴리스 AAB 빌드 스크립트
 *
 * Android Studio 없이 CLI만으로 서명된 AAB를 생성합니다.
 *
 * JAVA_HOME이 Android Studio 번들 JDK(jbr)를 가리키는 경우, 스튜디오 업데이트 중에는
 * 그 경로가 사라져 gradlew 런처가 아예 뜨지 못합니다. 이를 피하기 위해 유효한 JDK를
 * 직접 찾아 자식 프로세스에만 JAVA_HOME을 지정합니다. (시스템 환경변수는 건드리지 않음)
 *
 * 사용법: npm run build:aab
 */

const { spawnSync, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');
const { assertNoDevServer } = require('./lib/assert-no-dev-server.cjs');

const repoRoot = path.resolve(__dirname, '..');
const androidDir = path.join(repoRoot, 'android');
const isWindows = process.platform === 'win32';

/** 해당 경로가 실제로 동작하는 JDK인지 확인 */
function isUsableJdk(home) {
    if (!home) return false;
    const javaBin = path.join(home, 'bin', isWindows ? 'java.exe' : 'java');
    // jvm.cfg가 없으면 런타임이 반쯤 지워진 상태(스튜디오 업데이트 중)입니다.
    const jvmCfg = path.join(home, 'lib', 'jvm.cfg');
    return fs.existsSync(javaBin) && fs.existsSync(jvmCfg);
}

/** PATH에 있는 java로부터 JDK 홈 경로를 역추적 */
function jdkFromPath() {
    try {
        const probe = isWindows ? 'where' : 'which';
        const out = execFileSync(probe, ['java'], { encoding: 'utf8' });
        const javaBin = out.split(/\r?\n/).find(Boolean);
        if (!javaBin) return null;
        // <home>/bin/java -> <home>
        return path.resolve(path.dirname(javaBin), '..');
    } catch {
        return null;
    }
}

function resolveJdk() {
    if (isUsableJdk(process.env.JAVA_HOME)) {
        return process.env.JAVA_HOME;
    }

    const fallback = jdkFromPath();
    if (isUsableJdk(fallback)) {
        console.log(`ℹ️  JAVA_HOME이 유효하지 않아 PATH의 JDK를 사용합니다: ${fallback}`);
        return fallback;
    }

    console.error('❌ 사용 가능한 JDK를 찾지 못했습니다.');
    console.error('   JAVA_HOME을 JDK 21 경로로 지정하거나, java를 PATH에 추가하세요.');
    process.exit(1);
}

function main() {
    assertNoDevServer();

    const javaHome = resolveJdk();
    const gradlew = path.join(androidDir, isWindows ? 'gradlew.bat' : 'gradlew');

    if (!fs.existsSync(gradlew)) {
        console.error('❌ gradlew를 찾을 수 없습니다:', gradlew);
        process.exit(1);
    }

    if (!fs.existsSync(path.join(androidDir, 'keystore.properties'))) {
        console.warn(
            '⚠️  keystore.properties가 없습니다. AAB가 서명되지 않아 업로드할 수 없습니다.',
        );
        console.warn('   android/keystore.properties.example을 복사해 값을 채우세요.');
    }

    console.log('🏗️  릴리스 AAB 빌드 중...');
    // Windows의 .bat는 Node 20+에서 shell 없이는 실행되지 않으므로 shell 경유로 실행합니다.
    // 경로에 공백이 있을 수 있어 실행 파일은 따옴표로 감쌉니다.
    const result = spawnSync(`"${gradlew}"`, [':app:bundleRelease'], {
        cwd: androidDir,
        env: { ...process.env, JAVA_HOME: javaHome },
        stdio: 'inherit',
        shell: true,
    });

    if (result.error) {
        console.error('❌ gradlew 실행 실패:', result.error.message);
        process.exit(1);
    }

    if (result.status !== 0) {
        process.exit(result.status ?? 1);
    }

    const aab = path.join(
        androidDir,
        'app',
        'build',
        'outputs',
        'bundle',
        'release',
        'app-release.aab',
    );

    if (!fs.existsSync(aab)) {
        console.error('❌ 빌드는 끝났지만 AAB를 찾을 수 없습니다:', aab);
        process.exit(1);
    }

    const version = require(path.join(repoRoot, 'package.json')).version;
    const sizeMb = (fs.statSync(aab).size / 1024 / 1024).toFixed(1);

    console.log('');
    console.log(`✅ 빌드 완료 — v${version} (${sizeMb} MB)`);
    console.log(`   ${aab}`);
}

main();
```

이 스크립트에 들어간 판단 네 가지:

1. **`isUsableJdk`가 `bin/java`만이 아니라 `lib/jvm.cfg`도 본다** — 함정 1
2. **`JAVA_HOME`을 자식 프로세스에만 준다.** 시스템 환경변수를 바꾸면 Android Studio가 깨진다
3. **`shell: true` + 실행 파일 따옴표** — 함정 9
4. **빌드 성공 후 AAB 존재를 다시 확인한다.** gradle이 exit 0으로 끝나고도 산출물이 없는 경우가 있다

## 7-6. `scripts/publish.cjs`

```js
#!/usr/bin/env node

/**
 * Play Console 업로드 스크립트
 *
 * 서명된 AAB를 빌드해 지정한 트랙에 업로드합니다.
 * Gradle Play Publisher(GPP)를 사용하며, 서비스 계정 키가 있어야 동작합니다.
 *
 * 사용법:
 *   node scripts/publish.cjs internal      # 내부 테스트 트랙
 *   node scripts/publish.cjs production    # 프로덕션 (서비스 계정에 권한을 주지 않았으므로 실패한다)
 */

const { spawnSync, execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');
const readline = require('readline');
const { assertNoDevServer } = require('./lib/assert-no-dev-server.cjs');

const repoRoot = path.resolve(__dirname, '..');
const androidDir = path.join(repoRoot, 'android');
const credentialsPath = path.join(androidDir, 'play-service-account.json');
const isWindows = process.platform === 'win32';

const VALID_TRACKS = ['internal', 'alpha', 'beta', 'production'];

function isUsableJdk(home) {
    if (!home) return false;
    const javaBin = path.join(home, 'bin', isWindows ? 'java.exe' : 'java');
    const jvmCfg = path.join(home, 'lib', 'jvm.cfg');
    return fs.existsSync(javaBin) && fs.existsSync(jvmCfg);
}

function jdkFromPath() {
    try {
        const probe = isWindows ? 'where' : 'which';

            .split(/\r?\n/)
            .find(Boolean);
        return javaBin ? path.resolve(path.dirname(javaBin), '..') : null;
    } catch {
        return null;
    }
}

function resolveJdk() {
    if (isUsableJdk(process.env.JAVA_HOME)) return process.env.JAVA_HOME;

    const fallback = jdkFromPath();
    if (isUsableJdk(fallback)) {
        console.log(`ℹ️  JAVA_HOME이 유효하지 않아 PATH의 JDK를 사용합니다: ${fallback}`);

}

/** 프로덕션 배포 전 확인 (되돌리기 어려운 작업) */
function confirmProduction(version) {
    return new Promise((resolve) => {
        const rl = readline.createInterface({ input: process.stdin, output: process.stdout });

                rl.close();
                resolve(answer.trim().toLowerCase() === 'yes');
            },
        );
    });
}

    assertNoDevServer();

    const track = process.argv[2];

    if (!VALID_TRACKS.includes(track)) {
        console.error(`❌ 트랙을 지정하세요. 사용 가능: ${VALID_TRACKS.join(', ')}`);
```

## 7-7. `scripts/play-status.cjs` — 콘솔을 열지 않고 트랙 상태 보기

`gradlew`를 거치지 않고 Android Publisher API를 직접 호출한다. Node 내장 `crypto`로 JWT를
만들어 OAuth 토큰을 받으므로 **의존성이 하나도 없다.**

```js
#!/usr/bin/env node

/**
 * Play Console 트랙 상태 조회
 *
 * 업로드한 버전이 각 트랙에서 실제로 어떤 상태인지 확인합니다.
 * (검토 중인지, 배포됐는지, 어떤 버전이 활성인지)
 *
 * 사용법: npm run play:status
 */

const crypto = require('crypto');
const fs = require('fs');
const path = require('path');

const repoRoot = path.resolve(__dirname, '..');
const credentialsPath = path.join(repoRoot, 'android', 'play-service-account.json');
const PACKAGE_NAME = 'com.marklet.md';
const SCOPE = 'https://www.googleapis.com/auth/androidpublisher';
const API = 'https://androidpublisher.googleapis.com/androidpublisher/v3';

function base64url(input) {
    return Buffer.from(input).toString('base64url');
}

/** 서비스 계정 키로 OAuth 액세스 토큰 발급 */
async function getAccessToken(credentials) {
    const now = Math.floor(Date.now() / 1000);
    const header = base64url(JSON.stringify({ alg: 'RS256', typ: 'JWT' }));
    const claims = base64url(
        JSON.stringify({
            iss: credentials.client_email,
            scope: SCOPE,
            aud: 'https://oauth2.googleapis.com/token',
            exp: now + 3600,
            iat: now,
        }),
    );

    const signature = crypto
        .createSign('RSA-SHA256')
        .update(`${header}.${claims}`)
        .sign(credentials.private_key)
        .toString('base64url');

    const res = await fetch('https://oauth2.googleapis.com/token', {
        method: 'POST',
        headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
        body: new URLSearchParams({
            grant_type: 'urn:ietf:params:oauth:grant-type:jwt-bearer',
            assertion: `${header}.${claims}.${signature}`,
        }),
    });

    const body = await res.json();
    if (!res.ok) throw new Error(`토큰 발급 실패: ${JSON.stringify(body)}`);
    return body.access_token;
}

async function api(token, urlPath, options = {}) {
    const res = await fetch(`${API}${urlPath}`, {
        ...options,
        headers: { Authorization: `Bearer ${token}`, ...(options.headers ?? {}) },
    });
    const text = await res.text();
    const body = text ? JSON.parse(text) : {};
    if (!res.ok) throw new Error(`${urlPath} → ${res.status}: ${JSON.stringify(body)}`);
    return body;
}

async function main() {
    if (!fs.existsSync(credentialsPath)) {
        console.error('❌ 서비스 계정 키가 없습니다:', credentialsPath);
        process.exit(1);
    }

    const credentials = JSON.parse(fs.readFileSync(credentialsPath, 'utf8'));
    const token = await getAccessToken(credentials);

    // 트랙 조회는 edit 컨텍스트가 필요합니다. 조회만 하고 바로 폐기합니다.
    const edit = await api(token, `/applications/${PACKAGE_NAME}/edits`, { method: 'POST' });

    try {
        const { tracks = [] } = await api(
            token,
            `/applications/${PACKAGE_NAME}/edits/${edit.id}/tracks`,
        );

        console.log(`📦 ${PACKAGE_NAME}\n`);

        if (process.argv.includes('--raw')) {
            const internal = tracks.find((t) => t.track === 'internal');
            console.log(JSON.stringify(internal ?? tracks, null, 2));
            return;
        }

        for (const track of tracks) {
            console.log(`━━ ${track.track} ━━`);

            if (!track.releases?.length) {
                console.log('   (출시 없음)\n');
                continue;
            }

            for (const release of track.releases) {
                console.log(`   상태       : ${release.status}`);
                console.log(`   버전 코드  : ${(release.versionCodes ?? ['-']).join(', ')}`);
                if (release.name) console.log(`   출시 이름  : ${release.name}`);
                if (release.userFraction !== undefined) {
                    console.log(`   배포 비율  : ${release.userFraction * 100}%`);
                }
                console.log('');
            }
        }
    } finally {
        // 조회용 edit이 남지 않도록 정리
        await api(token, `/applications/${PACKAGE_NAME}/edits/${edit.id}`, {
            method: 'DELETE',
        }).catch(() => {});
    }
}

main().catch((e) => {
    console.error('❌', e.message);
    process.exit(1);
});
```

**`finally`에서 edit을 지우는 것이 중요하다.** Android Publisher API의 edit은 세션 같은 것이라
만들고 안 지우면 콘솔에 "검토 중인 변경사항"으로 남아 **다음 업로드를 막는다.**

## 7-9. 해마다 돌아오는 일 — `targetSdk` 상향

**구글이 강제하는 것은 `minSdk` 가 아니라 `targetSdk` 다.** 이 구분을 놓치면 엉뚱한 데를 손보게 된다.

| | 강제 여부 | 어기면 |
|---|---|---|
| `targetSdk` | **강제한다.** 매년 상향된다 | 기한이 지나면 **그 앱의 업데이트를 더 이상 게시할 수 없다.** 이미 나간 버전은 계속 배포되지만 고칠 방법이 없어진다 |
| `minSdk` | 강제하지 않는다 | 낮게 두어도 불이익 없다. 다만 낡은 기기를 실제로 검증해야 한다(`01_제품_결정서.md` 11.3절) |

**할 일 — 1년에 한 번, 새 안드로이드 정식판이 나온 뒤:**

1. **기한을 확인한다.** Play Console → 정책 → 프로그램 공지에 그 해의 마감일이 뜬다.
   ★ 이 문서에 날짜를 적어 두지 않는 것은 일부러다 — 적어 두면 그 값이 **조용히 낡아** 거짓말을 시작한다.
2. `android/variables.gradle` 의 `compileSdkVersion` · `targetSdkVersion` 을 새 값으로 올린다.
3. **동작 변경 목록을 읽는다.** targetSdk 를 올리는 순간 그 판의 동작 변경이 전부 적용된다.
   이 앱에서 특히 걸릴 만한 것: SAF·저장소 접근, 포그라운드/백그라운드 제약, 알림 권한.
4. **실기기로 확인한다.** 최소한 파일 열기(SAF) · 저장 · 공유 세 갈래는 손으로 눌러 본다.
   여기서 깨지면 게시가 막힌 채로 고치게 되므로 **기한 직전에 하지 마라.**
5. 새 버전으로 internal → alpha 순서로 올린다(7-8절).

> **왜 이 절이 뒤늦게 생겼나.** 2026-08-31에 "구글이 구버전 지원을 줄이는 것 같은데 어떻게 대비하나"를
> 따져 보다가, **이 문서 어디에도 "매년 올려야 한다"가 적혀 있지 않다**는 것을 발견했다.
> 지금은 `targetSdk 36` 이라 여유가 있지만, 그 여유가 이 일을 잊게 만든다.

## 함정 1. Android Studio 번들 JBR이 깨져 gradle이 조용히 실패한다 — 하루 지난 APK를 테스트했다

**증상.** `gradlew`를 돌렸는데 아무 일도 안 일어나거나 알 수 없는 오류로 끝난다.
그런데 **기기에는 앱이 설치돼 있다.** 그래서 "빌드는 됐구나" 하고 테스트를 계속한다.
실제로 설치돼 있던 것은 **하루 전에 만든 APK**였다. 고친 내용이 하나도 반영되지 않은 상태로
몇 시간을 검증했다.

**원인.** `JAVA_HOME`이 Android Studio 번들 JDK(JetBrains Runtime, `jbr`)를 가리키고 있고,
스튜디오가 업데이트되는 동안 그 디렉터리 내용물이 반쯤 지워진다.
**`bin/java.exe`는 남아 있는데 `lib/jvm.cfg`가 없는 상태**가 된다.
런처 파일은 존재하지만 JVM이 뜨지 못한다.

**이 PC에서 지금도 재현되는 상태다.** 2026-07-31 확인:

```bash
$ echo "$JAVA_HOME"
C:\Program Files\Android\Android Studio\jbr

$ ls "/c/Program Files/Android/Android Studio/jbr/bin/java.exe"
/c/Program Files/Android/Android Studio/jbr/bin/java.exe     ← 있다

$ ls "/c/Program Files/Android/Android Studio/jbr/lib/jvm.cfg"
ls: cannot access '...': No such file or directory           ← 없다
```

**해결.** `bin/java` 존재만으로 판단하면 안 된다. `lib/jvm.cfg`까지 확인한다.
그것이 `build-aab.cjs`의 `isUsableJdk()`이고(7-5절), 유효하지 않으면 PATH의 `java`에서
홈을 역추적해 **자식 프로세스에만** `JAVA_HOME`을 넘긴다.

### `org.gradle.java.home`만으로는 왜 부족한가

`gradle.properties`의 `org.gradle.java.home`은 **Gradle 데몬이 어느 JDK로 빌드를 수행할지**를
정하는 값이다. 그런데 **그 값을 읽으려면 먼저 Gradle 런처 JVM이 떠야 한다.**
런처를 띄우는 것은 `gradlew.bat` 스크립트이고, 그 스크립트는 `JAVA_HOME` → PATH의 `java`
순서로 실행 파일을 찾는다.

**즉 `JAVA_HOME`이 깨져 있으면 `gradle.properties`를 읽기도 전에 죽는다.**
`org.gradle.java.home`은 이 문제를 절대 고칠 수 없다.
게다가 `gradle.properties`에 절대 경로를 박으면 다른 PC에서 clone했을 때 그대로 깨진다.

**→ JDK 경로는 파일에 적지 말고 실행 시점에 찾아라.**

### 추가로 확인할 것 — 폴백이 JDK 8을 집을 수 있다

이 PC의 `where java` 결과:

```
C:\Program Files\Eclipse Adoptium\jdk-21.0.9.10-hotspot\bin\java.exe
C:\Program Files\Eclipse Foundation\jdk-8.0.302.8-hotspot\bin\java.exe
```

**JDK 8이 PATH 두 번째에 있다.** 순서가 뒤바뀌면 폴백이 JDK 8을 집어서 AGP 8.13이
`Unsupported class file major version`으로 죽는다. 폴백을 믿기 전에 한 번은
`java -version`으로 21이 나오는지 봐라.

> **확인하지 못한 것:** "하루 지난 APK를 테스트했다"는 구체적 정황은 사장님이 알려 준 내용이고,
> 저장소의 git log와 `.docs/` 전체를 검색했으나 그 사건의 기록은 찾지 못했다.
> 저장소에서 확인된 것은 `build-aab.cjs`의 주석, `isUsableJdk`가 `jvm.cfg`를 검사한다는 사실,
> 그리고 **지금 이 PC의 `JAVA_HOME`이 실제로 깨져 있다는 것**이다.
> `org.gradle.java.home`을 시도했다 실패한 기록도 없다 — 위 설명은 Gradle 실행 구조에 근거한 것이다.

## 함정 4. 디버그 빌드 패키지명을 분리하지 않으면 스토어 설치본을 지워야 한다

```groovy
debug {
    applicationIdSuffix ".debug"
    versionNameSuffix "-debug"
}
```

**왜 필요한가.** Play 앱 서명을 쓰면 사용자가 받는 앱은 **Google의 키로** 서명된다.
로컬 디버그 빌드는 안드로이드 디버그 키로 서명된다. 패키지명이 같고 서명이 다르면
`adb install -r`이 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`로 거부한다.
설치하려면 스토어 버전을 **지워야** 하고, 그러면 그 앱의 로컬 데이터도 같이 날아간다.

**따라오는 함정 세 개.**

1. **`am start`의 컴포넌트 이름.** `applicationIdSuffix`는 자바 패키지를 바꾸지 않는다.
   ```bash
   # 맞다
   adb shell am start -n com.marklet.md.debug/com.marklet.md.MainActivity
   # 틀리다 — Activity class does not exist
   adb shell am start -n com.marklet.md.debug/com.marklet.md.debug.MainActivity
   ```
2. **logcat이 어느 쪽을 볼지 정해야 한다.** `['com.marklet.md.debug', 'com.marklet.md']`
   순서로 `pidof`를 돌려 실행 중인 쪽을 찾는다
3. **인앱결제는 `.debug` 빌드에서 동작하지 않는다.** Play가 설치한 앱이 아니기 때문이다

## 함정 5. 서비스 계정에 일부러 프로덕션 권한을 주지 않는다

**권한을 주면 스크립트 한 줄로 전 세계 사용자에게 배포가 나간다.**
`node scripts/publish.cjs production`은 프로덕션 트랙에 즉시 올리고, GPP 설정이
`releaseStatus = COMPLETED`라 **단계적 출시도 아니고 100% 즉시 공개다.**

`publish.cjs`에 `yes` 확인이 있지만 **그건 사람이 실수로 엔터를 누르는 것만 막는다.**
에이전트가 자동으로 돌리는 경우, 또는 다른 트랙을 올리려다 인자를 틀리는 경우는 못 막는다.

그래서 서비스 계정에는 **내부·비공개 테스트 트랙 권한만** 준다(1-7절).
프로덕션 승격은 Play Console에서 사람이 직접 한다. "내부 테스트에서 확인된 빌드를
프로덕션으로 승격" 버튼 한 번이라 번거롭지도 않다.

**이 조합이 만드는 성질이 좋다: 자동화는 되돌릴 수 있는 곳까지만 하고, 되돌릴 수 없는 곳에는
사람의 손을 한 번 넣는다.**

## 함정 6. 버전 번호를 두 곳에 적으면 반드시 어긋난다

픽셀오아시스 초기에는 `package.json`의 `version`과 `build.gradle`의 값을 손으로 맞췄다.
커밋 `a2459aa`의 제목이 그냥 **"feat: 버전일치"** 다. 맞추는 작업 자체가 커밋이 될 만큼
자주 어긋났다는 뜻이다.

지금은 `build.gradle`이 `package.json`을 읽는다(7-2절). 주의할 점:

- **minor·patch가 99를 넘으면 안 된다.** `1.0.100` → `10100` = `1.1.0`과 충돌한다
- **같은 versionCode는 Play에 두 번 올릴 수 없다.** 업로드에 실패해 다시 올릴 때도 patch를
  올려야 한다. "빌드만 다시 했는데 왜 거부되지"의 답이 이것이다
- 버전 문자열이 `1.0`처럼 두 자리면 `tokenize('.')` 결과가 2개라 구조분해에서 실패한다.
  **항상 세 자리로 쓴다**

## 함정 7. 심사 대기가 개발 속도를 앞지른다 — 버전업 단위를 크게 묶어라

**사장님이 픽셀오아시스에서 내린 판단이다. 새 앱에도 그대로 적용한다.**

고친 것 하나마다 프로덕션에 올리면, 다음 수정이 끝날 때쯤 앞의 심사가 아직 안 끝나 있다.
그러면 개발은 대기열 관리가 되고, 심사 중인 버전과 로컬 버전이 어긋나 무엇이 사용자에게
나가 있는지 헷갈리게 된다.

**규칙:**

| 트랙 | 무엇을 올리나 | 얼마나 자주 |
|---|---|---|
| `internal` | 뭐든지. 실기기 확인용 | 하루에 몇 번이든 |
| `production` | **여러 수정을 묶은 의미 있는 단위** | 최소 1~2주 간격 |

그리고 **버전 번호 규칙:**

- internal에 올릴 때마다 `patch`를 올린다 (같은 versionCode 재업로드 불가 — 함정 6)
- **프로덕션에 나가는 것은 `minor`를 올린다** (`1.0.x` → `1.1.0`)
- **patch는 99가 상한이다**(함정 6). patch만 계속 올리면 `1.0.99` 다음이 없다.
  프로덕션 단위로 minor를 올리는 규칙이 이 상한도 같이 해결한다

**근거의 한계를 밝힌다.** 저장소에 남은 심사 시간 기록은 서로 다르다 —
`.docs/PLAYSTORE_GUIDE.md`는 "심사는 보통 3~7일", `.docs/앱스토어_출시_가이드.md`는 "1~3일"이다.
**Google 공식 문서에서 트랙별 심사 시간을 명시한 페이지는 이번에 찾지 못했다.**
확실한 것은 픽셀오아시스가 v1.0.37까지 갔다는 사실뿐이고, 묶어서 올리라는 판단은 사장님의 경험이다.

**하나 더 — "게시 관리(Managed publishing)"를 켜라.** Google 문서에서 확인한 기능이다:
변경사항을 "저장"해 검토만 받아 두고, **게시 시점은 사람이 고른다.**
여러 변경(등재 문구 + 새 버전 + 데이터 안전)을 각각 검토받은 뒤 **한 번에** 내보낼 수 있다.
위치: Play Console → **게시 개요 → 게시 관리 설정 → 사용**.

## 함정 11. `npx cap run android -l`은 Windows에서 동작하지 않는다

커밋 `dbf19ef` 메시지 원문:

> `npx cap run android -l` 은 Windows에서 동작하지 않는다. Capacitor CLI가 자체 프로세스로
> `'./gradlew'`를 실행하는데 cmd.exe가 이 경로 형식과 확장자 없는 셸 스크립트를 처리하지
> 못한다. 또한 cap run은 개발 서버를 직접 띄우지 않고, host 기본값이 LAN IP라 localhost
> 바인딩인 Vite에 기기가 접근할 수 없다.

**시간을 아끼려고 `cap run -l`부터 시도하지 마라. 안 된다.** `dev-device.cjs`가 `gradlew.bat`과
`adb`로 같은 일을 직접 한다.

## 함정 12. Node 20+ 에서 `.bat`/`.cmd`는 `shell: true` 없이 실행되지 않는다

```js
spawnSync(`"${gradlew}"`, [':app:bundleRelease'], { shell: true });  // ← 없으면 EINVAL
```

Node 20의 보안 수정(CVE-2024-27980) 때문이다. 그리고 `shell: true`를 쓰면 경로가 셸에 문자열로
들어가므로 `C:\Program Files\...` 같은 공백 경로를 **따옴표로 감싸야 한다.** 두 가지를 함께 해야 동작한다.

## 함정 13. 저장소 경로에 한글이 있으면 AGP가 빌드를 거부한다

```properties
# android/gradle.properties
android.overridePathCheck=true
```

`D:\dev\코드프로젝트\...` 처럼 경로에 non-ASCII가 있으면 AGP가 검사에서 막는다.
이 한 줄이 없으면 `Your project path contains non-ASCII characters`로 즉시 실패한다.

## 함정 14. `cap sync`가 만드는 파일을 손으로 고치면 다음 sync에 사라진다

매번 재생성되는 파일: `android/app/capacitor.build.gradle`, `android/capacitor.settings.gradle`,
`android/app/src/main/assets/capacitor.config.json`, `.../capacitor.plugins.json`,
`android/capacitor-cordova-android-plugins/**`.

앞의 둘은 `// DO NOT EDIT THIS FILE!` 주석이 붙어 있다.
설정을 바꾸려면 **저장소 루트의 `capacitor.config.json`을 고치고 sync해라.**
어쩔 수 없이 생성 파일을 건드려야 하면 **sync 뒤에 자동으로 다시 적용되는 후처리 스크립트**로 만들어라
(`remove-flatdir.cjs`가 그 예다).

## 함정 15. 릴리스 빌드에서는 웹 로그가 보이지 않는다

두 겹으로 막혀 있다.

1. `vite.config.ts`의 `esbuild.drop: ['console','debugger']`가 릴리스에서 console 호출을 지운다
2. Capacitor의 `loggingBehavior` 기본값이 `debug`라 릴리스에서는 웹 로그를 네이티브로 넘기지 않는다

**그래서 릴리스 빌드에서 "왜 안 되는지"를 로그로 알 수 없다.** 픽셀오아시스는 이것 때문에
사용자에게 보이는 실패를 여러 번 놓쳤다:

- `e178e64`: "저장이 실패해도 console.error만 남는데 프로덕션은 console을 제거한다.
  사용자는 앱을 껐다 켠 뒤에야 작업이 사라진 것을 안다" → Toast로 알리도록 고침
- `c956025`: DB 읽기 오류가 조용히 넘어가 저장된 작업을 덮어썼다
- `f7fb980`: BGM 로드 실패가 조용히 무음이 되어 원인을 알 수 없었다

**규칙: 사용자가 알아야 하는 실패는 console이 아니라 화면에 띄워라.**
마크다운 뷰어에서 해당하는 것 — **파일 열기 실패, 인코딩 판별 실패, 저장 실패, 용량이 커서
렌더링을 포기한 경우.** 이 앱의 차별점 3번("파일을 절대 잃지 않는다")이 통째로 여기에 달려 있다.

## 함정 16. 백그라운드 전환 시 디바운스된 저장을 flush하지 않으면 데이터가 사라진다

커밋 `be7e44f`. 사용자가 직접 보고한 문제였다. `saveProgress()`가 1초 디바운스인데 백그라운드
전환 시 flush하지 않아, 프로세스가 회수되면 그 1초 안의 변경이 사라졌다.

```ts
document.addEventListener('visibilitychange', () => {
    if (document.visibilityState === 'hidden') flushPendingSave();
});
```

**편집 기능이 있는 앱에서 이건 더 치명적이다.** 편집 중에 홈키를 누르면 사용자 문서가 날아간다.
`beforeunload`는 안드로이드 WebView에서 믿을 수 없다.
같은 계열로 커밋 `a811c3f`: `destroy()`에서 리스너 해제를 빼먹어 누수가 있었다.
**붙였으면 떼는 것도 같이 써라.**

## 함정 17. 앱 용량 — 에셋이 AAB의 대부분을 차지한다

커밋 `f7fb980`: **BGM이 AAB의 68%(108.5MB)** 였다. Opus 64k로 바꿔 167MB → 88.6MB.

마크다운 뷰어에 오디오는 없지만 같은 함정이 **폰트**에 있다.
**결정: 웹폰트를 번들하지 말고 안드로이드 시스템 폰트를 쓴다.**
(형제 문서 `05_조사_렌더링스택.md`에서 Pretendard Regular 하나가 748KB로 실측되었다 —
JS 스택 전체의 4배가 넘는다.)
픽셀오아시스는 Google Fonts를 `<link>`로 불러왔는데 **그건 오프라인에서 깨진다.**

## 함정 18. 미디어쿼리 `orientation: landscape`는 키보드가 올라와도 참이 된다

커밋 `30f0c2e`. 실기기 보고: "글자 입력 중일 때 이미지가 좌측 정렬되어 보인다".
`orientation: landscape`는 **뷰포트 높이가 폭보다 작으면 참**이라, 세로로 든 기기에서
소프트 키보드가 올라와도 매칭된다. 375×340에서 실제로 true였다.

```css
/* 틀리다 */ @media (orientation: landscape) { ... }
/* 맞다   */ @media (min-width: 600px) { ... }
```

**편집 기능이 있으므로 이 함정을 반드시 만난다.**

## 함정 19. 한글 IME + `maxlength`는 마지막 글자를 덮어쓴다

커밋 `30020cb`. 조합 중인 글자도 value 길이에 포함되므로, 한도에 닿으면 브라우저가 새 입력을
거부하고 조합이 진행되지 못한다. 그래서 자모를 눌러도 새 글자가 되지 않고 **마지막 글자만 계속 바뀌었다.**

**해결: `maxlength`를 쓰지 말고 `compositionstart`/`compositionend`를 추적해 조합이 끝난 뒤에만 자른다.**

같은 커밋에서 나온 것 둘:
- `enterkeyhint="done"`은 **키 모양만 바꾸고 동작은 없다.** Enter를 받아 직접 `blur()`해라.
  **단, 조합 중인 Enter는 가로채면 안 된다** (한글 확정용 Enter까지 먹으면 글자가 씹힌다)
- **`<input>`은 부모의 `text-align`을 상속하지 않는다**

## 함정 20. 키보드가 올라오면 입력칸이 화면 밖으로 나간다

커밋 `853ad93`. 포커스 시 `scrollIntoView`로 올리되 **포커스 직후가 아니라 `visualViewport`의
`resize`를 기다린 뒤에** 옮긴다. 그리고 컨테이너의 `overflow`를 `hidden`에서 `auto`로 바꾼다 —
**스크롤될 여지가 없으면 `scrollIntoView`가 아무것도 하지 않는다.** 둘 다 해야 고쳐진다.

## 함정 21. 여닫기 타이머가 겹치면 UI가 사라지고 뒤로가기를 먹는다

커밋 `13195dc`. 열기는 10ms 뒤 `.visible`, 닫기는 300ms 뒤 `display:none`. 그 사이에 반대
동작이 들어오면 뒤늦게 터진 타이머가 새 상태를 덮어썼다. 결과: **화면에는 아무것도 없는데
`isOpen`은 true라 안드로이드 뒤로가기를 한 번 잡아먹었다.**

**모달별로 걸린 타이머를 들고 있다가 반대 동작에서 취소한다.**
목차 서랍·검색 패널·설정 시트가 전부 이 구조다. 처음부터 이렇게 만들어라.

## 함정 22. Tailwind의 `.hidden`이 컴포넌트 클래스에 진다

커밋 `3370254`. **6개 클래스 중 5개가 이 상태였다.** `.hidden{display:none}`이 먼저 놓이고
뒤의 컴포넌트 클래스가 `display`를 지정하면, 같은 명시도에서 **나중에 선언된 쪽이 이긴다.**
증상은 "숨겼는데 화면에 보이고, 눌러도 반응이 없다".

해결 두 가지를 **같이** 해야 한다:
1. `utilities.css`에 `.hidden`을 넣고 **CSS import 중 가장 마지막에** 불러온다
2. **`.hidden`을 페이드 용도로 쓰지 마라.** 페이드는 `.is-leaving` 같은 다른 이름으로 분리한다

그리고 **import 순서를 검사하는 테스트**를 넣었다. 브라우저 없이 판정된다.

## 함정 23. 존재하지 않는 전역을 검사하는 조건은 영원히 거짓이다

커밋 `82f814a`. 토스트 아이콘이 **한 번도** 렌더링되지 않았다. `window.lucide`를 확인했는데
그 값은 코드 어디에서도 할당되지 않았다(ES 모듈로 import해 쓰기 때문).
**그리고 테스트가 `window.lucide`를 목으로 채워 넣어 이 결함을 가리고 있었다.**

같은 커밋에서: **lucide는 `<i>`를 `<svg>`로 `replaceChild`한다.** `.foo i { }` 셀렉터는 죽는다.

# 10. 검증 절차 — adb로 확인하는 실제 명령

화면을 보지 못하는 에이전트도 앱을 조작하고 결과를 확인할 수 있다.

## 10-1. 준비

```bash
# SDK 경로 (Windows 기본)
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"
EMU="$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe"

# 기기 목록
adb devices
```

출력 예:

```
List of devices attached
emulator-5554	device
R3CT10ABCDE	device
```

**실기기와 에뮬레이터가 동시에 붙어 있으면 `adb`가 어느 쪽인지 모른다.**
이후 모든 명령에 `-s <시리얼>`을 붙여라. 안 붙이면 `more than one device`로 실패하거나,
**더 나쁘게는 엉뚱한 기기에서 실행된다.**

에뮬레이터 부팅 완료를 기다리는 확실한 방법:

```bash
adb -s emulator-5554 wait-for-device shell 'while [[ -z $(getprop sys.boot_completed) ]]; do sleep 1; done'
```

## 10-2. 설치·실행·초기화

```bash
# 디버그 APK 설치 (패키지가 .debug라 스토어 본앱과 충돌하지 않는다)
adb -s emulator-5554 install -r android/app/build/outputs/apk/debug/app-debug.apk

# 실행 — 앞은 applicationId(suffix 포함), 뒤는 자바 클래스의 실제 패키지
adb -s emulator-5554 shell am start -n com.marklet.md.debug/com.marklet.md.MainActivity

# 강제 종료 (재시작 검증용)
adb -s emulator-5554 shell am force-stop com.marklet.md.debug

# 데이터 초기화 (첫 실행 상태 재현)
adb -s emulator-5554 shell pm clear com.marklet.md.debug
```

## 10-3. 이 앱에 특히 필요한 검증 — 파일 열기·저장

```bash
# 1) 테스트 문서 준비 (Mermaid·표·수식·각주·한글 개행이 전부 든 파일)
adb -s emulator-5554 push test/fixtures/kitchen-sink.md /sdcard/Download/test.md

# 2) 미디어 스캐너에 알린다 (안 하면 파일 관리자 목록에 안 뜬다)
adb -s emulator-5554 shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Download/test.md

# 3) VIEW 인텐트를 직접 쏘아 인텐트 처리 코드만 확인한다
adb -s emulator-5554 shell am start -a android.intent.action.VIEW \
  -d file:///sdcard/Download/test.md -t text/markdown \
  -n com.marklet.md.debug/com.marklet.md.MainActivity

# 4) MIME을 바꿔 가며 반복한다 — .md의 MIME은 앱마다 다르다
#    text/plain / application/octet-stream / 빈 값
adb -s emulator-5554 shell am start -a android.intent.action.VIEW \
  -d file:///sdcard/Download/test.md -t text/plain \
  -n com.marklet.md.debug/com.marklet.md.MainActivity

# 5) 저장 검증 — 앱에서 내용을 지우고 저장한 뒤 파일을 꺼내 본다
adb -s emulator-5554 pull /sdcard/Download/test.md ./after-save.md
#    파일 끝에 옛 내용이 남아 있으면 truncate가 안 된 것이다

# 6) 어떤 MIME이 왔는지 로그로 확인
#    ★ 삼성 기기는 ActivityTaskManager / am_intent 로그가 꺼져 있다. events 버퍼를 봐라.
#      형식: [user,id,uid,컴포넌트,action,MIME,URI,...]
#    "$ADB" -s $S logcat -b all -c        ← 누르기 전에 비우고
#    "$ADB" -s $S logcat -d -b events | grep wm_create_activity | grep -E "action\.(VIEW|SEND)"
#
# 6-1) 앱이 어떤 MIME을 받았는지 우리 플러그인 로그로 확인
adb -s emulator-5554 logcat -c
#    (파일을 연 뒤)
adb -s emulator-5554 logcat -d -v brief | grep -i "intent\|mime\|MdFile"
```

## 10-4. 앱이 살아 있는지 / 지금 어느 화면인지

```bash
adb -s emulator-5554 shell dumpsys activity activities | grep topResumedActivity
```

출력 예:

```
topResumedActivity=ActivityRecord{a1b2c3 u0 com.marklet.md.debug/com.marklet.md.MainActivity t42}
```

**이게 왜 중요한가.** 앱이 크래시하면 액티비티가 사라지는데, 화면을 못 보는 에이전트는
"탭이 안 먹었나?" 하고 같은 조작을 반복하게 된다. 조작 전후로 한 번씩 확인하면 크래시를 즉시 안다.

살아 있는지만 보려면:

```bash
adb -s emulator-5554 shell pidof -s com.marklet.md.debug
```

PID가 안 나오면 죽은 것이다.

## 10-5. 화면 조작

```bash
adb -s emulator-5554 shell wm size                                   # 화면 크기 확인
adb -s emulator-5554 shell input tap 540 1200                        # 탭
adb -s emulator-5554 shell input swipe 540 1600 540 600 300          # 위로 스크롤
adb -s emulator-5554 shell input swipe 900 1200 200 1200 300         # 표 가로 스크롤 검증
adb -s emulator-5554 shell input swipe 540 1200 540 1200 800         # 길게 누르기
adb -s emulator-5554 shell input text "hello%sworld"                 # 텍스트 (공백은 %s)
adb -s emulator-5554 shell input keyevent KEYCODE_BACK               # 뒤로가기
adb -s emulator-5554 shell input keyevent KEYCODE_HOME               # 홈
adb -s emulator-5554 shell input keyevent KEYCODE_APP_SWITCH         # 최근 앱
```

**`input text`로 한글은 입력되지 않는다.** adb는 ASCII 키 이벤트만 보낸다.
**함정 19(한글 IME)는 adb로 재현할 수 없다. 실기기에서 손으로 쳐야 한다.**

## 10-6. 회전 — 두 방법의 동작이 다르다

```bash
# (1) 설정으로 강제 고정 — 안정적이다. 스크린샷 찍을 때 이걸 써라
adb -s emulator-5554 shell settings put system accelerometer_rotation 0
adb -s emulator-5554 shell settings put system user_rotation 1
#   0=세로, 1=가로(왼쪽), 2=거꾸로 세로, 3=가로(오른쪽)
adb -s emulator-5554 shell settings put system accelerometer_rotation 1   # 되돌리기

# (2) 에뮬레이터 콘솔로 물리 회전 흉내 — 센서 이벤트가 실제로 발생한다
adb -s emulator-5554 emu rotate
```

**`orientationchange` 이벤트나 `screen.orientation` API를 검증하려면 `emu rotate`를 써야 한다.**
`settings put`은 그 경로를 타지 않는 경우가 있다.
회전 후 레이아웃이 자리 잡을 시간을 줘라(0.5~1초). 바로 찍으면 전환 중간 프레임이 잡힌다.

> `emu rotate`를 픽셀오아시스에서 실제로 썼다는 기록은 없다. 저장소에서 확인된 방법은
> `settings put system user_rotation` 뿐이다.
