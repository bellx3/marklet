# Marklet

마크다운 뷰어. AI 가 만들어 준 `.md` 를 **받은 그대로** 열어 읽는 것이 목표다.
문서는 기기를 벗어나지 않는다 — 광고도 계정도 없다.

| 플랫폼      | 상태                                                  |
| ----------- | ----------------------------------------------------- |
| **Windows** | 진행 중. 설치형 배포는 [Releases](../../releases)     |
| Android     | **보류.** 필요해지면 재개한다 ([아래](#android-보류)) |

## Windows

`.md` 를 더블클릭하면 그 문서만 보이는 창이 뜬다. 사진 뷰어처럼 화면에는 문서밖에 없다.

- 표 · Mermaid 다이어그램 · 수식(KaTeX) · 각주 · 체크박스 · 코드 하이라이트
- 문서와 같은 폴더의 그림(`![](img/a.png)`)과 다른 문서 링크(`[x](other.md)`)가 그대로 동작한다
- **편집** (`Ctrl+E`): 글자만 있는 편집기로 바뀐다. `Ctrl+S` 로 저장하고, 다시 `Ctrl+E` 를 누르면 고친 글이 미리보기로 그려진다
- `.txt` 도 연다. 서식 없이 글자 그대로 보여 주고, `Ctrl+U` 로 마크다운처럼 볼 수도 있다
- 다른 편집기에서 저장하면 자동으로 갱신되고 읽던 자리를 지킨다
- 한글 인코딩(CP949)으로 저장된 옛 문서도 깨지지 않고 열린다
- 라이트 · 다크, 한국어 · 영어. 원격 이미지는 기본으로 불러오지 않는다

### 설치

[Releases](../../releases) 에서 `Marklet-Setup-<버전>.exe` 를 받아 실행한다. 관리자 권한이 필요 없다(현재 사용자 설치).

> **코드 서명이 없다.** 처음 실행하면 Windows SmartScreen 이 "알 수 없는 게시자" 경고를 띄운다.
> **추가 정보 → 실행** 으로 넘어간다. 서명은 인증서를 마련하면 붙인다.

`.md` 를 더블클릭해도 다른 앱으로 열리면: `.md` 우클릭 → **연결 프로그램** → **다른 앱 선택** →
Marklet → **항상**. 앱의 **도움말 → 기본 앱으로 설정** 이 같은 설정 화면을 연다.
윈도우가 프로그램이 기본 앱을 직접 바꾸는 것을 막아 두어서 설치기가 대신 정해 주지 않는다.

### 쓰는 법

화면에는 문서만 있다. 기능은 세 경로로 닿는다.

- **마우스를 움직이면** 우상단에 컨트롤(목차 · 찾기 · 테마 · 더 보기)이 나타났다가 곧 사라진다.
  **본문을 한 번 탭(클릭)** 하면 고정되고, 다시 탭하면 닫힌다
- **Alt** 로 메뉴 막대, **우클릭** 으로 같은 기능의 메뉴
- 단축키

| 키                                  | 기능                                  |
| ----------------------------------- | ------------------------------------- |
| `Ctrl+O`                            | 열기 (창에 파일을 끌어다 놓아도 된다) |
| `Ctrl+E`                            | 편집 모드 ↔ 보기 모드                 |
| `Ctrl+S`                            | 저장                                  |
| `Ctrl+F`                            | 문서 안 검색                          |
| `Ctrl+T`                            | 목차 (왼쪽에 도크, 다시 누르면 닫힘)  |
| `Ctrl+U`                            | 원문 보기 ↔ 서식 보기                 |
| `Ctrl` + `+` / `-` / `0`, `Ctrl`+휠 | 확대 · 축소 · 원래 크기               |
| `F11`                               | 전체 화면                             |
| `Ctrl+P`                            | 인쇄 (항상 밝은 색으로)               |
| `Ctrl+W` · `Esc`                    | 닫기 · 열려 있는 목차/검색 닫기       |

목차는 문서 왼쪽에 붙어 문서를 옆으로 밀고, 지금 읽는 절을 따라 표시한다. 제목이 없는 문서에서는 안내 창이 뜬다.
읽는 화면에서 `Tab` 은 아무것도 순회하지 않는다(편집기 · 검색 바 · 대화상자 안에서만 동작).

#### 편집과 저장

- **열린 그대로 되돌려 쓴다.** 인코딩(UTF-8 · BOM · UTF-16 · CP949), 줄바꿈(CRLF/LF)을 바꾸지 않는다.
  한 글자도 안 고쳤는데 파일이 통째로 달라지는 일이 없다
- 임시 파일에 쓰고 이름을 바꿔 덮어쓰므로 쓰다 멈춰도 원본이 온전하다
- **저장하지 않은 편집**이 있으면 창 제목에 `●` 가 붙고, 닫거나 다른 문서를 열기 전에 묻는다
- 편집 중에 다른 프로그램이 같은 파일을 바꾸면 화면을 갈아엎지 않고, 저장할 때 덮어쓸지 묻는다
- CP949 파일에 CP949 로 표현할 수 없는 글자(이모지 등)를 넣고 저장하면 UTF-8 로 바꿀지 묻는다
- 편집 모드를 나갔다 들어오면 되돌리기(`Ctrl+Z`) 기록은 새로 시작한다

열 수 있는 확장자는 `.md` `.markdown` `.mdown` `.mkd` `.txt` 이다. 설치기는 `.md` 계열만 기본 연결 후보로 올리고,
`.txt` 는 **"연결 프로그램" 목록에만** 올린다(메모장 등 기존 기본 앱은 건드리지 않는다).
4MB 를 넘는 문서는 서식 없이 원문으로 열고, 64MB 를 넘으면 열지 않는다. 설정(테마 · 확대 · 최근 문서 · 창 크기)은 `%APPDATA%\marklet\state.json` 에 저장된다.

### 개발

```bash
npm install
npm run desktop:dev     # 렌더러를 빌드하고 Electron 으로 실행
npm run desktop:dist    # 설치 파일 → release-desktop/Marklet-Setup-<버전>.exe
```

```bash
npm test                # vitest
npm run lint
npm run typecheck
```

구조:

| 경로                     | 역할                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| `desktop/main.cjs`       | 메인 프로세스. 창 · 메뉴 · 파일 읽기 · 더블클릭 연결 · 자동 갱신    |
| `desktop/menu.cjs`       | 메뉴 정의. 순수 함수라 시험할 수 있다                               |
| `desktop/preload.cjs`    | 렌더러에 내미는 좁은 창구. **임의 경로 읽기 같은 것을 더하지 마라** |
| `desktop/installer.nsh`  | 설치기가 덧붙이는 레지스트리 항목(연결 프로그램 목록에 뜨게 한다)   |
| `src/desktop/`           | 렌더러. 문서를 그리고 떠오르는 컨트롤을 둔다                        |
| `src/markdown/`          | **파싱 · 살균 · 렌더. Android 와 같은 코드다**                      |
| `vite.desktop.config.ts` | 렌더러 빌드 → `dist-desktop/`                                       |

보안: 렌더러는 sandbox + contextIsolation 이고 노드 API 가 없다. 마크다운은 출처를 모르는 입력이라
링크는 기본 브라우저로만 열고(http · https · mailto), 문서가 가리키는 로컬 파일은 **그림 확장자만** 내준다.

설치 파일이 100MB 쯤 되는 것은 Electron 런타임(Chromium)이 대부분이기 때문이다. 우리 코드는 6MB 다.

## Android (보류)

Capacitor 8 로 만든 Android 앱이 `android/` 에 있고 **코드와 문서는 그대로 남겨 두었다.**
당장 이어서 하지 않고, 필요해지면 재개한다.

- Google Play **내부 · 비공개 테스트** 트랙에 1.0.10 이 올라가 있다. **프로덕션은 출시하지 않았다**
  (비공개 테스트 12명 × 14일 요건이 걸려 있다. `.docs/설계문서/03_출시_절차서.md` 1-1절)
- 재개할 때: 먼저 `.docs/설계문서/00_시작하기.md` 와 `03_출시_절차서.md` 의 7-9절(해마다 `targetSdk` 를 올려야 한다)을 본다
- 미결: `src/markdown/sanitize.ts` 의 `SAFE_URL` 이 `//host/x.png` 같은 프로토콜 상대 주소를 통과시킨다.
  모바일에서는 원격 이미지 기본 차단을 우회하는 개인정보 문제다(Windows 판은 CSP 로 막혀 영향 없음)

```bash
npm run dev             # 브라우저에서 모바일 화면 확인
npm run dev:device      # 실기기 라이브 리로드
npm run build           # 번들 예산 검사 포함 (Android 용 www/)
npm run build:aab       # 서명된 릴리스 번들
npm run publish:internal
```

스택은 Capacitor 8 + Vite 7 + TypeScript 이고 **프레임워크를 쓰지 않는다** — 화면 대부분이 `innerHTML` 로 만든
문서라 가상 DOM 이 벌어 주는 게 거의 없고, 초기 JS 예산이 마크다운 스택(104KB)만으로 이미 절반을 넘는다.
근거는 `.docs/설계문서/02_기술_설계서.md` 0-3절. 파일 접근은 자체 네이티브 플러그인(`MdFilePlugin.java`)이 맡는다(5-1절).

## 문서

`.docs/설계문서/` 에 설계 · 조사 · 출시 절차가 들어 있다. **코드를 고치기 전에 읽어라** —
특히 `02_기술_설계서.md` 15장 "절대 하지 말 것"은 전부 실제로 한 번씩 겪은 것들이다.
설계 문서는 Android 기준으로 쓰였다. Windows 판의 근거는 코드 주석에 있다.

| 문서                | 내용                                                  |
| ------------------- | ----------------------------------------------------- |
| `00_시작하기.md`    | 여기부터                                              |
| `01_제품_결정서.md` | 무엇을 만들고 무엇을 안 만드는가                      |
| `02_기술_설계서.md` | 구현 전부. 함정 목록 포함                             |
| `03_출시_절차서.md` | Play Console 절차                                     |
| `04~07_조사_*.md`   | 경쟁앱 · 렌더링 스택 · 파일 처리 · 선행 프로젝트 자산 |

## 자격증명 (Android)

**저장소에 들어가지 않는다.** 아래는 `.gitignore` 로 막혀 있고, 없으면 해당 기능만 꺼진다.

| 파일                                                     | 없으면                              |
| -------------------------------------------------------- | ----------------------------------- |
| `android/keystore.properties` · `android/app/*.keystore` | 릴리스 서명 불가 (디버그 빌드는 됨) |
| `android/play-service-account.json`                      | Play 자동 업로드 태스크 비활성      |
| `android/local.properties`                               | SDK 경로를 못 찾음                  |

**키스토어 비밀번호를 어떤 문서에도 적지 마라.** 예시 파일은 `android/keystore.properties.example` 이다.
Windows 설치 파일에는 서명이 없어 지금은 자격증명이 필요 없다.
